How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Cognitive and behavioural development research often relies on validated and standardised assessments, which can indicate whether performance falls within typical or atypical boundaries for a given chronological age. However, researchers planning large collaborative projects and/or collecting data from hard-to-reach populations may face problems when attempting to use some of the most widely adopted measures. We outline the major consequences of restricting access and preventing modifications of measures for research in the fields of developmental psychology and education. The problems are illustrated using a case example of a big team science project on intellectual disability. Finally, a plan for collective action to establish public domain assessment tools is presented with specific recommendations for research funders and researchers. In the interest of scientific progression and international collaboration, we conclude that there should be opportunities for free access to research measures and their unrestricted adaptation and modification.

Introduction

The core utility of standardised assessments is the possibility of comparing the performance of the assessed individual against the typical performance observed for the same age and gender in the general population. Assessment results are often reported as standardised scores referenced to the general population norms. Such results indicate whether functioning is typical and highlight specific strengths and/or difficulties.

Commonly used standardised cognitive and behavioural measures come in many different formats. Some require specific materials. For example, coloured blocks are used to assemble shapes during the assessment of visuospatial cognition. Other assessments include questionnaires with answers on a Likert scale. The questionnaires can be completed either by the assessed individual or someone else (parent/caregiver, teacher, partner). Assessment measures are predominantly used in clinical and educational contexts by psychologists, speech and language therapists, and in some countries, also by occupational therapists and physiotherapists. In a research context, the standardised scores can be used to define participant groups, to compare performance between groups of participants, to track developmental patterns of cognitive and behavioural functions, or to measure intervention-related changes.

However, the use of these tools for researcher is often restricted. Clinicians who have the appropriate training and funds to purchase assessment measures can use them as intended for patient assessment. Researchers who have similar training and funds often must apply for a research license first.

Most standardised assessments are owned, copyrighted and distributed by publishing companies. The companies often invest in the development, validation, standardisation, and translation of the assessments, which takes significant time and resources.

Furthermore, the companies are responsible for printing and distributing the tests. They also tend to verify the credentials of users prior to authorising a purchase to prevent test misuse. It would not be feasible for the experts (often academic researchers), who develop the assessments, to manage these responsibilities themselves (Bishop, 2011).

Therefore, it could be argued that publishers are needed to manage assessment development, access, and distribution. In return, they maintain full control over the materials and monitor their usage. Users with sufficient prior education and training pay for core materials (the administration guide, usually a book, and a toolkit if needed) and record forms -one for each assessed individual. The commercial aspect of assessment management incentivises the publishers to avoid producing easily accessible versions of the materials, which could compromise usage monitoring. For example, publishers are reluctant to sell stand-alone electronic copies of the materials in a PDF format, even if shared under strict copyright rules.

Publishers typically require researchers to apply for a research license or permission prior to conducting any study using standardised assessments ( Because of the increase in international collaborations and remote assessment administration, it is difficult for many current studies to meet these criteria.

Consequently, the use of commercial standardised assessments in research may become very difficult or impossible given recent shifts towards valuing large datasets coming from diverse collaborators and populations, unless the research licence and copyright restrictions are relaxed.

Consequences of the Copyright and Research Licence Restrictions

The broad field of psychology is in the midst of a "credibility revolution" (Vazire, 2018) in response to widespread difficulties with reproducing and replicating already published results. The credibility revolution places great emphasis on transparency and openness of the research process at all levels of the research lifecycle (Chambers, 2017; Munafò et al., 2017). Open science is a general term that encompasses a variety of transparent research practices (Parsons et al., 2022). One example of such practice in psychology is data sharing, which has been gaining popularity over the last ten years, with best practice guides and instructions now available (van Ravenzwaaij et al., 2025). Transparency is also important when it comes to enabling access to the materials used to collect or generate the data. The two main arguments for openly sharing measures are (1) the possibility to assess validity and reliability (2) enabling access and further use to facilitate methodological homogeneity.

First, transparent reporting and open sharing of measures in psychology research allow readers and other researchers to assess validity and reliability (Lawson et al., 2026). This is necessary when reading published literature and interpreting the data and findings and is especially helpful in evidence synthesis studies. Access to the assessments is also crucial when designing new studies. Researchers need to access all elements of the administered assessment to evaluate whether it is fit for purpose, especially given how psychology assessments are at a high risk of becoming outdated or may not be suitable for application in cultures or contexts for which they were not developed (Kessels, 2019).

Currently, checking all details of the standardised copyrighted assessment measures is typically only possible after their purchase.

Second, open sharing of measures facilitates a consistent approach to research by increasing the chances that researchers will choose the same measures in their studies.

Repeated use of the same measures facilitates methodological homogeneity, which is essential for data aggregation, evidence synthesis and systematic comparisons across different studies. A reliable synthesis of available knowledge is a fundamental requirement to ensure that research fields continue making progress. There is, however, a significant problem surrounding methodological heterogeneity in psychological and educational research, which is largely attributed to differences in administered measures and outcome operationalisation (Imrey, 2020; Linden & Hönekopp, 2021; Uttal et al., 2024). For instance, a systematic review of measures used in 402 publications on autism found 327 unique measures of which 69% were used only once (Provenzani et al., 2020). Methodological heterogeneity is a complex issue, and the first step to resolve it is unrestricted and easy access to measures (Uttal et al., 2024), allowing for their further development and adaptation whilst avoiding proliferation (Elson et al., 2023). One particularly important aspect that must be addressed in further research is the validation of the already existing assessments in different language versions, applied in different cultures and contexts, with the inclusion of participants with disabilities. As long as researchers cannot openly share all measures used in their studies, as is the case with copyrighted standardised assessments, measurement validity will be obscured, and measurement heterogeneity will remain high (Lawson et al., 2026). Below, we outline three ways in which research licences prevent a wider uptake and further development and standardisation of commercial measures in research projects.

Translations

There is a well-documented discrimination problem in psychology research with significantly lower numbers of publications by non-English speaking authors, and insufficient attempts to include non-English speaking research participants (Hoffman et al., 2025; Tindle, 2021). In addition, the research process itself is limited by language barriers, where epistemological positions and research methodology are often noninclusive beyond Western cultures (Uskul et al., 2024). One way to improve inclusion and involve samples of participants who use different languages is a carefully planned translation approach guided by evidence-based translation practices and researcher collaboration (Hoffman et al., 2025). This is in line with the UNESCO recommendation on open science (UNESCO, 2023), which frames open research practices predominantly in the context of collaboration and inclusion, highlighting the need for sharing multilingual materials for future reuse. However, translations are another form of material modification often restricted under copyright laws and research licences.

Some non-English language versions of common commercial assessments already exist. There are publishers who are present in many countries and distribute tests translated into the relevant languages. Some countries, such as Italy or Poland, have their own country-wide publishers of commercial assessments who develop, standardise and distribute translated versions. These companies typically have special permission or a partnership agreement with the original publisher. However, managing access to these materials becomes challenging in collaborative groups. The more countries involved in a collaboration, the more complicated the research permission request process (see Box 1a for an example), although this is also dependent on the individual publisher's procedures.

A permission for new translations, where needed, can be difficult to obtain due to publishers' translation requirements. For example, Pearson Clinical requests the names, qualifications and a description of prior translation experience of all translators who would be involved in the process. The publisher also expects that the translation process should include back-translations. Professional translators are not always best placed to translate research measures. Beaton et al.'s (2000) guidance suggests that at least one of two translators working together on a measure should be from the target research field to serve as an "informed translator". The same guidance warns about limitations of backtranslations as this approach does not guarantee accuracy in the context of cultural adaptations. Indeed, it has been found that back-translations may encourage inappropriate translations because this approach is indifferent to the intended use of the measure (Ozolins et al., 2020) and it does not consider the measure's intended difficulty level. Furthermore, an entirely different translation and adaptation approach is required for assessments of language-related skills where phonological, grammatical and orthographical aspects must be carefully considered. From this perspective, publishers' translation requirements may be misdirected and, in some situations, may place unnecessary resource and financial demands on researchers who may not be able to afford it. In comparison, international psychological research collaborations that use public-domain measures tend not to hire professional translators, and the researchers often translate measures through a research community effort (for an example, see the Psychological Science Accelerator translation process at https://psysciacc.org/translation.html).

Remote administration

A digital display of assessment measures is a very helpful solution for researchers who wish to test participants remotely. This is especially applicable in cases where prospective participants are distributed over large geographical distances, for example in studies involving individuals with rare conditions. In contrast to clinics, where assessments are carried out for diagnostic and rehabilitation purposes, researchers do not often have easy access to participants with specific characteristics. Depending on the country or the research context, either researchers or participants travel significant distances to conduct or take part in data collection. Irrespective of who is travelling, this is problematic. For researchers, it is time-consuming and expensive, and for participants with disabilities, it could be a significant barrier to participation in research. Additionally, for participants with certain disabilities and/or communication differences, an introduction of a stranger into their home environment might cause distress and poses a further barrier to inclusion. Recently, researchers have developed new approaches for displaying and administering cognitive and behavioural tests remotely via video conference software (Ashworth et al., 2021; Harvey et al., 2025; Laverty & Richards, 2026).

It is worth noting that not all participants can comfortably complete remotely administered procedures, and this is still an unusual route of administration. However, digital administration of assessment measures has other benefits. It supports neat data management, especially in large projects with many researchers. It also provides opportunities for disability-focused adaptations, such as a direct set up with participants' augmentative and alternative communication devices using eye control. A research licence with special permission for digital display must be obtained prior to choosing this route of administration. In order to obtain such a licence, researchers must carefully plan the following: the elements of the tests to be displayed digitally; the hardware and software to be used; if the materials will be stored on any online platform or cloud service, who will have access to these materials, and how to prevent the participants from taking screenshots. Publishers may choose not to grant a licence for digital display of particular graphics-heavy assessments, or if they have concerns about copyright breach of their material based on the plan proposed by the researchers. If this happens, researchers have limited options. There is a lack of alternative public-domain tests that can be administered digitally, and those that exist are most often nonstandardised or validated to a limited extent.

Adaptations

Inclusivity in assessment development is a significant limitation of standardised assessments. The normative data used to calculate the standardised scores come from predominantly Global North populations. There are usually limited numbers of translated versions available for each test, and the available non-English language versions rarely come with standardisation based on a country-specific reference sample. For example, the Adaptive Behavior Assessment System Third Edition (ABAS-3) is used to assess adaptive functioning. It includes questions about a favourite restaurant and the ability to place an order when eating out. Such questions would not be relevant to daily functioning of all participants depending on their prior experience and background. Ideally, these could be adapted for cultural and contextual relevance. Given that researchers rarely get a chance to see the assessments prior to purchase, the need for such adaptations could be identified after the research licence is already agreed. In this case, a request for permission to adapt would have to be submitted separately, risking further delays to the project.

This issue also concerns the assessment of individuals with disabilities. Some of the most popular standardised assessments are those measuring the intelligence quotient (IQ), which are used within diagnostic procedures for intellectual disability. They are also a key research design tool for studies on atypical development. It is standard practice to match groups of participants with atypical development to a control group based on the scores from the standardised assessments (Russo et al., 2021). Other standardised measures assessing executive functioning are also commonly used with individuals with intellectual disabilities, and it has been suggested that these assessments may produce a more accurate representation of individual abilities compared to non-standardised assessments (Spaniol & Danielsson, 2022). However, these tests were not designed to be accessible or inclusive of individuals with intellectual disabilities. For example, standardised scores often are not sensitive to variation at the lower end of the distribution. Raw scores can be more sensitive, but using raw scores alone removes the ability to make normative comparisons. In addition, some standardised tasks demand abilities (e.g., receptive language, complex sentence comprehension) that make it unfeasible for participants with the most complex needs to engage with them, yielding true floor effects, even with raw scores.

Test administration instructions do not typically account for adaptations in case of disabilities despite increasing calls for assessment inclusivity. In 2022, the American Psychological Association published a guide for the adaptation of clinical assessments to ensure inclusion and accommodation for individuals with different types of disabilities (American Psychological Association, 2022). However, clinicians and researchers alike cannot easily implement these suggestions due to copyright laws restricting the modification of commercial assessment materials (see box 1b for an example). Notably, the main argument for adhering to standardised procedures is that these ensure the representativeness of norms. However, adaptations are typically only considered in situations when the applicability of norms is already in question. For example, when there are strong reasons to believe that disability-related factors risk interfering with test performance or construct measurement. In these situations, the choice is between two approaches that could risk introducing bias (unmodified assessment vs adapted assessment), rather than one with risk and another without. One way to address this problem is to use similar cognitive and behavioural measures but with criterion-based assessments. Such assessments would be referenced to fixed performance levels and would still produce results reflecting individual cognitive and behavioural functioning. At the same time, disability-focused adaptations would not undermine the outcomes to the same extent as in standardised assessments. Publisher-imposed restrictions would significantly complicate the validation of such tests, especially in the context of different disabilities and adaptations.

Box 1. Examples of how adaptations are complicated by licence restrictions (a) Translations If a collaboration including British, Swedish, Italian and Polish researchers decided to collect data using one commercial assessment available in all languages, the British and Swedish researchers could apply for a research licence to the same publisher and receive their materials in English and Swedish. The Polish and Italian researchers would have to separately source their permissions and materials from their countryspecific publishing partner. If the group had an additional collaborator from Bulgaria, where no Bulgarian test version exists, the British or Swedish researchers would have to also request permission to translate the test to Bulgarian in addition to their research license request.

(b) Adaptations and modifications A project is seeking to assess intellectual functioning in a group of children with visual impairment. Often, the Wechsler Intelligence Scale for Children -Fifth Edition (WISC-V) is considered for such purposes. It uses a version of the Kohs Block Test Design to assess visuospatial reasoning. Recently, a haptic version of the blocks used in the task has been developed (Bertonati et al., 2020). Researchers willing to use the haptic blocks when administering WISC-V to participants with visual impairment would first have to request permission for an adaptation of the mode of delivery from the publisher, even if they have purchased the WISC-V testing battery. If the researchers also wanted to use a standardised copyrighted questionnaire for their participants with visual impairment, they may wish to record audio files with the items or prepare braille versions, both of which would have to be first permitted by the publisher.

Taken together, the restrictions imposed by the copyright laws and research licences significantly hinder international collaborations and pose a barrier to the inclusion of participants with disabilities and diverse socio-economic and cultural backgrounds.

Researchers who use the copyrighted materials and follow through with the permission request processes must be aware that permissions can be granted or denied at the sole discretion of the publisher. Where agreement is not reached, the researchers must conduct the study without the standardised measures or limit their research plans to include only the already available languages and administer the tests with no other adaptations.

A Case Example -the CO-IND Project

Cognition and Intellectual Disability (CO-IND) is an international big-team science (Forscher et al., 2023) project focusing on the study of cognitive and behavioural functioning in children and young people with intellectual disabilities. The collaboration, at the time of writing, involves 33 research groups in 20 countries with approximately 100 researchers. We are implementing the study procedure in 15 languages and have started collecting data for 12 planned studies, four of which are registered reports (Topor & Danielsson, 2025). The project is coordinated by a team based at Linköping University in Sweden, who have obtained a grant to cover one of the planned studies, but otherwise, the project is unfunded and the collaborating teams are not reimbursed for their contributions.

The large-scale collaborative approach in CO-IND was employed in response to the recognition of methodological limitations in research on atypical child development (Farran & Scerif, 2022). Our participants form a heterogeneous sample representing a relatively low-prevalence population -children and young people with intellectual disability (ID), characterised by significant support needs in intellectual functioning and adaptive behaviours (Schalock et al., 2010). The diagnostic practices and educational provisions for young people with ID vary considerably between different countries (van Bakel et al., 2014), which makes cross-cultural comparisons challenging. Research involving young people with ID is characterised by methodological heterogeneity, which hinders efficient evidence synthesis (Batinović et al., 2026). Perhaps the biggest limitation of all is that research involving young people with ID most often includes very small sample sizes, limiting the generalisability and replicability of results and preventing the detection of small but meaningful effect sizes (Farran et al., 2026; Farran & Scerif, 2022; Laverty & Richards, 2026).

The big-team science approach has been rapidly gaining popularity over the last 10 years (Nogrady, 2023), though its application in the field of atypical development is limited. It may be particularly well-suited to remedy the above limitations by helping researchers harmonise assessments, methodological operationalisation of constructs, and analytical methods. It also makes it possible to assemble a large, rich dataset and mitigate the issues of low statistical power (Baksh et al., 2023; Lavigne et al., 2015; Santoro et al., 2023). This collaborative approach itself, however, comes with several challenges in the attempt to address the issue of methodological heterogeneity. In CO-IND, we surveyed participating principal investigators about the diagnostic practices in their countries, as well as the commonly used assessments of verbal and non-verbal reasoning and adaptive behaviours used in diagnostic procedures. According to the international diagnostic manuals, one of the criteria for a diagnosis of ID is markedly lower intellectual functioning confirmed by a standardised test (typically a score <70-75) and clinical assessment (American Psychiatric Association, 2022; The AAIDD Ad Hoc Committee on Terminology and Classification, 2010; ICD-11; World Health Organization, 2024). In research, the intellectual functioning scores can be used to understand the sample characteristics, match participant groups, control covariates, and track intervention effects. They can also be used as predictor variables in statistical models.

Our collaborators listed a total of 31 different standardised reasoning tests and 12 adaptive behaviour scales (Appendix A). Among these 43 measures, only one was open access (the Module on Child Functioning by Washington Group on Disability Statistics), and 39 were subject to copyright and fees.

A Call to Action -Open and Inclusive Assessment Measures

The open science movement has thus far mostly focused on open data, open analysis code and open access publications. We are proposing that more attention is needed on the measures used to generate data. We are not the first group of researchers voicing the need for public domain cognitive and behavioural measures. The team behind the ICAR Project (Dutry et al., 2025; Dworak et al., 2021) have created a library of cognitive measures for adults, specifically to address the barriers regarding the use of such measures in research. Some of their measures have been validated for administration to children between 11 and 14 years of age. This is an important foundation to build on. We believe that researchers, higher education institutions and funders should collectively work towards enabling open access research measures. Support from funding bodies has been instrumental in the widespread uptake of open access publications (Ross-Hellauer et al., 2018). We hope for a similar momentum regarding open access assessment measures in developmental psychology. We propose a set of concrete actions -two actions for funders and five actions for researchers.

1. Funders -support studies on open and inclusive method development

The development or adaptation of assessments is a lengthy process starting with creating materials, piloting and calibrating all elements.

Inclusive assessments require further work on translating instructions and items, as well as testing for measurement validity and reliability with diverse samples, including wide age ranges, based in different countries and contexts, and including people with disabilities. Currently, methodological development research is rarely prioritised by funders, which significantly limits the feasibility of conducting such studies. By allocating public funding to develop/adapt, validate, translate and standardise measures, the research community would become less reliant on publishers and less affected by copyright and research licence restrictions. Removing these obstacles would facilitate more robust research, more efficient collaborations, and accelerate knowledge progression.

2. Funders -include open measures in open science policies

Some funders already have open science policies to ensure that authors supported by public funding publish reports with open access and make their data openly available.

Such polices should be updated with a requirement to openly share assessment measures developed and/or validated in studies supported by public funding.

1. Researchers -Use already existing open access measures if possible

Choose an open access measure in favour of a proprietary alternative if it is reasonable for your research project. Do not create new measures if you can find one that is suitable for your project aims and your target population.

One concern regarding open assessment measures is the possibility that potential participants could access them and learn the right answers prior to participating in research. AI tools will have access to open measures and the answers making the tools easily accessible to participants prior to and even during assessment if conducted remotely. However, it is likely that most individuals participating in research would not have accessed these measures previously. It is advisable to ask participants before taking part in research whether they had done such assessments before either in their own time or as part of other studies. Researchers should avoid disclosing to participants what exact measures will be administered prior to their participation.

2. Researchers -Share all developed, translated and adapted materials

Ensure that any newly developed measures and adapted versions of open access measures are openly shared for further use and further development. This includes versions with new translations, cultural adaptations, age-appropriate adjustments and adaptations for different types of disabilities. Share the materials necessary to administer the measure as well as the administration protocol and instructions. Follow the FAIR principles (Wilkinson et al., 2016) to make these materials easy to find and reuse, for example by sharing the materials in different file formats on repositories with a search functionality. One current example of a suitable repository for such materials is Zenodo.

3. Researchers -Share adaptation details

Since adaptations of the existing tests for use with participants in different countries, contexts and with disabilities are still rare, future research should focus on evaluating how to best adapt assessments and cater for different needs. Therefore, sharing a measure itself is not sufficient. Authors should aim to share additional methodological information outlining translation, adaptation, piloting and validation procedures as previously postulated by Elson et al. (2023). Share the data collected during these method development processes to facilitate reliable validation and standardisation.

4. Researchers -Plan research to validate open and inclusive assessments

It is not feasible to expect that all basic or applied research projects should validate translated or adapted measures before their implementation. Therefore, projects aiming specifically to validate open and inclusive measures should be developed and funded.

We encourage the research community to recognise this as an urgent need.

Especially important is the inclusion of groups that have so far been excluded from the process of measure development, such as non-Western, non-English speaking participants or individuals with the greatest support needs. Future measure development should carefully reconsider the theoretical bases for the measures in the context of participant diversity. As of today, established theoretical models are based on neurotypical samples, and thus account for relatively narrow developmental variance. It is unknown whether the same developmental theories apply to atypically developing groups. This question will remain unanswered if measures do not exist to investigate the key mechanisms or variables for a theoretical model. It is also important to consider that here we focus on the development and validation of tools for research purposes. Further validation procedures will be needed if the tests are to be used for clinical purposes as well.

5. Researchers -Share collected data

As the validation processes take time, we need an alternative way to learn about the meaning of performance on cognitive and behavioural assessment tasks. Large-scale collaborations such as CO-IND are resource-demanding and cannot be expected to be the new gold-standard. It is realistic to expect that small-sample designs will still dominate. To reduce the limiting impact of small samples, placing more focus on methodological harmonisation and data sharing is key. One way to enable the interpretation of scores from open measures is through comparing results with those obtained in many similar studies. We, therefore, encourage researchers to openly share their data in accessible formats with clear documentation so that other researchers using the same tools can compare scores across datasets. A well-managed database, pooling all available data for a given measure could aid future standardisation and facilitate evidence synthesis.

The planning of data sharing should take place at the early stages of the project.

Researchers should consider the FAIR principles (Wilkinson et al., 2016) in the context of the target population and the risk of de-identification of individuals with rare conditions.

Data should be as open as possible and as closed as necessary. The shared datasets may therefore not always include all demographic information or may need to be preserved in closed-access repositories. All participants (and caregivers where applicable) should be properly informed and have the opportunity to give consent to having their anonymised data shared in a public repository. Researchers should explain to participants very clearly how open science benefits research progress and what may happen with their data when shared openly, to give participants the option of some gatekeeping or access only to bona fide researchers.
