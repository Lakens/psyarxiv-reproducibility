What we found

We found 1 non-significant p value that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Power analyses need to contain the following information to be interpretable: the type of power analysis, the statistical test, the software used, sample size, critical alpha criterion, power level, effect size, and an effect size metric. In addition, it is recommended to make sure the power analysis is reproducible (by sharing the code, or a screenshot, of the power analysis), and to provide good arguments for why the study was designed to detect an effect of this size.

How Ethics Approval Check works

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

This module was developed by Lisa DeBruine, Daniel Lakens and Cristian Mesquida

Read more in the metacheck manual.

Validation: In a sample of 128 papers with 246 instances of power statements, 203 were correctly detected (true positives), 22 were missed (false negatives) and 21 were incorrectly detected (false positives). Overall, among all instances flagged as power statements, 90.6% were correct (positive predictive value).

How Preregistration Check works

Retrieve information from preregistrations in a standardised way, and make them easier to check.

The Preregistration Check module identifies preregistrations on the OSF and AsPredicted based on links in the manuscript, retrieves the preregistration text, and organizes the information into a template. The module retrieves text from the OSF with its API, and from AsPredicted with ResearchBox’s API when a ResearchBox key is set (see rbox_token()), or else from the preregistration’s web page. The information in the preregistration is returned. An AsPredicted link that could not be read is named in the report, with the reason.

The module can’t extract information from non-structured preregistration templates (i.e., where the preregistration is uploaded in a single text field) and it can’t retrieve information in preregistrations that are stored as text documents on the OSF.

If you want to extend the package to be able to download information from other preregistration sites, reach out to the Metacheck development team.

This module was developed by Daniel Lakens and Lisa DeBruine

How Marginal Significance works

List all sentences that describe an effect as ‘marginally significant’.

The marginal module searches for regular expressions that match a predefined pattern. The list of terms is a subset of those listed in a blog post by Matthew Hankins. The module returns all sentences that match terms describing ‘marginally significant’ results.

Some of the terms identified might not be problematic in some contexts, and there are ways to describe ‘marginal significance’ that are not detected by the module.

This module was developed by Daniel Lakens

How StatCheck works

Check consistency of p-values and test statistics

The Statcheck module runs Statcheck. Statcheck searches for regular expressions that match a predefined pattern, and identifies APA reported statistical tests. More information on the package can be found at https://github.com/cran/statcheck. The module only returns Statcheck results for t-tests and F-tests, as these are the only tests which have been validated, see https://osf.io/preprints/psyarxiv/tcxaj_v1/.

Statcheck was developed by Michèle Nuijten and Sascha Epskamp.

Statcheck considers p = 0.000 an error, as you should report p < 0.001. Furthermore, p < 0.03 is an error if the p-value was 0.031, and one should simply report exact p-values (p = 0.031). How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Full text

Abstract

Personalized recommender algorithms are among the most influential design features of modern digital platforms, continuously adapting content in response to user behavior. Yet, little is known about how the brain responds as personalized digital environments emerge over time. To examine neural activity during this process, we used functional near-infrared spectroscopy (fNIRS) to develop a highly ecologically valid paradigm where 72 young adults scrolled on new accounts for a short-form video platform for 35 minutes while recommendation algorithms adapted content to their individual preferences. Participants reported that content was significantly more personally relevant by the end of scrolling, and durations of felt boredom significantly decreased. Despite all encountering unique content and scrolling at their own pace, participants who reported greater perceived personalization exhibited distinct trajectories of prefrontal and temporal neural connectivity, and these trajectories varied by problematic social media use. Among participants reporting higher problematic social media use, successful personalization was associated with increasing intra-prefrontal connectivity, suggesting that shifts in cortical dynamics during personalization may be relevant to vulnerability for pathological use. To our knowledge, this study provides the first in vivo evidence on how neural systems dynamically adapt alongside personalizing digital environments, and that this adaptive trajectory varies as a function of problematic social media use. More broadly, these findings demonstrate that neural adaptation to algorithmic personalization can be measured during actual deviceusage, providing a framework for studying brain responses to real-world digital experiences.

Personalized algorithms dominantly shape what people see and engage with online, yet, we have previously not studied how brain dynamics shift alongside real-time algorithmic personalization to individual user preferences. We provide the first in vivo evidence that neural systems dynamically adapt alongside algorithmic personalization and that these trajectories differ according to vulnerability for problematic social media use. The ability to find meaningful neural signal while all participants engage with the app in different manners demonstrates the feasibility of studying how the brain adapts to digital technology use in real-time with highly ecologically valid paradigms.

Introduction

The design features of social media are crafted to be engaging in manners directly related to natural biases in our psychological and neural processing of social and reward stimuli 1 . Personalized recommender algorithms are the latest, and perhaps most powerful, design feature of concern. Neuroscience has provided valuable insights into how specific features of social media platforms leave some people more vulnerable to problematic use than others [2] [3] [4] . Yet, we still have little direct data on how the brain responds as platforms actively adapt to user preference.

Algorithmic personalization has vastly changed how we navigate digital spaces. Over the past decade, media platforms have shifted away from feeds based on user-selected content or temporal order 5, 6 . Now, most default to recommender systems which use artificial intelligence (AI) to curate content based on data-driven insights into individualized user preferences 7 . Short-form video (SFV) apps have had major success with this approach, developing algorithms which personalize content to the user quickly and unobtrusively, relying largely on likes, video dwell time, swiping statistics, and background data from the device 8 . It is this personalization success, where every user can make an account and quickly be fed content that is tailored to their preferences, which has led to SFV apps becoming a dominant form of social media 9.

Experimental evidence has demonstrated that personalization on social media feeds is directly related to the tendency to use social media apps for increased lengths of time, less perceived self-control over use, and more felt enjoyment compared to feeds of non-personalized content 10, 11 . Previous work has found notable differences in neural responses to short form video content recommended by personalized algorithms versus generically obtained social media content. Personally recommended videos elicit more connectivity between regions implicated in self-referential and social processing, including the dorsomedial prefrontal cortex (dmPFC), ventral lateral prefrontal cortex, and the temporal parietal junction (TPJ) 12 . At the same time, the temporal pole was found to have decreased connectivity with both medial and lateral prefrontal regions potentially suggesting a reorganization of higher-order socio-affective processing 13 . Overall, recommender algorithms appear to modulate nodes important to the broader defaultmode network (DMN), possibly due to self-referential processing becoming acutely focused on the presented video content. Yet, these effects are not likely to be static. Algorithmic personalization emerges gradually during scrolling, and as such, we should expect these prefrontal and temporal regions to dynamically change in response.

When users first download a SFV app they are exposed to a naïve recommender system. The recommender algorithms of SFV apps are tuned to get new users to become habitual users, meaning this initial calibration is essential to establishing future patterns of use 10, 14, 15 . This calibration period may be especially consequential for individuals vulnerable to problematic SFV use, as personalized recommendations may amplify preexisting tendencies toward excessive engagement. Importantly, social media does not affect all users in the same way, and there is individual variation in susceptibility to problematic engagement 16 . Prior work suggests that traits associated with problematic SFV use, such as heightened sensitivity to self-relevant content and lower self-concept clarity, may lead users to become more easily immersed into SFV apps 17 . As personalized feeds increasingly align with individual interests, users with vulnerabilities such as this may be especially likely to experience a greater sense of immersion and engagement, leading to problematic use. Neurally, adults with higher problematic SFV use exhibit different patterns of dorsolateral prefrontal cortex (DLPFC) connectivity in which the DLPFC is preferentially embedded within higher-order association networks as opposed to sensory and attention networks 18, 19 . These associations represent important relationships between problematic SFV use and neural/psychological processing, but they do not capture how neural responses evolve, as content becomes increasingly personalized, in vivo. How the brain responds to a feed of content that is becoming more personalized is foundational to understanding how, and for whom, addictive patterns of engagement emerge.

Traditional neuroimaging paradigms often rely on standardized stimuli presentations that provide limited opportunity for users to selectively engage with content. More importantly, highly controlled stimulus sets are not designed to capture algorithmic tuning, whereby content becomes increasingly personalized through continuous user feedback. This limitation speaks to a broader challenge in the field: real-world experiences are often defined by evolving, irregular, timecourses for experiences which are near impossible to model in controlled stimuli 20 . Functional nearinfrared spectroscopy (fNIRS), a portable neuroimaging method, has previously been used to study unique affordances of real-world media contexts, finding distinct patterns of activation in the dorsolateral prefrontal cortex (DLPFC) during social media scrolling compared to television viewing and gaming 18 ; this highlights the importance of treating digital media not as purely an audiovisual stimuli but as an interactive experience 21 . As such, we took advantage of fNIRS's greater ecological validity to develop a highly naturalistic study on algorithmic personalization, allowing individuals to scroll on an actual smartphone device while neural connectivity is measured in real time.

In the present study, we used fNIRS to examine dynamic functional connectivity while 72 users naturally scrolled on a naïve short-form video account for 35 minutes. This paradigm allows us to investigate the varying neural trajectories of users in real time as the algorithm personalizes to their preferences. We hypothesized that prefronto-temporal and intra-prefrontal connectivity would increase over the course of scrolling, depending on how personalized the content felt to users by the end. Further, we predicted that this relationship would vary as a function of problematic social media use, such that individuals with higher problematic use would show larger increases in connectivity as content became increasingly personalized, reflecting more recruitment of these self-relevant networks due to their heightened vulnerability to be 'captured' by the flow state of the app.

Results

Change in personalization and affective content

After scrolling for 35 minutes, we asked participants to rate how personally relevant the videos they were shown felt during the first 5 minutes of scrolling and during the last 5 minutes of scrolling on a 1-7 Likert scale (1= "Not relevant at all",7= "Completely relevant"). We tested the difference in these subjective ratings of personal relevance as a manipulation check to ensure that the paradigm was successful. Personal relevance was significantly higher by the end of scrolling (M = 4.29, SD =1.51) compared to the first 5 minutes of scrolling (M = 1.81, SD =1.06; t= 12.21, p<0.001, Cohen's d= 1.44). This finding demonstrates that the recommender algorithm substantially increased the perceived relevance of video content to individual users. Notably, there was meaningful variation in the extent to which personal relevance increased for participants. Due to this variability, we used the personal relevance rating as moderator in our subsequent analyses of how neural connectivity changed over time, and how these trajectories differed based on problematic social media use.

Using screen recordings, we had subjects annotate how they felt during the first 5 minutes of scrolling, 20-25 minutes in, and 30-35 minutes in. The 20 minute timepoint was chosen as an estimate of when the algorithm may be adapted to personal preferences if this occurs more quickly than 30 minutes. Across all 5 minute windows of annotated videos, the most commonly reported feeling was interest, which was reported for an average of 104.43 seconds across all segments. Other commonly reported feelings were amusement (M=96.21 seconds), boredom (M=70.21 seconds), and happiness (M=41.21 seconds). Nostalgia (M=17.50 seconds), awe (M=17.15 seconds), sadness (M=12.75 seconds), and disgust (M=9.55 seconds) were generally reported for shorter durations, though still were reported in the majority of annotated segments (~59%, 56%, 51% and 50% respectively). Anger was rare, being reported in less than half of all segments (~34%, (M=5.77seconds).

We used mixed linear effects models to test differences in affect duration between the first, second, and third annotated segments of videos so that random intercepts for subjects could be included. Subjects experienced significantly shorter durations of boredom in the second (β= -21.20, p=0.016), and last segment (β=-17.64, p=0.045) compared to the first. Participants also reported significantly more amusement in the last segment compared to the first segment (β=21.39, p=0.042). No other duration differences in affect between segments reached significance (Figure 2).

Dynamic functional connectivity

Longitudinal mixed-effects models with natural splines (3 degrees of freedom) and subject-specific random slopes were used to model nonlinear changes in connectivity over time (Table S1). An omnibus Wald F-test was used to test the non-linear effects of time. Dynamic functional connectivity significantly changed over time in the intra-prefrontal (F(3, 29064) = 8.13, p < 0.001), prefrontal-temporal (F(3, 38916) = 16.89, p < 0.001), and temporal lobe models (F(3, 4809) = 3.55, p = 0.014) (Table 1). Both the intra-prefrontal and prefrontal-temporal models showed significant three-way interactions between time, problematic social media use, and perceived personalization by the end of scrolling (intra-prefrontal: F(3, 29064) = 5.19, p = 0.001; prefrontaltemporal: F(3, 38916) = 3.21, p = 0.022). This effect was not observed for the temporal lobe model (F(3, 4809) = 0.18, p = 0.907).

For intra-prefrontal connectivity, perceived personalization exhibited a crossover pattern across levels of problematic social media use (Figure 3). Among participants endorsing less problematic social media use, greater personalization was associated with relatively lower intraprefrontal connectivity across much of the scrolling session compared with lower personalization. In contrast, among participants reporting higher problematic social media use, greater personalization was associated with relatively higher intra-prefrontal connectivity during the latter half of the session. Thus, the association between perceived personalization and intra-prefrontal connectivity differed across levels of problematic social media use, such that greater personalization was associated with lower connectivity among those with lower problematic social media use but higher connectivity among those with higher problematic social media use. For prefrontal-temporal connectivity, participants with higher problematic social media use exhibited higher connectivity at the beginning of the scrolling task (Figure 3). Connectivity trajectories varied as a function of perceived personalization success, particularly among participants reporting higher problematic social media use. Among these participants, those reporting greater personalization success showed an overall sustained decline in prefrontal-temporal connectivity across the scrolling session. In contrast, participants reporting lower personalization success exhibited a nonlinear trajectory characterized by an initial decline followed by a later rebound. As a result, trajectories increasingly diverged across the session, with the high-personalization group exhibiting lower prefrontal-temporal connectivity during the later portions of scrolling.

Discussion

This study uses a novel, naturalistic paradigm to study how algorithmic tuning of content affects neural processes as it unfolds in real time. The self-report data on personalization confirmed the effectiveness and speed of short-form video feed algorithms at tuning to user preference. While the reports of personalization reflect the first and last 5 minutes of the 35 minute paradigm, the affect labelling data suggests that a significant shift likely occurred well before 30 minutes. By 20-25 minutes into scrolling, subjects reported boredom significantly less often. Our findings further show that the perceived success of algorithmic personalization is associated with neural trajectories diverging within approximately 20 minutes of scrolling. More broadly, this period of algorithmic calibration represents a laboratory analogue of the real-world process through which social media platforms progressively increase user engagement and, for some individuals, contribute to problematic patterns of use. These neural trajectories depended on individual differences in problematic social media use, suggesting different vulnerabilities to digital engagement. Participants reporting more problematic social media exhibited connectivity trajectories consistent with increasing segregation of prefrontal and temporal processing as content become more personalized. The specificity of this diverging trajectory to individual variation in problematic social media use is notable, as the majority of the sample used SFV apps on at least a daily basis. Of methodological significance, these temporal patterns were uncovered despite all subjects encountering unique video content, and all scrolling at their own pace. This study is the first evidence of how the organization of cortical networks shift during real-world algorithmic personalization and gives insight into how distinct processing of personally relevant content may facilitate excessive and problematic use.

Our neural connectivity data, measured on a continuous sliding-window basis, demonstrated noticeably diverging patterns related to personalization success possibly as early as 10 minutes in. Although the reported personalization success used in the models is only a retrospective reflection specific to the last 5 minutes of content, its association with connectivity trajectories this early suggests that the effectiveness of algorithmic tuning is reflected in psychological and neural processes well before. Individual susceptibilities to algorithmic personalization may also play a role in this early stage-setting, as shown by problematic social media use's association with personalization-related neural trajectories. The neural connectivity results align with previous fMRI studies finding that personalized SFV content preferentially engages dorsomedial prefrontal and broader default mode network systems relative to generic content 13 . These regions are thought to support self-referential processing, social cognition, and the integration of personally relevant information. Personalized short-form video content has previously been associated with greater recruitment of dorsomedial prefrontal DMN pathways and stronger coupling between self-referential and attentional systems, suggesting that algorithmic recommendations increase the personal significance of viewed content 12 . Our findings extend this work by demonstrating that these neural differences are not simply static properties of relevant versus irrelevant media content, but dynamically emerge during the process through which recommender systems learn user preferences. This pattern was most pronounced among individuals reporting greater problematic social media use, for whom successful personalization was associated with opposing changes in intra-prefrontal and prefrontal-temporal connectivity trajectories. Specifically, greater personalization success was associated with relatively higher intra-prefrontal connectivity and lower prefrontal-temporal connectivity over the course of scrolling. This pattern is consistent with a reorganization of cortical network dynamics during algorithmic personalization. Shifts in prefrontal-temporal connectivity are broadly consistent with previous literature on DMN alterations in problematic social media use, though fNIRS does not cover the entirety of the DMN. Resting-state studies have demonstrated that people with problematic internet use exhibited altered inter-network and intranetwork functional connectivity of the DMN 22, 23 . Work specific to problematic SFV use has found altered patterns of DLPFC connectivity -a well covered region in our fNIRS montage. In a partial parallel to our results, DLPFC-dorsal anterior cingulate connectivity increases during personally recommended short form videos, broadly mirroring our finding of increased intra-frontal connectivity 24 . Another study also found prefrontal decoupling from sensory and attention-related regions during short-form videos compared to longer videos in the learning context 25 . Mechanistically, our results may suggest that individuals prone to problematic use may process increasingly personally relevant content in a more segregated manner, with regions important to integration such as key prefrontal nodes communicating more amongst themselves than within a cross-network cortical system. This study has limitations. Subjects were generally regular SFV users, which may influence engagement and neural responses in ways distinct from a user's first time on the app. Personalization was measured through self-reported relevance of the content during the first and last 5 minutes of scrolling, which may not fully represent the 35 minutes of scrolling. Future studies could use more objective and detailed measures of personalization, such as comparing content categories between the novel scrolling task and the subject's personal short-form video app account, or behavioral metrics such as changes in swiping speed. Similarly, affect was retrospectively measured in three 5 minute video segments to balance subject-level specificity with participant burden. fNIRS's mobile nature and flexibility allows the ecological validity necessary for this study, but it cannot give a full neurobiological picture of personalization processes. Many important regions of the DMN, as well as all subcortical regions, are not measurable through fNIRS. These regions likely play an important role in algorithmic capture based on previous literature on social media use and personalized content. More broadly, our study uses a short-form video app algorithm as a prominent and widely used example of personalization in the real-world, but this type of algorithmic tuning extends beyond video platforms, to shaping behavior on social media apps, AI chatbots, e-commerce, and even health and learning platforms. As recommender systems are implemented into more technologies, understanding how they shape brains has implications beyond any specific media platform.

Despite these limitations and the further work which needs to be done, one of the most novel aspects of the present study is our ability to observe the brain in real time as a naive shortform video account is progressively shaped by the platform's personalization algorithms. Rather than treating the social media environment as static exposure, our approach captures the dynamic co-evolution of the digital environment and the brain's responses to it as the algorithm learns about the user. This provides a rare window into the neural correlates of personalization as it unfolds in real-time, allowing us to simultaneously watch change in the digital environment and the resulting neural adaptation. It also should be highlighted that temporal neural trends related to personalization and problematic social media use were found despite all subjects having individualized, uncontrolled, streams of content shown to them. As the field of neuroimaging has evolved, we have gradually made progress toward paradigms that better capture real-world experiences by sacrificing some experimental control, including reliance on averaged activity, strict standardization of stimuli, consistency of content exposure, and attempts to minimize variability in affective responses across participants [26] [27] [28] [29] . This study demonstrates that neuroimaging paradigms can successfully accommodate all of these naturalistic necessities, even in combination, while still identifying scientifically useful insights.

Our data demonstrate that the success of algorithmic personalization is associated with measurable changes in neural processing that emerge within minutes of use. These trajectories differed as a function of problematic social media use, suggesting that personalization's effects on neural processing may depend on individual vulnerabilities. A neuroscience that can abstract trends across highly individualized experiences is critical for deriving ecologically valid insights into how algorithmic systems influence affect and behavior.

Materials and Methods

Study participants

We collected data from 80 college-aged subjects, all of which currently, or had in the past, used short-form video apps. Informed consent was obtained and all aspects of the study were approved by the University of North Carolina's institutional review board. Of these subjects, 8 were removed due to having poor quality data in too many fNIRS channels (see Pre-processing and Dynamic functional connectivity sections) leaving a main sample of 72 participants (Table 2). Over 93% of participants reported using TikTok or Instagram Reels, two of the most popular SFV apps, at least once a day.

fNIRS parameters

All data were collected using a 16x16 NIRSport system (NIRx Medical Technologies). Participants' head size was measured so that an appropriately sized cap could be selected.

Changes in oxygenated (HbO) and deoxygenated hemoglobin (HbR) were measured with a 48channel montage across bilateral frontal and temporoparietal cortices. We additionally had 8 short-channels for capturing confound signals (Figure S1). We used a sampling rate of 7 Hz. Before data collection, signal quality was checked for each channel, and optodes were adjusted until good quality was achieved.

Algorithm reset

We used TikTok as the short-form video app in the study. The TikTok accounts on lab smartphones were reset before every new data collection, and efforts were taken to limit or eliminate accumulated data from modifying the TikTok algorithm between sessions. Sessions were run with two different iPhone and four email-based TikTok accounts, rotating phones and accounts to always use the least recently used one. The only initial demographic information in these accounts was a generic date of birth set to indicate a 20 year old, aligning with our targeted sample of 18-24 year olds. After each data collection, multiple steps were taken to reset the algorithm to a naive state as much as transparently possible. First, all videos 'liked' in the previous session were manually un-liked. In the "Activity Center" of the TikTok app, watch history, comment history, and search history were all deleted. In Settings and Privacy-> Ad preferences of the phone itself, "off-TikTok data" was disabled to prevent TikTok from using data from other apps to inform ad selection. Within Settings and Privacy, the cache was cleared for Tiktok. Finally, the TikTok app would be re-opened and "Refresh you Feed" would be selected within Content Preferences.

fNIRS resting-state connectivity

A 5-minute resting-state recording was performed to be used as a control variable in analyses. Subjects were instructed to sit and stare at the off iPhone screen.

fNIRS naive algorithm scrolling task

Reporting and user data analysis by the Washington Post found that TikTok's algorithm can generally personalize content to an effective enough extent to increase future use durations in approximately 30 minutes of scrolling 15 . As such, we made our paradigm 35 minutes long to attempt to capture this window of algorithmic tuning. Subjects were given a lab iPhone with the TikTok app loaded, and instructed to scroll and view videos as follows: "Scroll as you normally would if this were your own brand-new TikTok account, but only stay on the For You page. You can do anything on the For You page, like watching, scrolling, skipping videos, and looking at comments -whatever feels natural to you, as we just want to see how you'd typically explore and interact with the feed."

The researcher would begin screen recording on the iPhone while hitting an initial trigger for fNIRS recording, then hand it to the participant telling them not to begin scrolling until told. The researcher would then tell the subject to begin scrolling while sending a second trigger, marking a starting point in the neural data for the session that the data could be trimmed to begin at the first scroll in the screen recording. A silent timer was then started for 35 minutes. When time was up, participants were told they could stop viewing, the researcher stopped the screen recording, and the fNIRS recording was ended. Subjects were asked on conclusion of the task to rate on a 1-7 Likert scale: 1) "For the first 5 minutes of scrolling, how personally relevant did the content feel?" and 2) "For the last 5 minutes of scrolling, how personally relevant did the content feel?".

Emotion annotation

Immediately after the naive algorithm task, subjects were presented with three 5-minute clips from their session, close to the first, middle, and last 5 minutes of their scrolling. Of our 72 participants with valid fNIRS data, 59 participated in this emotion annotation. To assure rapid processing of these videos clips while also excluding seconds at the beginning and end of the screen recording which were not during the 35 minute scrolling duration, the first clip was started at 60 seconds into the recording, the middle at 1260 seconds, and the last at 360 seconds before the end of the recording (to exclude the final 60 seconds). We used the publicly available Cinemotion tool (https://github.com/jtkaplan/cinemotion) to allow subjects to retrospectively report their emotional state during the task. Using a set of interactive buttons that could be turned on and off during the clips, subjects were instructed to label how they had felt during that part of the TikTok scrolling task, trying their best to reflect on how they had felt on initial viewing rather than in the current moment rewatching the clips. Subjects could turn 9 different emotion labels on and off (happy, amused, interested, sad, angry, bored, disgusted, nostalgic, awed), and multiple labels could be on at the same time. An additional "All off" button was present to turn off all current labels. We aimed to pick a set of labels encompassing positive, negative, and potentially mixed valence, while also best representing emotional states that were likely to be frequent during SFV viewing (hence, excluding otherwise typically measured states such as fear). The Cinemotion tool generates time logs indicating when buttons were turned on and off, which were then used to calculate reported emotion durations for each of the three segments, as well as the total number of times subjects transitioned between emotion states (indicated by any change in a button to 'on' or 'off').

Survey data

Participants in the study completed a battery of survey measures. Relevant to the current analysis, problematic social media use was assessed using the 9-item Social Media Disorder scale 30 . The scale is based on addictive disorder criteria from the Diagnostic and Statistical Manual of Mental Disorders 5th edition, with each of the 9 items being endorsed or not. A score of 0-1 is generally considered normative behavior, 2-4 indicates potentially risky usage, and 5 or more is considered pathological use or "disordered". In our sample, roughly even proportions fell into normative and risky ranges (47.2% and 45.8% respectively) while 6.9% endorsed 5 or more items.

Pre-processing

NIRS data were preprocessed to remove physiological noise and head motion artifacts using Satori 2.2.4 31 . First, we trimmed data to the length of the rest (300 seconds) and TikTok (2100 seconds) periods. Raw data were converted to optical density data. Then, channels were rejected and removed if their scalp coupling index (SCI) was below 0.7. Motion correction was applied using temporal derivative distribution repair 32 . Using the modified Beer-Lambert law, optical density data was converted to concentration changes of HbO and HbR. We then applied short channel regression to remove physiological noise, using all available short channels after channel rejection 33 . A Butterworth bandpass filter was applied with cutoff frequencies of 0.1 Hz and 0.009 Hz. Data were visually inspected to assess signal quality at each step.

Dynamic functional connectivity

HbO values for each channel, in each subject, were extracted. Channels were grouped into regions of interest (ROIs) for subsequent dynamic connectivity analyses (see Table S2). Subjects were excluded from analysis if they had valid data in less than 50% of channels in any ROI. Because of the high rate of drop-out of channels in the superior parietal area (~10% of the sample would be excluded if required to have the superior parietal ROIs), we excluded these ROIs from further analysis. Overall, this led to a final sample of 72 participants with complete fNIRS data and personalization data. Dynamic functional connectivity was calculated using a sliding window approach, with windows being 60 seconds long (420 timepoints) and with 30 second steps (210 timepoints) between each window. For each pair of regions of interest in each window, Pearson's correlations were calculated for each pairwise combination of valid channels in each ROI. Correlations were converted to Fisher's z statistics, which were then averaged for the overall connectivity of that window.

Mixed-effects modelling of connectivity trajectories

Statistical modelling was performed in R using the Non-Linear Mixed Effects package (nlme) 34 . The 15 pairwise ROI combinations of dynamic connectivity were grouped into three separate models: 1) intra-prefrontal connectivity, 2) intra-temporal lobe connectivity, 3) prefrontaltemporal lobe connectivity. Since the first and third models involved more than one pair of ROIs, specific ROI-ROI pair was included as an independent variable in these models, so each model could broadly be considered to predict connectivity of these intra and inter-lobe dynamics.

We used longitudinal linear mixed-effects models to characterize changes in connectivity over time. Time was modelled using natural splines with 3 degrees of freedom to allow for nonlinear trajectories. Additional fixed effects of the model included ROI pair, post-scrolling personalization, early scrolling personalization (to account for baseline content relevance before algorithm shaping), the interaction between post-personalization and time, and average resting-state connectivity for the corresponding pair of ROIs. Subject-specific random slopes were included. To best account for the temporal dependence, including that introduced by the 50% overlap in adjacent connectivity windows, a first-order autoregressive residual correlation structure was specified for each ROI pair within each subject.
