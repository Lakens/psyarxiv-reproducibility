- The page of findings per check: `modules/index.html` (with `modules.js` and `modules.css`), at `<site>/modules/`, made on 8 November 2026. It is not linked from the landing page yet, and is kept out of search engines (`noindex`) until it is. On top: a reminder that every finding can be a false positive. One tab per check, all 16, in the order of the report and with the check's own title; the address ends in `#<check>` for each tab. Most tabs list the preprints where the check gave red, yellow or "info" (grouped in that order), each with the check's own summary; the checks that flag sentences or cited references show those too, the first three and the others behind "more": Power (analyses with parts missing, and which), Marginal Significance, Exact P-Values (imprecise or zero p-values), Effect Sizes (tests without an effect size, or with one that does not fit), PubPeer, RetractionWatch and Replication (the cited reference, with the comments, the database entry or the replication). StatCheck, Reproducibility and Data Check have tabs of their own. The "Data Check" tab shows, per preprint, the problems in its data files, grouped by kind (empty column, personal information, whitespace, numeric as text, ...), each as "file → column: detail" (the detail at most 300 characters), with metacheck's warning that a personal-information flag means "look at this column". They come from the data check's `findings` (one row per problem), which the SURF server keeps in the JSON result from its branch `data-check-findings` on (with `careless`, the respondents flagged for careless responding); for results without it, `update.py` reads the "Issues Identified" table in the report text, which is R code (`r_table()`); on the first 85 preprints it read 1,008 problems in 20 preprints. The "StatCheck" tab (`stat_check`) lists every p-value that differs from the one computed from its test statistic: those where the conclusion changes (on different sides of .05) first, then the others. Each shows the sentence with the test marked, the reported and the computed p-value, and the preprint (title linking to its report, id, OSF). The sentence is cut out of the paragraph metacheck stores; when the converter joined text (a page header, figure text), it can be longer than one sentence. The data: `data/modules/<check>.json`, written by `update.py` (`update_module_lists()`, with one function per check in `MODULE_FINDINGS`): after each preprint only its entry is renewed, and preprints of the index the file has not looked at yet (its list `looked_at`) are added; the whole file is made again from all results when it is missing or `MODULE_FORMAT` changed. The 16 files together were 438 KB for 85 preprints. All wording on the page is a placeholder for Daniel's. The "Reproducibility Check" tab (`reproducibility_check`) lists the scripts that did not run through, one entry per preprint and reason (metacheck's `reason`), each script with its error message and the files it reads that are not in the repository. First the reasons in the code itself (a file, an object not created, a syntax error, another error), then apart, under "Could not be checked", the limits of the check (a package that could not be installed, software or the internet the check does not have, the time limit, a script waiting for a person, a download too large). The message comes from the table's `error_message` (metacheck 0.4.3.19 and later, scienceverse/metacheck#615); for older results `update.py` takes it from the script's error output in the report text, with the same rule as metacheck's `.repro_error_line()` (on the 9 scripts that have both, the two agreed every time). For a time-out in an older result there is no message, as its output ends anywhere.

It draws what Metacheck found in the checked preprints, in 16 sections: open science (a funnel from repository to code that runs, shares, preregistration templates, and which repository websites the preprints link to: OSF, GitHub, Zenodo, ...; a DOI counts by its prefix, a link pasted from Outlook is unwrapped); ethics approval (new data collected, and how many of those mention ethics approval); "How often does Metacheck spot a potential issue to improve?" - The scheduled run: `scripts/update.py`, run by `.github/workflows/update.yml`. It runs every hour (switched on 7 November 2026, after a test run on GitHub for one preprint, `js3wm_v1`, succeeded); to stop it, put a `#` before the two schedule lines in that file. The first five reports were made on 7 November 2026 by running the script on Daniel's computer (`--max 5`).
  - It lists preprints on the OSF and downloads each one's file (PDF or Word) itself, then uploads it to the SURF server as one job that returns both the JSON result and the report page (`kind=check`, `report=true`). The server's own `psyarxiv` field cannot be used: it looks preprints up on `next.psyarxiv.org`, which does not have the newest ones yet, and it always takes the newest version.
  - Order: preprints published since the last run, newest first; when none is waiting, older ones, one day at a time going back, until 1000 older preprints have been sent.
  - A preprint is checked in the version that is its newest at that moment. When a newer version is checked later, the reports on older versions stay.
  - A run starts no new preprint after 50 minutes. A failed job is tried twice (one retry), then listed in `state.json` under `failed` (Daniel, 8 November 2026; it was three times).
  - Each preprint's files are stored on GitHub (committed and pushed, `--push`) as soon as it is checked, not at the end of the run. So a preprint whose files GitHub refuses costs only itself: it is left out, listed under `failed` with the reason, and not sent again. GitHub refuses a file that contains a key it recognises ("push protection") or that is over 100 MB. (Before 8 November 2026 a run stored everything at its end, and one refused file lost all of that run's reports: twice, on 8 November 2026, for `6qf9p_v3`.)
  - Keys: authors sometimes leave a key for a paid service in their files (`6qf9p_v3`: an OpenRouter key in a Qualtrics survey file on OSF), and metacheck can copy it into its result. Before saving, the script replaces every key it finds in the result and the report page with `[key removed]`, and lists what it removed, by rule, as `keys_removed` in the result file. The rules are those of the secret scanner betterleaks (MIT licence; by the authors of gitleaks), 427 of its 474: those with high or medium confidence. `scripts/make_key_patterns.py` collects them into `scripts/key_patterns.json`; run it by hand to take up newer rules. Tried on 8 November 2026: it found fake keys of nine common types and the real OpenRouter key, and removed nothing from the 71 reports then on the site. TruffleHog's patterns, tried first, removed ordinary words, links and file names 2,820 times, because TruffleHog checks each find with the provider before reporting it. Keys that betterleaks does not know can still be refused by GitHub; see the previous point.
  - The runs follow each other: at the end of a run that succeeded, the workflow starts the next run itself (job `next`), because GitHub's hourly timetable proved unreliable (on 7 November 2026 it started no run at 19:17 or 20:17; Daniel's other site, automated_review_daily_build, shows scheduled runs hours late or missing). The hourly timetable stays as the backup that restarts the series after a failed run. With nothing waiting, a run looks for new preprints every 10 minutes until its 50 minutes are up.
  - A preprint is sent only when the server is completely idle: no job running or waiting there, ours or anyone's (Daniel's rule, 7 November 2026). Otherwise the script asks again every minute, and the next run carries on waiting. Someone who submits while our paper runs gets the server's other place; only a second person at that moment can wait behind our one paper.
  - One preprint at a time on the server, so one of its two places stays free for other people (Daniel's rule). The job the script has on the server is kept in `data/current_job.json`; no new job is sent while it is still queued or running, also not by the next run. Do not run the script on your own computer while the hourly run is on: the two would not see each other's jobs.
  - Started by hand (Actions tab, "Update the reports", "Run workflow"), it asks how many preprints to check at most (0: no limit).

## Decisions so far

- Source: the old PsyArXiv site, through the OSF API: `https://api.osf.io/v2/preprints/?filter[provider]=psyarxiv`. Not `next.psyarxiv.org`.
- Scope: every new preprint, newest first. When no new preprint is waiting, older ones, one at a time.
- Checks: the checks the SURF server already runs for its regular report (the 15 modules listed below), with the paper's code run in the sandbox (`run_code=true`).
- Repository links: found by scanning each paper, not taken from OSF's data-link field.
- No reproducibility labels: the metacheck report is the output.
- Storage: keep everything the server returns (Daniel, 7 November 2026: the data is valuable; when the repository gets too large, that is solved then). That is the JSON result with every module's full output, tables included, and the checklist report page. Reports on older versions of a preprint stay.
  - Not stored, because the server does not return them: the uploaded file, the paper's full text, the downloaded repository files, and the progress and log files.
  - Open: the reproducibility check's full console output (every line each script printed). It may be large. Measure it on the first real runs, then decide.
- Report addresses: `<site>/<id>/`, ending in the id with its version as the OSF's address does.
- Landing page: a running tally of preprints listed on PsyArXiv, preprints checked, and the date of the last update. Still open: whether to count PDFs (this needs one more request per preprint to read its file type).
- The intro text and any other page wording are written by Daniel, or on his request. The title is his ("Metacheck reports for PsyArXiv preprints"). The intro (7 November 2026, on his request) starts with the sentences of the SURF site's landing page, adds the warning from the server's PsyArXiv reports page, and links to Metacheck's GitHub page and issues page, the manual, and the SURF server, thanks SURF, and gives Metacheck's citation (from the package's `inst/CITATION`, without a version number; the DOI 10.5281/zenodo.20704754 is Zenodo's DOI for all versions). Note: the Zenodo record lists other authors (DeBruine, Lakens, Werner, Merz, Wallrich, van Berkel) than the package's citation (DeBruine, Mesquida, Werner, Lakens).

## The SURF server

- Public address: `https://metacheckserve.metacheck.src.surf-hosted.nl`. Health check: `/api/health`.
- Jobs: `POST /api/jobs` (form data) with `kind` (`report` or `check`), `psyarxiv` (a preprint id) or `file`, `report_type=checklist`, `modules`, `run_code` (`true` or `false`), `crossref`. Then `GET /api/jobs/<id>`, and `GET /api/jobs/<id>/result` when done. Results are deleted 60 minutes after they finish.
- The 15 modules the server runs for a report: `power`, `marginal`, `prereg_check`, `ethics_check`, `ref_pubpeer`, `ref_retraction`, `ref_replication`, `stat_check`, `stat_p_exact`, `stat_p_nonsig`, `stat_effect_size`, `repo_check`, `code_check`, `data_check`, `codebook_check`.
- `reproducibility_check` (the module that runs the code) is not on that list, but the server adds it itself when `run_code=true`, so each result has 16 modules.
- The server stops a paper's code after 60 minutes and refuses files larger than 50 MB.
- Access: SSH key `~/.ssh/id_ed25519_metacheckserve`, user `dlakens`, host `metacheckserve.metacheck.src.surf-hosted.nl`.
- On the server: the code clone is `~/surf-research-cloud` (branch `main`); the running copy is `/opt/metacheck-component`.
- Deploying a change:
  1. Push `main` in the `surf-research-cloud` repository.
  2. On the server: `cd ~/surf-research-cloud && git pull --ff-only origin main`.
  3. Check that no run is active: `ps -eo args | grep "[a]nsible-env/bin/python"` must print nothing.
  4. Start the playbook in the background, with a log file: `sudo ~/ansible-env/bin/ansible-playbook --connection=local -i localhost, -b metacheck.yml > ~/playbook-<date>.log 2>&1`. A run takes about two minutes. Check the end of the log for `failed=0`.
- Remembered settings: the server keeps values given in earlier runs in `/etc/metacheck-settings.json`. A changed default in `metacheck.yml` does not override a remembered value. To change one setting, pass it on the command line: `-e name=value`.

## How to continue

1. Get the latest version of this repository (`git pull` in its folder).
2. See the page: from the project folder run `python -m http.server 8765`, then open `http://127.0.0.1:8765/`.
3. Check the server: `python scripts/test_surf_jobs.py`. It sends three jobs to the public server; it takes several minutes.
4. Try the scheduled run without touching the site: `python scripts/update.py --max 1 --data-dir <a test folder> --site-dir <a test folder>` (copy `fonts/` and `images/` into that test folder first).
5. Add reports: start the workflow by hand on GitHub, or switch on its hourly schedule.
