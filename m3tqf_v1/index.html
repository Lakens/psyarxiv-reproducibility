How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. Data Transparency in Industrial, Work, and Organizational Psychology: A Primer on Data Sharing and Documentation of Data Reuse

Most research in industrial, work, and organizational (IWO) psychology is based on empirical data, such as employee surveys, supervisor ratings of performance, diary data on daily work experiences, or behaviors coded from videotaped team meetings. These data enable researchers to test theoretical assumptions about work and organizational phenomena. The results of such tests are typically reported in journal articles that describe data collection and analysis procedures and present the findings. However, regardless of how detailed these reports are, the validity of the conclusions presented in empirical articles can only be fully evaluated when the underlying data can also be considered (Rudolph & Zacher, 2021). This is not to suggest that researchers are generally suspected of engaging in data fabrication, fraud, or questionable research practices, although evidence suggests that questionable research practices do occur in IWO psychology (Banks et al., 2016; Torka & Hüffmeier, 2025). Rather, data analysis is inherently prone to human error (Bakker & Wicherts, 2011; Bosma & Granger, 2022) and involves numerous researcher degrees of freedom, including decisions regarding outliers, careless respondents, and control variables (Gelman & Loken, 2013; Mazei & Hüffmeier, 2026; Schweinsberg et al., 2021). Because errors and analytic decisions can affect the results reported, an important requirement for evaluating the validity of empirical findings is to test whether these findings can be reproduced.

Reproducibility is a core component of the self-correcting mechanisms underlying scientific progress (Nosek et al., 2015). In contrast to replicability assessments, which involve investigating the same research question using independent data, assessing reproducibility refers to investigating the same research question by reanalyzing the original dataset (Nosek et al., 2025; Obenauer, 2026). Although reproducibility can be evaluated by the original researchers (i.e., dependent reproducibility; Köhler & Cortina, 2021), assessments by researchers who were not involved in the original study (independent reproducibility; Köhler & Cortina, 2021) reduce the likelihood of repeating the same errors and minimize dependence on potentially biased decisions. Reproducibility can be distinguished into computational reproducibility (i.e., same data and analysis code), recreated reproducibility (i.e., same data, but independently recreating the original analyses), and robustness reproducibility (i.e., same data, but using alternative analytical approaches; Dreber & Johannesson, 2025).

Regardless of the form of reproducibility, its assessment requires access to the original data and therefore depends on whether researchers share their data. Beyond independent reproducibility assessments, data sharing is also important to enable reuse of existing data for secondary analyses, including meta-analyses (Rudolph et al., 2020; Rudolph & Zacher, 2021) and investigations of novel research questions (Klein et al., 2018). Data sharing thus represents an essential practice within open science (Nosek et al., 2015).

Despite its benefits, data sharing remains relatively uncommon in psychology (Hardwicke et al., 2024; Tedersoo et al., 2021; Towse et al., 2021), including IWO psychology (Guzzo et al., 2022). As an illustration, we examined empirical articles published in the Journal of Applied Psychology and the Zeitschrift für Arbeits-und Organisationspsychologie in all issues published in 2025 and up to May 2026. Only 44.2% (42/95) of empirical articles in the Journal of Applied Psychology and 11.8% (2/17) of empirical articles in the Zeitschrift für Arbeits-und Organisationspsychologie made the data underlying the reported findings openly available. 1 1 The complete results of this analysis are available in the online supplemental materials at Zenodo (Tables S2 and S3; https://doi.org/10.5281/zenodo.23099186)

Another issue related to data transparency is the documentation of data reuse. Transparent documentation of data reuse helps avoid piecemeal publication, in which multiple publications use the same dataset to address highly similar research questions (Kirkman & Chen, 2011). Such practice is problematic because these publications may create the impression of independent evidence, distorting cumulative knowledge-building. However, standards for the transparent documentation of data reuse are currently not consistently implemented across journals in IWO psychology. Moreover, resources from the open science literature (e.g., Alter & Gonzalez, 2018; Gilmore et al., 2018; Klein et al., 2018; Martone et al., 2018) largely stop at making data available and provide limited guidance on documenting reuse of these data across publications.

In this primer, we aim to address these gaps by focusing on data sharing and the documentation of data reuse in IWO psychology. In the first part, we outline the benefits and practical challenges of data sharing in IWO psychology. We show that although these challenges require careful consideration, they typically do not prevent data sharing, and we offer several recommendations for how researchers, reviewers, and journal editors in IWO psychology can contribute to the implementation of data sharing in the field. Qualitative data raise distinct methodological and practical considerations, such as the difficulty of removing identifying information from interview transcripts or recordings, and we refer readers to existing guidance (e.g., Branney et al., 2023; Endacott et al., 2026; Gilmore et al., 2018). In the second part, we focus on the documentation of data reuse. We explain why transparent documentation matters for evaluating evidence across studies and provide recommendations for documenting reuse in IWO psychology.

Data Sharing in IWO Psychology

Data sharing refers to the practice of making unprocessed or minimally processed data available as part of research (Houtkoop et al., 2018; Martone et al., 2018). According to the German Psychological Society (DGPs; Gollwitzer et al., 2020 Gollwitzer et al., , 2021)), this includes primary data such as item-level survey responses, trial-level experimental data, observational codings, audio/video recordings, and physiological measures. When sharing primary data is not possible due to ethical, legal, or contractual constraints (see section "Ensuring Data Privacy and Security"), researchers may share secondary data derived from processed primary data.

Requirements for Data Sharing

Journal policies are an effective mechanism for promoting data sharing (Giofrè et al., 2017; Guyatt & Storms, 2026; Nuijten et al., 2017). To support journals in implementing such policies, the Center for Open Science developed the Transparency and Openness Promotion (TOP) guidelines, which define three levels of data transparency (Grant et al., 2026; Nosek et al., 2015). 2 Level 1 requires disclosure of data availability; Level 2 requires deposition of data in a trusted repository with proper citation; and Level 3 adds independent verification of data deposition and metadata quality. Several journals in IWO psychology, including Journal of Applied Psychology, Personnel Psychology, Journal of Organizational Behavior, Journal of Business and Psychology, Journal of Managerial Psychology, and Zeitschrift für Arbeits-und Organisationspsychologie, have adopted TOP Level 1 or similar data-sharing policies that require authors to include a data availability statement (see Table S4 in the online supplemental materials at Zenodo for the selected IWO psychology journals, and Table S5 for an overview of data transparency policies in these journals; https://doi.org/10.5281/zenodo.23099186).

Although evidence suggests that researchers in psychology are not always compliant with their data availability statements (Hussey, 2025; Tedersoo et al., 2021; Wicherts et al., 2006), the Journal of Applied Psychology reported a 378% increase in the inclusion of links to repositories since 2020 after implementing the TOP guidelines in 2021 (Eby, 2025). These links may not only refer to data, but also to code or other research materials. Nonetheless, this increase suggests that journal policies, even when only requiring a data availability statement, can encourage researchers to make their data more accessible. At the same time, a recent analysis of articles in 25 APA journals shows that data sharing is more common under stricter policies: 15.0% of articles in journals without a data policy reported shared data, compared with 26.4% in journals requiring a data availability statement (TOP Level 1) and 70.4% in journals requiring data sharing (TOP Level 2; Guyatt & Storms, 2026). Even under mandatory policies, most articles without shared data provided no reason for not sharing their data.

Despite this, many journals in IWO psychology have not yet implemented standards for data sharing (Hüffmeier & Mertes, 2023). Although publishers generally have substantial influence over journal policies and are therefore important actors in implementing changes, journal editors may use their positions to advocate for and support the adoption of such standards in IWO psychology journals.

A common concern among researchers is that data sharing enables "scooping," which means that others use parts of a dataset before the original researchers do (Houtkoop et al., 2018). However, even when journals have policies that require data sharing (currently not the norm in IWO psychology journals), these policies typically require sharing only the data underlying a specific publication, which allows researchers to retain exclusive access to other variables included in a dataset. For example, researchers who have collected multi-wave data from employees can share only the variables and waves analyzed in a given article.

In addition, most journal policies do not require unrestricted public access to data (i.e., "open data; " Hüffmeier et al., 2022). For example, researchers concerned about scooping may provide access only to reviewers and editors during peer review, restrict access to approved users after publication of their study, or delay public release until their studies are published or they have completed their broader research projects. Additionally, researchers could provide synthetic data, which are artificially generated datasets that resemble the original data in their statistical structure, but do not contain real observations. Instead, values are simulated based on patterns in the original data so that key properties (e.g., distributions and relations between variables) are preserved (see Wang et al., 2025, for a guide on the use of synthetic data).

Beyond journal policies, reviewers may increasingly contribute to requirements for data sharing in IWO psychology. When data are not made available, reviewers can request access and encourage authors to deposit their data in a repository, thereby contributing to the adoption of data transparency practices. This aligns with initiatives that emphasize reviewers as agents of change in advancing open science (Morey et al., 2016).

Funding agencies have also introduced increasing expectations regarding data sharing (Houtkoop et al., 2018; Klein et al., 2018). Many funders now require applicants to provide a detailed data management plan that describes how data generated within the project will be documented, stored, and shared. For example, the European Research Council, German Research Foundation, Austrian Science Fund, and Swiss National Science Foundation have policies supporting or requiring open access to research data from funded projects.

Benefits of Data Sharing

Perceived costs are an important barrier to data sharing (Houtkoop et al., 2018; Tenopir et al., 2011). As long as data sharing is optional, researchers weigh the effort, time, and resources it requires against the costs of not sharing, which requires no additional effort, time, and resources.

Incentives are an important means to increase the perceived benefits of data sharing, so that they outweigh these costs.

One example of such an incentive is the Open Data Badge, which was introduced by the Center for Open Science to acknowledge researchers who make their data openly available. 3Journals display these badges in published articles, thereby making data sharing visible to readers. Despite calls for a broader implementation in IWO psychology (Hüffmeier & Mertes, 2023; Torka et al., 2023), only few journals in IWO psychology, such as Organizational Research Methods and Group & Organization Management, currently use such badges.

However, evidence on the effectiveness of badges is mixed. Data sharing increased after Psychological Science introduced badges (Kidwell et al., 2016), whereas a randomized controlled trial at BMJ Open found no increase (Rowhani-Farid et al., 2020). Badges may therefore be most useful in combination with journal policies.

At the funding level, incentives for data sharing include the possibility of budgeting costs for data sharing in grant applications. For example, the German Research Foundation allows applicants to budget for staff, hardware and software, and infrastructure use related to data sharing (Deutsche Forschungsgemeinschaft, 2015). In addition, funders offer dedicated programs for data sharing, such as the Data Reuse Initiative by the Volkswagen Foundation. 4At the institutional level, open science practices are increasingly being incorporated into hiring and tenure criteria at universities and other research institutions. In Germany, this development is in line with recommendations by the German Psychological Society (DGPs; Schönbrodt et al., 2017). For example, some application processes in IWO psychology ask applicants to list their open science activities, including links to shared data. Although implementation currently varies widely, these developments suggest that data sharing can also benefit academic career evaluation and development.

A further incentive for data sharing is academic recognition. First, empirical evidence suggests a potential citation advantage for publications with openly shared datasets (Christensen et al., 2019; Colavizza et al., 2020 Colavizza et al., , 2024)). Second, data sharing enables formal recognition through citations. For example, the APA provides guidelines for citing datasets, specifying that citations should include information on the data creators, year of publication, title of the dataset, and the repository in which the data are deposited (American Psychological Association, 2020).

Third, data journals provide peer-reviewed publication outlets for datasets. Examples of data journals include Scientific Data, Data in Brief, and Journal of Open Psychology Data.

These journals allow researchers to publish data descriptors that provide detailed descriptions of datasets (see Buttler et al., 2026 and Mundnich et al., 2020 for examples from IWO psychology).

Journal editors in IWO psychology could support the sharing of well-documented datasets relevant to the field by advocating for the introduction of data articles as an additional publication format in their journals. This may also increase journal impact, as data articles are often cited when data are reused.

Data sharing also offers several practical benefits. First, it reduces the risk of data loss and supports long-term accessibility, which can be less reliably ensured when data are stored only on local devices or individual systems (Klein et al., 2018). Second, we have experienced that data sharing can facilitate peer review processes. Our openly shared data are often acknowledged in comments from reviewers and editors. We have also found that making data openly available can reduce the need for ad hoc analyses that are sometimes requested by reviewers but extend beyond the scope of a study. When such requests arise, we explain in our response letter why the requested analysis is not included in the manuscript and refer to the openly available data, allowing others to independently conduct these analyses.

The possibility that others may inspect shared data and identify errors can be perceived as a risk of data sharing. However, anticipating that data (and analysis code) will be made openly available may encourage researchers to pay even more careful attention to preprocessing steps, such as exclusion criteria, reverse-coding of items, and computation of scale scores. In our experience, this has helped us identify errors that might otherwise have gone unnoticed. Thus, preparing data and code for sharing can also provide an opportunity to identify and correct errors before they get published. Moreover, data sharing can reduce concerns related to the detection of errors in publications by changing how such errors are interpreted. Sharing data makes clear that errors were not intentionally concealed and can help distinguish unintended mistakes from deliberate attempts to mislead others.

Accessibility

Accessibility refers to how easily data can be obtained once they are located. Although data availability statements often state that data are available "upon (reasonable) request," access to data underlying psychological research is often difficult to obtain (Hussey, 2025; Tedersoo et al., 2021; Wicherts et al., 2006). One way to address this is to deposit data in repositories.

Repositories are online platforms for storing, preserving, and sharing datasets. Compared with sharing data upon request, repositories make data easier to find, preserve them in the long term, allow researchers to add documentation such as codebooks and README files, and facilitate data citation. They also reduce the burden of handling individual requests, at least when access is fully open. Moreover, "data available upon request" often means that researchers reconstruct data and documentation only after a request is received. Interoperability

Interoperability refers to how easily (meta)data can be used across software and combined with other data. Non-proprietary formats such as CSV or TXT facilitate broad accessibility because they are software independent. At the same time, it can be useful to additionally provide data in formats such as SAV (SPSS) or RDS (R), as these can preserve metadata such as variable and value labels and therefore facilitate interpretation of the data. However, when multiple formats are provided, it is important to ensure that the different files are consistent and updated simultaneously when changes are made.

Reusability

Reusability refers to how easily (meta)data can be understood and used by others. To enable reusability, data should be accompanied by comprehensive metadata, including information about the context, quality, conditions, and characteristics of the data. Moreover, researchers should provide information on data provenance, which refers to the origin and processing history of the data.

Although psychology lacks universally adopted metadata standards, researchers in IWO psychology should provide comprehensive metadata using either study-specific schemas or established standards. To support interoperability, standardized approaches should be used, such as the Data Documentation Initiative (DDI) standard, which is well established in the social sciences (Vardigan et al., 2008). 9 However, using DDI requires some training. A simpler alternative is the Dublin Core standard, which uses a small set of general elements (e.g., title, creator, and description). 10 Many repositories also provide structured metadata fields.

Beyond structured metadata, detailed documentation is essential for making data reusable. This includes descriptions of the study design and data collection procedures (e.g., number and timing of measurement waves, sampling approach, and participant characteristics), which can be provided in a README file, as well as a detailed codebook documenting the structure and content of the dataset. README files can also explain what the different files (e.g., datasets in different formats and analysis scripts) contain and how they relate to one another, how the data can be accessed, and any requirements or restrictions on using the data. Codebooks should provide information needed to interpret the data, including variable names and labels, response formats, coding and scoring procedures, and missing-data codes. In multi-wave employee surveys, codebooks should also indicate at which waves each item was administered and whether item wording or response formats changed across waves. To facilitate reuse, researchers should use consistent naming conventions, document data-processing steps (e.g., recoding of variables), and keep documentation and shared data aligned across versions.

As an example of such detailed data documentation, we have developed a web-based data exploration tool as part of a project providing public access to a large-scale longitudinal dataset collected from a large sample of employees in Germany over five years. The tool is designed to facilitate data reuse by offering detailed information on the structure and content of the dataset, thereby allowing users to assess the suitability of the data for their research questions and to develop research questions. 11 To document data provenance, researchers should specify who generated or collected the data, whether the data have been previously published, and how raw data were processed (e.g., exclusion criteria, recoding of variables, construction of scale scores, and handling of missing data). Ensuring Data Privacy and Security

A major concern in data sharing is protecting privacy and complying with legal requirements (Houtkoop et al., 2018). Many datasets collected in IWO psychology contain individual-level data from employees, managers, or job applicants, which may include information that could potentially allow the identification of study participants. This is not only an ethical issue but also a legal issue under data protection regulations (e.g., the European

General Data Protection Regulation).

To reduce the risk of compromising data privacy and security, data should be anonymized by removing personal identifiers prior to sharing.

However, adequate anonymization requires more than the removal of direct identifiers such as names, email addresses, panel IDs, and IP addresses. Even in the absence of direct identifiers, identification may be possible through the combination of indirect identifiers such as demographic or geographic information (e.g., gender, birth date, and postal codes). To reduce the risk of re-identification, researchers can aggregate, recode, or remove variables (Morehouse et al., 2025). For example, dates of birth can be replaced with age, detailed job titles can be recoded into occupational groups, and postal codes can be aggregated at the regional level or omitted.

In IWO psychology, additional challenges for anonymization can arise when data on organizational characteristics are collected. Variables such as industry, organizational size, geographic location, or distinctive organizational practices may allow organizations to be identified, thereby increasing the risk of re-identification at the level of individual employees.

Researchers in IWO psychology should therefore also carefully consider whether potential protection concerns is to share only the subset of data necessary to reproduce the reported analyses (Torka et al., 2023).

Finally, researchers should ensure that informed consent procedures address data sharing (Schönbrodt et al., 2017). Information on data sharing and anonymization should specify whether and in what form anonymized data may be shared, who may access and use the data (e.g., researchers within or outside the institution, the public, or commercial entities), under which conditions (e.g., open or controlled access), and for which purposes (e.g., reanalysis, secondary analyses). In organizational studies, consent information should also state whether the partner organization will receive individual-level data, as employees may otherwise worry about how their employer could use their responses. Data protection officers can support the development of appropriate consent procedures.

Ensuring Author Anonymity During Peer Review

Another challenge for researchers who share their data is ensuring author anonymity during peer review (Obenauer, 2025). When journals use anonymous peer review, researchers need to ensure that neither the repository nor the shared data and accompanying materials reveal their identities (see Table 1). This includes removing author-identifying information from repository metadata, file names and metadata, README files, and documentation. Analysis scripts, outputs, file metadata (especially in PDF or Excel files), and version histories should also be checked for identifying information (e.g., file paths, usernames, or comments). During peer review, researchers can then provide reviewers with access through an anonymous link or by replacing author names with "Anonymous" in the repository project, depending on the options provided by the repository. After the article has been accepted, author-identifying information can be restored in the shared files and repository materials.

Documentation of Data Reuse in IWO Psychology

Many datasets in IWO psychology can be reused across multiple studies. For example, measures of multiple constructs (e.g., work characteristics, job attitudes, performance, wellbeing) allow for different variable combinations, large and diverse samples enable subgroup analyses (e.g., employees from specific industries, different age groups), and multilevel structures can support different analyses at individual, group, and organizational levels.

Such reuse is generally reasonable given the substantial resources required for data collection in work and organizational settings, including recruitment, time (especially in longitudinal designs), participant burden, and financial costs. Moreover, using datasets for only a single study often leaves much of their scientific potential unused. This is particularly relevant in IWO psychology, where many constructs, such as employment characteristics, personality traits, and wellbeing, are also of interest to other fields. From this perspective, data reuse contributes to research sustainability, as it reduces redundant data collection and maximizes the scientific impact of data. However, these benefits depend on ensuring that the same dataset is not used to address identical or substantially overlapping research questions with the same or highly similar sets of variables across multiple publications.

The use of the same data to address identical research questions in multiple publications can constitute duplicate publication under the APA Ethics Code, which prohibits publishing data as original when they have been previously published (Standard 8.13). This also includes publishing the same study in different languages or formats (e.g., a German-language and an English-language journal article, or a journal article and a book chapter). The use of the same data to answer substantially overlapping research questions is addressed in the APA publishing standards under the concept of piecemeal or fragmented publication, which occurs when the same research is unnecessarily divided into multiple publications (American Psychological Association, 2020). 14 Importantly, this concerns not only variable selection but also the scope of research questions. For instance, it is problematic to use the same dataset in separate studies to test directive leadership predicting follower satisfaction in one study and empowering leadership predicting the same outcome in another. Likewise, using the same set of job characteristics in separate studies to predict work engagement and emotional exhaustion can be problematic when both could be examined jointly. In both cases, more integrative designs would allow for direct comparison of effects.

Both duplicate and piecemeal publication are problematic because they undermine cumulative knowledge building by obscuring the non-independence of findings and inflating apparent evidence (American Psychological Association, 2020). To allow others to assess whether data reuse is unproblematic, it is important that prior use of data is transparently documented. Most IWO psychology journals (e.g., Journal of Applied Psychology, Journal of Organizational Behavior, European Journal of Work and Organizational Psychology) require authors to report prior uses of data, including potential overlap with concurrent or planned publications, and describe the distinct contribution of the current study. Such statements and, if applicable, references to publications based on the same dataset can be included in an Openness and Transparency section of the Method. When data overlap exists, authors should clearly explain how studies differ (e.g., research questions, variables, subsamples, or levels of analysis).

Documentation of data reuse will become even more important if data sharing becomes more common, as we hope. Traditionally, data reuse has been largely confined to the researchers who collected the data (i.e., the data creators). Because the number of researchers using the dataset is then limited, data creators can document reuse relatively easily.

Outsiders can in principle reconstruct undocumented reuse by comparing the publications of the data creators, although this can be difficult. When data are shared, additional researchers can analyze the same dataset, which makes reuse even more difficult to trace and document across studies. This issue is also reflected in concerns from other fields, such as psychology and aging research, in which the repeated and uncoordinated use of publicly available large-scale longitudinal datasets has been argued to increase the risk of "data overuse" (Mroczek et al., 2022).

Although it appears relatively unlikely that such overuse occurs for data shared as part of single studies in IWO psychology, the broader concern of how data reuse can be traced and documented across independent research efforts remains. When depositing data, data creators can provide metadata and documentation on how the data have been previously used. However, as data are reused across multiple publications by other researchers, this information must be updated. This is relatively straightforward when data creators reuse the data themselves but requires additional mechanisms when other researchers use the data. Although dataset citations allow tracking of publications that use the same dataset, these citations do not capture which specific parts of a dataset are reused and in what ways.

Therefore, procedures are needed to enable data users to report data reuse in a structured format that can be integrated into existing metadata by data creators or repository systems. For example, data creators may provide a structured form, in which data users can insert the relevant information about their reuse and submit it to the data creators after publication. The data creators could then update the metadata accordingly. More automated solutions are conceivable, and repository operators are encouraged to develop and implement corresponding features to further support data transparency.

Concluding Remarks

This primer highlights substantial potential for advancing data transparency in IWO psychology through data sharing and documentation of data reuse. Implementing these practices as the default requires efforts at multiple levels of the research system, including publishers, editors, funders, universities and other research institutions, as well as reviewers and researchers.

We offer several actionable recommendations involving both top-down regulations and bottomup initiatives. However, change should also start with oneself. Working on this primer has led us to critically reflect on how we share data and document data reuse as part of our research practice, and we have identified several areas for improvement, including sharing data as close to the raw data as possible and providing more detailed documentation. These reflections also illustrate the value of "small wins" in adopting open science practices (Castille et al., 2022): progress does not require getting everything right at once, but can emerge from taking incremental steps toward more open and transparent research practices. For example, researchers who have not shared data before could start by depositing the data and a codebook for their next study in a repository, using the checklist in Table 1. By considering data transparency as a shared responsibility and a continuous process of improvement, we believe that IWO psychology can move toward more open and transparent research.

Nested data pose a related risk. When datasets include team or supervisor identifiers, members of small teams or supervisors who provided ratings may be able to identify individual responses.
