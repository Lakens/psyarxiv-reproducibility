What we found

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

The arrow-word Stroop task measures inhibitory control by assessing the slowing of vocal responses to arrow direction when paired with an incongruent word (e.g., 'LEFT' printed on a right-pointing arrow). This interference is commonly attributed to the automaticity of word reading. However, the same pattern is not observed with manual responses, suggesting modality influences interference. We investigated competing theoretical accounts by systematically manipulating the task-relevant stimulus and response modality. Thirty-two participants (18-52 years) completed two Stroop variants using either manual left/right button presses, or vocal "left"/"right" responses. In each condition the task-relevant stimulus was either the arrow or word, and performance in Pure (100% congruent or incongruent trials) and Mixed (66% congruent, 33% incongruent) blocks were compared with Baseline blocks.

Vocal responses were faster to words than arrows, and incongruent words slowed responses to arrows, but arrow direction did not affect word responses. This pattern reversed for manual responses: button presses were faster to arrows than words, with incongruent arrows slowing word responses. These findings challenge accounts attributing Stroop interference to automatic word processing, instead suggesting interference arises when the task-relevant stimulus requires translation into the response modality while the irrelevant dimension is more directly compatible with that response.

1 Introduction

Suppressing the urge to check a phone notification while studying, or refraining from swearing at work, are everyday examples of inhibitory control: a key executive function that suppresses impulsive or prepotent responses in favour of more appropriate or goal-directed behaviours (Diamond, 2013). Cognitive inhibition, which involves suppressing interference from over-learned responses, is commonly assessed with the Stroop task (Stroop, 1935).

Stroop interference refers to the decrement in performance (i.e. slower responses or increased errors) that occurs when an irrelevant stimulus (typically the presence of a word) interferes with the response required by the task (typically naming the colour the word is printed in).

Despite being studied for almost a century, the mechanisms responsible for the interference remains debated (Macleod, 1991). Traditional accounts emphasise the automaticity of word reading, whereas alternative accounts suggest that interference is determined by how readily competing stimulus dimensions map onto the required response. The arrow-word Stroop task provides a means of investigating these accounts because both the task-relevant stimulus dimension (respond to the word meaning versus arrow direction) and response modality (vocal versus manual button pressing) can be independently manipulated, yet few studies have systematically examined these factors within the same experiment.

Beyond its theoretical importance, Stroop paradigms also have clinical relevance, with subtle impairments in performance observed in preclinical Alzheimer's Disease (AD) (Wells et al., 2025). However, common Stroop paradigms require participants to produce spoken responses, making it difficult to distinguish impaired cognitive inhibition from impairments in speech production (Ivanova et al., 2024). Speech becomes slower and more error-prone with ageing (Gollan & Goldrick, 2019), and is further impaired in neurodegenerative diseases such as Parkinson's Disease (PD) (Mu et al., 2024) and AD (Gerstner et al., 2007; Martínez-Nicolás et al., 2022). A manual Stroop paradigm could therefore reduce the influence of speech-related impairments, provide more precise measurement of response times than voice-based response detection, and facilitate remote or online assessment. Although other inhibitory paradigms such as the Simon (Simon & Rudell, 1967) , and Flanker tasks (Eriksen & Eriksen, 1974) use manual button presses, they assess different forms of conflict and so cannot directly substitute for Stroop interference (Egner et al., 2007; Scerrati et al., 2017). Thus, establishing how Stroop interference operates with manual responses has both theoretical and potential clinical value.

Stroop tasks present stimuli composed of at least two distinct features: the response stimulus (S r ), which is the task-relevant feature participants are instructed to respond to, and the task-irrelevant stimulus (S i ), which must be ignored (see MacLeod, 1991 MacLeod, , 2005 for review) for review). In the classic colour-word Stroop Task (Stroop, 1935), participants name aloud the ink colour of a written word (S r ) and attempt to suppress the tendency to say the written word (S i ); for example, responding "blue" to the word 'RED' printed in blue ink. Stroop interference refers to slower or less accurate responses on incongruent trials, in which S i and S r conflict, relative to a neutral baseline condition (e.g., naming the colour of 'XXXX'). Conversely, Stroop facilitation refers to faster or more accurate responses on congruent trials, in which S i and S r correspond (e.g., saying "red" when presented with the word 'RED' in red ink) compared to baseline (Macleod, 1991).

Although the classic colour-word Stroop task typically requires verbal responses, manual versions that require arbitrary stimulus-response mappings (e.g., press the 'F' key for blue), are also used. These tasks introduce additional response-rule learning demands and produce diminished interference effects. The arrow-word Stroop task (Baldo et al., 1998; Besner et al., 2026; Luo & Proctor, 2013), is an alternative that overcomes this limitation, whereby words with a directional meaning (e.g., 'LEFT' or 'RIGHT') are presented within arrow symbols pointing left or right, thus stimulus features may be congruent (e.g. 'LEFT' presented within a left arrow) or incongruent (e.g. 'LEFT' presented within a right arrow).

Previous manual arrow-word Stroop studies suggest that interference patterns do not align with traditional vocal task, as the arrows disrupt responses to words more than words disrupt responses to arrows (Baldo et al., 1998; Besner et al., 2025; Luo & Proctor, 2013). These findings suggest that Stroop interference does not strictly depend on the automaticity of word reading. As either dimension can serve as the task-relevant stimulus, the Stroop arrow-word paradigm provides a useful framework for systematically manipulating stimulus-response compatibility to evaluate competing theoretical models.

1.1 Theoretical models of Stroop interference

A simple, response speed account (Figure 1A) suggests that the cognitive process that yields faster responses should be considered as more automatic. On the basis of this view, interference in incongruent scenarios is maximal when the stimulus associated with the slower (less automatic) process is nominated as the responding stimulus (S r ), such that the capacity to override the faster, more automatic process (S i ) can be measured in terms of changes to response speed and accuracy (Morton & Chambers, 1973). Indeed, in the classic colour-word Stroop task participants are faster at reading printed words than they are at naming colours. Thus, when responding to the stimulus feature that relies on the less automatic process (i.e., colour naming) and ignoring the stimulus that engages the more automatic process (i.e., word reading) responses are slowed and less accurate on incongruent trials (interference) or hastened and more accurate on congruent trials (facilitation). In contrast, for the reverse configuration -when the response is to the more automatic process (word reading) -the less automatic stimulus feature (ink colour) produces no interference (or facilitation). This unidirectional pattern is referred to as the asymmetry of the Stroop effect.

Word-reading may be a special case of stimulus processing as, in skilled adult readers, it is thought to operate automatically as an overlearned skill that is difficult to voluntarily suppress (see Besner et al., 1997 for review; Samuels & Flor, 1997). According to the reading automaticity model (Figure 1B), the meaning of a written word is activated involuntarily upon presentation, regardless of whether it is relevant to the task. This prediction is supported by findings of the verbal colour-word Stroop paradigm (see Macleod, 1991 for review), and studies of priming that show that word reading is relatively unaffected by other top-down cognitive processes (Tse & Neely, 2007). According to the reading automaticity model, Stroop effect asymmetry should be observed regardless of response modality (i.e., whether responses are vocal or manual) since word reading dominates other stimulus dimensions. However, evidence from both the colour-word and arrow-word Stroop tasks challenge this view. When responses are manual, interference is markedly reduced in the colour-word Stroop task and the direction of interference is reversed entirely in the arrow-word Stroop task -with arrows interfering more with responses to words (Baldo et al., 1998; Besner et al., 2026). These findings are at odds with the idea that word reading is always the more automatic process, challenging strictly stimulus-driven accounts of interference and instead pointing to an interaction between stimulus processing and response selection mechanisms.

The Translation Model (Virzi & Egeth, 1985), proposes that interference between the S i and S r depends on the extent to which the task-relevant stimulus must be translated into the required response format. By this model, interference is predicted to be greatest when the task-relevant stimulus dimension requires translation into the response modality and reduced when stimulus and response formats correspond directly (Virzi & Egeth, 1985). The Translation Model therefore makes similar predictions to the Response Speed account for the arrow-word Stroop task (Figure 1A) with manual responses to words slowed by the presence of incongruent arrows (Baldo et al., 1998; Besner et al., 2026; Luo & Proctor, 2013) consistent with the arrows interfering with the translation of word meaning into spatial coordinates needed to respond. Likewise, saying aloud the direction that an arrow is pointing is predicted to be slowed by the presence of incongruent words (Baldo et al., 1998; Besner et al., 2026; Shor, 1970; Shor et al., 1972) -consistent with interference in the language centres needed for the translation of spatial arrow cues into spoken responses. However, evidence from the less-studied stimulus-response compatible conditions (where translation is minimised) casts some doubt on the Translation model, as incongruent words have been shown to slightly slow manual responses to arrows relative to congruent words (Aarts et al., 2009; Baldo et al., 1998; Roelofs et al., 2006), while incongruent (relative to congruent) arrows have slowed verbal responses to words in one study (Baldo et al. 1998). These findings suggest that Stroop interference effects may not always be asymmetrical, as predicted by the Translation Model. Symmetrical interference effects -where both stimulus features disrupt responding, are predicted by the Dimensional Overlap Model (DOM; Figure 1C; (Kornblum et al., 1990).

The DOM proposes that interference occurs when an irrelevant stimulus dimension shares representational overlap with the relevant stimulus (stimulus-stimulus; S-S overlap), and/or activates a competing response (stimulus-response; S-R overlap). In the arrow-word Stroop task, both arrow direction and word meaning convey spatial information, producing S-S overlap across both manual and verbal responding. With manual responding, both dimensions also map onto spatial left/right actions, producing S-R overlap for both relevant and irrelevant stimuli. Accordingly, the DOM predicts bidirectional and symmetrical interference: incongruent arrows should disrupt responses to words, and incongruent words should similarly disrupt responses to arrows. Previous manual response arrow-word Stroop studies provide partial support for this prediction, with interference reported in both directions, but not necessarily to an equivalent magnitude; interference from arrows when responding to words is typically greater than interference from words when responding to arrows (Baldo et al., 1998; Roelofs et al., 2006). In contrast, for vocal responses, word stimuli map directly onto spoken responses ("left", "right"), whereas arrows do not. This asymmetry in S-R overlap leads the DOM to predict the traditional asymmetrical interference for vocal responding, with incongruent words disrupting arrow naming, but incongruent arrows producing little interference during word reading (Shor, 1970).

1.2 Effects of block structure on inhibitory control

Performance on Stroop tasks is thought to require two complementary processes: resolving interference on individual trials and maintaining task-goals across trials (goal maintenance) (Bélanger et al., 2010; Kane et al., 2007; Kane & Engle, 2003). Resolving triallevel interference involves suppressing the competing response activated by the irrelevant stimulus dimension. Whereas, goal-maintenance keeps attention directed towards the taskrelevant dimension (Kane & Engle, 2003). These processes are considered distinct but complementary aspects of inhibitory control which may be differentially engaged depending on how different trial-types are structured within a block.

In Pure-block designs, a single trial type is presented (i.e. 100% congruent or 100% incongruent trials), allowing stable expectations and strategic responding. For Pure incongruent blocks participants may exploit the S i as a reliable cue to predict the correct response, or use strategic responding (e.g., squint their eyes to minimise interference from the word in order to respond to stimulus features that are just as salient when acuity is diminished, such as arrow direction or font colour). In this way, Pure blocks are thought to be less taxing on goal-maintenance demands. In Mixed blocks, congruent and incongruent trials are randomly interleaved, reducing predictability and increasing goal-maintenance requirements. A higher proportion of congruent trials has been found to reinforce the inappropriate response more often; thus, when an incongruent trial is presented, participants must use goal-maintenance to adhere to the correct task goal, limiting reliance on strategic responding (Logan & Zbrodoff, 1979).

Although the effect of different block structures has been studied and reviewed in the classic colour-word Stroop paradigms (Bélanger et al., 2010; Kane & Engle, 2003; Logan & Zbrodoff, 1979), it is unknown if a similar pattern of responses occurs in the arrow-word Stroop task. Comparing performance on Pure and Mixed blocks in the arrow-word Stroop task allows the opportunity to assess whether interference patterns predicted by theoretical models remain consistent when goal-maintenance demands vary and determine how block structure modulates interference across response modalities during this task.

Thus, this study systematically examined the arrow-word Stroop task to investigate how the dynamics of stimulus-response mapping influences interference and facilitation processes separately for manual and vocal responses and compared the findings to theoretical model predictions (depicted in Figure 1) in both Pure-and Mixed-block designs. Identifying these effects will determine which task configuration most strongly engage inhibitory processes. The findings are relevant for future use of the manual arrow-word Stroop task to assess inhibitory ability in ageing and AD populations, where traditional vocal Stroop responses may be compromised or impractical, likely contributing to the tasks' limited application in these populations (Wells et al., 2025).

2 Method

2.1 Participants

Healthy adults (N = 32, mean (SD) age, 32.5 (10.4) yrs, range, 18 -52; 22 female, 10 male), took part in two versions of the arrow-word Stroop task; a manual task involving leftright button press responses, and a vocal task involving spoken responses. Participants had normal or corrected-to-normal vision, were free from known neurological conditions and could read and write fluently in English. Participants were either a convenience sample recruited via word of mouth, or recruited through the University of Tasmania's Research Participation system for students. All participants provided written consent prior to participation. This study conformed to the principles outlined by the Declaration of Helsinki and was approved by University of Tasmania Human Research Ethics Committee (Approval Number 27255).

2.2 Experimental Setup and Procedure

Participants were seated approximately 60cm from a 25" computer monitor (1920 x 1080, 60Hz) with their forearms resting on a desk. Custom-written software in MATLAB (2023a) running Psychtoolbox-3 (Version 3.0.19) presented visual stimuli on the screen. As shown in Figure 2, the manual task required participants to respond by pressing keyboard buttons with either their left or right index fingers, whereas the vocal task required participants to respond by saying either "left" or "right". 2.2.1 Manual Responses

Participants rested their left index finger on the "F" key and their right index finger on the "J" key of a standard QWERTY keyboard and were instructed to respond to stimuli presented on the screen with a left or right button press as 'quickly and as accurately possible'. Across all trials in all conditions, a fixation cross (+) was presented in the centre of the screen before the imperative 'Go' stimulus. The fixation cue was displayed for a time period randomly selected from a truncated exponential distribution between 0.5s to 1.0s to minimise proactive response anticipation. Feedback was displayed for 1.0s duration after a 0.8sec response time window. If the participant failed to respond within 0.8s, the feedback was 'Go faster'. If they responded with the correct button press within the 0.8s window, the feedback was 'Correct, RT = [x]ms' (where x was the time from Go stimulus presentation to button press); if they responded with the incorrect button press, the feedback was a reminder of the instructed S r , either, "Respond to the Word", or "Respond to the Arrow". For the manual button press conditions, there were 46 trials in each of the two baseline (Conditions 1, 2), Pure Congruent (Conditions 3, 4), and Pure Incongruent (Conditions 5, 6) conditions; there were 54 trials in each of the Mixed conditions (Conditions 7, 8), 36 of which were congruent and 18 incongruent (66.66% and 33.33% respectively). This totalled 384 trials, excluding practice. No other trials were excluded from analyses. One participant did not complete Condition 5 (Incongruent S r Arrow) due to an equipment error.

2.2.2 Vocal Responses

The same eight Conditions in the manual response task were performed in the vocal response task; however, rather than pressing a button, participants vocalised the direction by saying "left", or "right" aloud (Figure 2B). All 48 stimuli within a condition for the vocal task were presented in 6 rows of 8 stimuli on a single screen displayed on the 25" monitor. The size of the stimuli was equivalent between manual and vocal responses, but the format for the vocal response task resembled the standard paper-based Stroop procedure commonly used in clinical and experimental contexts. This format was chosen to allow comparability with the existing vocal Stroop literature. Because the primary aim was to compare interference and facilitation effects within each response modality across stimulus and block conditions, rather than make absolute comparisons in response speed between manual and vocal tasks, differences in presentation format were not expected to influence the theoretical predictions under investigation. Within each vocal Condition, participants spoke aloud their responses to each stimulus, moving from left-to-right through each row, and then onto subsequent rows until they completed all items. As in the manual tasks, the vocal task also comprised a total of 384 trials excluding practice. In the Mixed blocks, 32 trials were congruent and 16 incongruent (66.66% and 33.33% respectively).

Each participant saw the same sequence of cues for each of the eight conditions. The sequence of trials was pseudorandomised so that 1) the correct response was not the same (left or right) for more than 4 trials in a row, and 2) the directions represented by the stimuli were equally presented (i.e., for 50% of the stimuli the correct response would be "left", and 50% "right"). Other than practice trials, no trials were excluded from analyses. Vocal responses were recorded for each condition using audio recording software Audacity (Version

2.3 Statistical Analysis

Data for both manual and vocal responses were analysed separately using R version 4.4.1 (R Core Team, 2024). Random intercepts were always included in the statistical models, but random slopes were included only when the model still converged, and the AIC value was reduced (i.e. improved model-fit). All models were fit using the bobyqa optimizer with increased optimisation iterations to aid convergence (Powell, 2009). Details of model selection and distributions used for manual and vocal response tasks are provided below.

2.3.1 Manual Responses

2.3.1.1 Button Press Reaction Time

Reaction times for correct manual responses (at the single trial level) were analysed using a generalized linear mixed model (GLMM) with a Gamma distribution and log link function, appropriate for the positively skewed RT data (Lo & Andrews, 2015). Bonferroni corrections were used to control the family-wise error rate. For interpretability, model estimates were back-transformed from the log scale.

2.3.1.2 Button press Errors

Accuracy of responding was analysed using a GLMM with a binomial distribution and logit link function. The dependent variable was the binary indicator (errors), coded 1 for incorrect (no response, or inaccurate response) and 0 for correct responses. Participant ID was included as a random intercept (AIC = 2205.02); a random slope for Trial Type was also added (AIC = 2213.80) but did not significantly improve model-fit (χ²(5) = 1.21, p = .944).

Custom contrasts matched those used in the RT model, with Bonferroni correction for multiple comparisons.

4 Discussion

This study provides a novel examination of how stimulus-response (S-R) compatibility influences interference and facilitation effects in the arrow-word Stroop task.

By systematically manipulating response modality (button press, vocal), response stimulus (arrow, word), and block structure (Pure, Mixed blocks), we tested competing theoretical accounts of Stroop interference and facilitation. Importantly, these differing accounts make specific predictions about the pattern of interference within each response modality rather than absolute differences in response speed between manual and vocal responding. A clear crossover pattern emerged: interference occurred in S-R incompatible conditions, when responding vocally to arrows or with button presses to words, but not in S-R compatible conditions, when responding vocally to words or with button presses to arrows. The baseline conditions provide clear evidence that S-R compatibility determines the relative speed of responding. In baseline conditions participants responded fastest and more accurately when the stimulus dimension (S r ) matched the response modality, that is arrows elicited faster (left/right) button presses, whereas written words elicited faster vocal responses. When these features co-occurred in the Stroop task, the interference arose when the S i corresponded to the fastest, most response-compatible dimension, consistent with both Response Speed and Translation accounts. These findings were not consistent with the Reading Automaticity account, which predicts that word reading will dominate processing regardless of response modality and thus the strongest interference would occur when words are the S i . Instead, we observed the opposite pattern: there was greater interference when the word was the target (S r ) and the arrow was the S i.

The results from the manual task diverge from the predictions of the DOM, which would instead predict that either response stimulus would elicit bidirectional interference compared to the asymmetry shown in the present study. The DOM defines the manual arrowword Stroop task as having both S-S and S-R overlap, where the arrow does not share any greater spatial compatibility with the manual response than a written spatial word (Kornblum et al., 1990). Under this account, neither dimension should hold a compatibility advantage over the other in the manual task, and interference should therefore occur to a comparable degree regardless of which dimension is the S r . Contrary to this prediction, we observed a clear asymmetry: interference and facilitation occurred only when the word was the S r and the arrow the S i , not the reverse, which is aligned with the findings of one other recent manual arrow-word Stroop study (Besner et al., 2026). Although some manual arrow-word Stroop studies reported bidirectional interference (Baldo et al., 1998; Roelofs et al., 2006) the effect was not equivalent across dimensions as the DOM predicts, instead, interference found in the previous studies was consistently larger when the word was the S r . Further, the observed asymmetry in the present task suggests that the spatial codes activated by arrows and words are not equivalent in strength for a manual response as the DOM would predict.

Instead, arrows appear to provide a highly compatible, automatic spatial cue that directly activates the manual response, whereas words activate spatial codes only indirectly, via semantic processing. This additional translational step renders word responses vulnerable to the competing and automatic arrow-driven activation leading to interference, while arrow responses remain relatively insulated from competing word-driven activation when manually responding.

Although the present findings are consistent with the Translation Model, they may also be accommodated by accounts of graded compatibility between S-R dimensions (Braem et al., 2019; Lu & Proctor, 2001; Luo & Proctor, 2013). From this perspective, interference reflects the relative strength of representational overlap and automatic cross-activation across domains, rather than a binary presence or absence of translation, as in the Translational Model. For example, words indicating a direction may be compatible with a spatial manual response, however, this spatial compatibility may be less than that of the one between arrows and a manual response. This account suggests that on the manual task, arrows possess maximal spatial compatibility with the response, generating strong, automatic activation that intrudes on responding to the word, whereas words activate spatial codes and generate comparatively weak competing activation failing to disrupt arrow responses (Luo & Proctor, 2013). In the vocal task, the reverse pattern occurs; coupling between words and speech, and weaker associations between arrows and linguistic responses, produces interference and facilitation only when responding to the arrow, not the word (Lu & Proctor, 2001; Braem et al., 2019; Luo & Proctor, 2013). This account could also be used to explain our asymmetrical interference effects observed in both tasks; whereby interference occurs when compatibility between the S r and the response is comparatively weaker than that of S i and the response.

Therefore, an S-R association account or the Translational model could both explain the pattern of interference and facilitation observed here in both the manual and vocal response tasks.

The findings highlight an important design principle for Stroop tasks: inhibitory demands are maximised when the most response-compatible stimulus is assigned as the S i , requiring participants to suppress the faster response in order to respond to the stimulus feature that requires cross-domain translation. In the most commonly used manual Stroop task -the colour-word Stroop task -this criterion is not met as the ignored stimulus (word reading) does require translation across domains to a manual response, while responding to ink colour via an arbitrary button press is not necessarily slower. This may explain the reduced magnitude of Stroop effects observed in manual versions of the colour-word Stroop task compared to the vocal iteration (Augustinova et al., 2019; Kinoshita et al., 2017). In contrast, the manual arrow-word Stroop task studied here yielded robust interference effects when words were assigned as the S r and arrows as the S i.

Block structure also influenced performance. Manual responses to words were faster when a congruent arrow was present in Pure blocks compared to the same congruent trials presented in Mixed blocks. This aligns with previous research showing faster RTs to congruent stimuli in Pure blocks compared to those within Mixed blocks on Stroop tasks (Braem et al., 2019; Logan & Zbrodoff, 1979). In Pure blocks of congruent trials, participants may adopt an alternative task-goal that either responding to the arrow or the word yields correct responses, leading to both components of the stimuli aiding in response selection. Indeed, this may also explain why we observed faster RTs when words were presented with the congruent arrow in Pure blocks compared to the baseline word alone. In contrast, in Mixed blocks, responses to words on congruent trials were not faster than the baseline word alone in the manual tasks. This suggests that despite Mixed blocks containing a higher proportion of congruent trials relative to incongruent trials, the presence of a congruent arrow does not facilitate performance compared to the baseline word alone. A similar pattern emerged in the vocal task, where responses to the arrow paired with a congruent word facilitated overall RT in Pure congruent blocks, but slowed overall RT in Mixed blocks, compared to the baseline arrow. These findings indicate that the effect of block composition on goal-maintenance occur regardless of response modality.

In the manual task we observed that participants' responses to words in Mixed blocks with an incongruent arrow were significantly slower, and more erroneous, than their responses to the Pure-incongruent block. One possibility is that in Mixed blocks the predominance of congruent trials strengthens reliance on the response-compatible dimension, increasing the need to maintain the task goal when an incongruent trial occurs. This passive reinforcement of the unused response pathway may in turn weaken maintenance of the task goal (e.g., responding to the word). This resulted in slowed responses to both congruent and incongruent trials, compared to when trials are completed in Pure blocks, as observed in both response modalities. Inhibition is thought to not only require the ability to resolve interference at the trial level, but also to maintain task goals despite the presence of alternative goals (Bélanger et al., 2010; Cohen et al., 1992; Kane & Engle, 2003). Given that participants were slower and made more errors on incongruent trials when responding manually to the word in Mixed conditions compared to Pure blocks, our findings support this view that inhibition reflects two concurrent mechanisms: resolving interference at the trial level and maintaining task goals across trials.

These findings support the use of the manual arrow-word Stroop task as a sensitive measure of inhibitory control in healthy adults. This paradigm may be especially useful in evaluating inhibitory control in clinical groups, including those with, or at risk of, AD. On the manual colour-word Stroop task, people with preclinical AD exhibited greater interference than age-matched healthy older adults (Hung et al., 2022). Similarly, vocal responses to the colour-word Stroop task progressively impaired across healthy ageing, MCI, and AD groups (Bélanger et al., 2010). Therefore, the arrow-word Stroop task, which can be assessed online with manual keyboard responses may provide a practical and specific measure of inhibitory control. It could be used in both healthy and clinical populations, without confounding speech-related factors such as articulation issues, vocal hesitations, difficulty with artificial intelligence (AI) transcription errors or age-related language change.

Our study had several limitations. First, the manual and vocal tasks differed in their design, with manual task having trial-level data and the vocal task having block-level measures. Thus, absolute response times were not compared directly across response modalities. Instead, the analyses focused on within-task patterns of interference and facilitation relative to each task's own baseline conditions, as the primary objective was to determine whether the direction and magnitude of interference within each response modality were consistent with predictions from competing theoretical accounts. Relatedly, because RT in the vocal task was recorded at the block level, the Mixed condition reflects an aggregate RT across congruent and incongruent trials within that block, precluding separate estimation of congruent-and incongruent-trial RT within Mixed blocks, unlike the trial-level manual data. The vocal task required sequential responding across a visual array, whereas the manual task involved discrete trial-by-trial responses, and future work should determine whether presentation format contributes independently to interference patterns. Secondly, using a written word as the response stimulus requires rapid word recognition, which may depend on a general reading or English-language fluency level. Given that our participants were an educated, English-speaking, convenience sample, the impact of reading fluency was likely reflected in our relatively small proportion of errors and corrections observed in the vocal task. Purely spatial Stroop tasks, such as the arrow-position Stroop (see Viviani et al., 2024 for review) which manipulates arrow direction and screen position (on the left or right side of the display; congruent or incongruent with arrow direction), may offer an alternative design that eliminates linguistic processing demands and isolates interference resolution within the spatial domain.

5 Conclusion

In summary, this study examined how stimulus-response mapping shapes interference and facilitation in the arrow-word Stroop task. Across manual button-press and vocal paradigms, interference and facilitation were present when translation between stimulus and response domains was required. This crossover pattern is consistent with the Translation and Response Speed accounts but challenges explanations based solely on word-reading automaticity and the bidirectional interference predicted by the DOM. Further, Mixed-block designs may be better suited to assessing both interference resolution and maintaining tasklevel goal. Together, these findings demonstrate that Stroop interference is determined not simply by the properties of the stimulus, but by the relationship between the relevant and irrelevant stimulus dimensions, the required response, and the broader task context.
