To fix Exact P-Values

Show details

Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

P-Value Text
p > .17 In study 1, the disclaimer did not significantly affect any outcome (all p > .17).
p > .19 In study 2, it did not significantly affect empathy, reliability, or comprehensibility (all p > .19).

The APA manual states: Report exact p values (e.g., p = .031) to two or three decimal places. However, report p values less than .001 as p < .001. However, 2 decimals is too imprecise for many use-cases (e.g., a p value meta-analysis), so report p values with three digits.

American Psychological Association (2020). Publication manual of the American Psychological Association, 7 edition. American Psychological Association.

To improve Non-Significant P Value Check

What we found

We found 4 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

How Exact P-Values works

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Abstract

Large language models are increasingly used by the public as a source of medical advice, yet they can produce plausible but incorrect output. Disclaimers about the limitations of artificial intelligence (AI) are the most common safeguard and are also anchored in regulatory frameworks such as the European Union's AI Act. Whether disclaimers change how laypeople perceive and act on AI-generated medical advice, however, is unknown. We conducted two preregistered, randomized between-subjects survey experiments with US participants recruited via Prolific (study 1: N = 399; study 2: N = 396). Participants read four simulated dialogues in which a patient received medical advice from an AI tool and were randomized to see a disclaimer below the advice or no disclaimer. Study 1 used the standard disclaimer of a popular chatbot; study 2 used a stronger disclaimer that explicitly highlighted the higher risk of error compared with physicians and required participants to confirm having read it. Participants rated the advice's empathy, reliability, and comprehensibility and their willingness to follow it. In study 1, the disclaimer did not significantly affect any outcome (all p > .17). In study 2, it did not significantly affect empathy, reliability, or comprehensibility (all p > .19). Willingness to follow the advice was slightly lower with the disclaimer (p = .039), but this effect did not remain significant after correcting for multiple testing. Furthermore, there was no significant difference between the two disclaimers. Disclaimers may thus serve mainly as transparency and liability measures and should not be relied on alone to protect users. Alternatives, such as communicating uncertainty within the response and strengthening AI literacy, deserve evaluation.

Introduction

In recent years, artificial intelligence (AI) has evolved rapidly, with various applications across healthcare. AI systems are already used for clinical tasks such as diagnostics, treatment personalization, and gene editing [1]. In addition to these specialized applications, large language models (LLMs) such as ChatGPT are an emerging contact point for health-related questions for the general public [2]. These tools offer instant feedback and low-threshold access to medical information, which is particularly promising for people with limited access to health care services or financial constraints [3]. They also provide a sense of anonymity compared with face-to-face encounters, which can be especially relevant for stigmatized health issues [4].

As LLMs also achieve high diagnostic accuracy in common medical scenarios [5] [6] [7], they could thus help to relieve the strain on our healthcare system. However, other studies highlight significant limitations of LLMs in this context. In prior studies, diagnostic accuracy was mainly assessed with standardized vignettes or exam questions that contained all relevant information [8, 9]. Such scenarios, however, do not fully reflect the nature of real clinical encounters. Crucially, more recent studies, which investigated LLM performance in more naturalistic settings, showed substantially worse diagnostic accuracy [10]. A major reason for this discrepancy is suboptimal user behavior. Users often do not provide enough (or the key) information, which would be required for the model to provide an accurate assessment [10, 11]. Due to these obstacles in human-AI interaction, LLMs still frequently provide plausible, but factually incorrect responses. In medical contexts, reliance on such incorrect information can have serious consequences.

Disclaimers as a safeguard

Disclaimers are short notes about the limitations, biases, and potential inaccuracies of AI systems. Companies often use them for legal reasons, to distance themselves from content and exclude liability [12]. Within the present study, we focused not on this legal function but the informative and warning function: whether a disclaimer changes how users perceive and act on AI-generated medical information. While intuitively plausible, empirical evidence for such a warning effect is weak. In a series of studies, disclaimers had no effect on perceived credibility of AI-generated scientific information [12]. Other studies found no effect of limitation disclaimers on trust in a conversational agent [13] or on reliance on AI-generated misinformation [14]. In the only study in the medical context we are aware of, a randomized trial with medical students, a "can make mistakes" warning did not affect responses to AIgenerated diagnostic advice, possibly because students already attributed little credibility to the AI [15]. How disclaimers change medical laypeople's perception of AI-generated medical advice, however, has not been tested yet. Since laypeople lack the expertise to critically evaluate the accuracy of medical information, disclaimers may have a stronger influence on them.

Regulatory context

Recent regulatory developments have made it necessary to consider how disclaimers affect the perception of AI-generated information. This especially regards the European Union's AI Act (Regulation 2024/1689) [16], which entered into force in August 2024. It is the first comprehensive law on AI and regulates the development and use of AI systems in the European Union. Because of this pioneering role and as products must be adapted to EU standards, it is expected to influence AI development globally [17]. A central measure of the EU AI Act to protect users from the risks posed by AI is transparency. First, Article 50 requires that people must be informed when they interact with an AI system and that AI-generated content must be marked as such. Second, Article 13 requires that high-risk AI systems, which includes medical devices, must be accompanied by instructions for use describing their capabilities, and limitations [16]. Notably, Article 13 addresses deployers rather than end users, so how information about AI limitations should reach laypeople is left to implementation.

Understanding whether limitation disclaimers affect user perception is therefore relevant for the design of transparency measures and, more broadly, to evaluate the effectiveness of such measures in general.

The present research

We conducted two randomized online experiments to test whether a standard disclaimer (i.e., the disclaimer used by Google's Gemini in April 2025; study 1) and a strong disclaimer emphasizing AI risks (study 2) influence the perception of AI-generated medical advice. We hypothesized that disclaimers would increase awareness of AI's limitations and thereby lower ratings of perceived empathy, reliability, and willingness to follow the advice. As perceived comprehensibility is a more technical characteristic, no effect was expected for this dimension.

In an exploratory analysis, we further compared both experiments to test whether the strong disclaimer had a larger effect on user perceptions than the standard disclaimer. Contrary to our hypotheses, neither disclaimer significantly changed participants' ratings or behavior.

Materials and methods

Overview and ethics

Two online experiments with identical structure were conducted sequentially with independent samples. Participants (study 1: N=399; study 2: N=396) were randomly assigned to a disclaimer or a no-disclaimer condition. In both studies, they were presented with four simulated dialogues of patients consulting an AI tool for medical advice. Using established Likert scales, they evaluated the presented advice in terms of perceived empathy, reliability, comprehensibility and willingness to follow. The key difference between both studies was the wording of the disclaimer (see Table 1). We received ethics approval by the ethics committee of the Institute of Psychology of the University of Würzburg (reference number: GZEK 2023-66), and the research was conducted in accordance with the Declaration of Helsinki. All participants provided written informed consent electronically before taking part, were compensated for their efforts and debriefed about the study purpose at the end of the experiment. Data collection took place from 10 th to 14 th of December 2025 (study 1) and from 5 th to 8 th of May 2026 (study 2). Both studies were preregistered before data collection (https://osf.io/93n5w/overview?view_only=2ed21149959749119e18e4bbc69ac9b6 https://osf.io/tqw4m/overview?view_only=a5ee1f8236d2492a8a4c6f2e6b58c513)

Sample

Participants were recruited via Prolific. An a priori power analysis for a linear mixedeffects model with one fixed effect (disclaimer vs. no disclaimer) and two random intercepts (participant and scenario) indicated a required sample size of N=390 to achieve a power of 90% (standardized regression weight β = 0.3, α = 0.05, 5000 simulations, calculated in R with the simr package, v.1.0.11). To account for dropout, we preregistered 400 participants as our target sample size for both studies. We exclusively recruited participants from the US and stratified both samples across gender, age and ethnicity to approximate the composition of the US population (based on a simplified US census, following Prolific's representative-sample procedure). Due to a sampling error, we collected data from 404 participants in study 1 and from 400 participants in study 2. All conclusions for study 1 remain unchanged if the four latest datasets are excluded. As preregistered, we excluded participants who failed the attention check (study 1: 5 participants; study 2: 4 participants), leading to final sample sizes of 399 (disclaimer: 183, no disclaimer: 216; gender identities: 197 females, 194 males, 5 non-binary participants, 3 participants preferred to not disclose gender information; age: M = 46.9 years, SD = 16.5 years) and 396 participants (disclaimer: 201, no disclaimer: 195; gender identities: 197 females, 191 males, 7 non-binary participants, 1 participant preferred to not disclose gender information; age: M = 46.1 years, SD = 16.9 years), respectively.

Materials

Each participant was presented with four simulated dialogues, each consisting of a medical question posed by a patient and a respective response, labelled as coming from an AIsupported chatbot. These dialogues were adapted from Reis et al [18] and covered four medical topics (colonoscopy, agoraphobia, smoking cessation, and reflux disease). The shown questions were constructed and validated by a certified physician and responses were checked for factual accuracy.

In the disclaimer condition, a disclaimer was shown in bold directly below each AI response (see Table 1). In study 1, the disclaimer reproduced the text that Google's Gemini displayed in April 2025. In study 2, the disclaimer was reworded to emphasize the risks and limitations of AI. To ensure attention to the disclaimer, participants in study 2 additionally had to tick a box below each disclaimer confirming that they had read and understood it. After each dialogue, participants rated the advice on four 7-point scales (adapted from Reis et al [18]): empathy (very unempathetic to very empathic), reliability (very unreliable to very reliable), comprehensibility (very difficult to very easy to understand), and willingness to follow the advice (very unwilling to very willing).

Procedure

Participants viewed all four scenarios in random order and rated each immediately after reading it. After the fourth scenario, they were offered the option to save a fictitious link to the AI tool that had supposedly answered the patients' questions. This question was implemented as a behavioral indicator of willingness to consult AI for medical advice (see Castelo et al [19]).

As an attention check, participants then were asked whether the advice was labelled as coming from a human physician or an AI chatbot. In addition, participants in the disclaimer condition were questioned about how the disclaimer had affected their perception of the advice. Finally, for exploratory analyses, we assessed participants' attitudes toward AI with two questionnaires (the ATTARI-12 [20] and the health care section of the ATTARI-WHE [21])

Statistical analysis

Analyses were conducted in R (version 4.5.3), using the lme4 (v. 2.0-6) and the lmerTest (v. 3.2-1) packages. The underlying data and analysis script is available in the OSF repository (https://osf.io/vt24z/overview?view_only=39684a6679f244ea94d8fe965852fed7). Each outcome was analyzed separately with a linear mixed-effects model including disclaimer (dummy coded, disclaimer condition as reference) as a fixed betweensubjects factor and random intercepts for participants and scenarios. We report unstandardized coefficients (b) as the mean difference in scale points between the no disclaimer and disclaimer conditions, together with 95% Wald CIs (b ± SE*1.96). Additionally, Cohen's d is reported as an effect size measure. Because four outcomes were tested per study, we applied a Bonferroniadjusted threshold for statistical significance of p<.0125.

For the exploratory analysis of saved links to the fictitious tool, we calculated a binomial logistic regression (link saved vs. link not saved) with disclaimer condition as predictor; effect sizes are reported as odds ratios (ORs). To compare both experiments, we combined data from both studies and calculated linear mixed-effects models containing disclaimer, study, and their interaction as fixed effects as well as participant and scenario as random intercepts. To allow a meaningful interpretation of the results for both fixed effects, these were effect coded (disclaimer = 1 and no disclaimer = -1; study1 = 1 and study2 = -1).

Finally, we tested whether the effect of disclaimers on the four outcomes depended on participants' attitudes toward AI (measured via the ATTARI-12 score and the health care score of the ATTARI-WHE). Therefore, we calculated two separate ordinary least squares moderation models for each dependent variable (using Hayes' PROCESS macro, model 1).

Simple slopes were probed at the 16th, 50th, and 84th percentiles of the moderator. Results are reported in S1 Appendix.

Discussion

Summary

In two randomized experiments (N=795), we found no credible evidence that disclaimers about AI limitations meaningfully change how laypeople perceive AI-generated medical advice. This outcome held true across various rating dimensions (perceived empathy, reliability, comprehensibility and willingness to follow the advice) as well as for an exploratory behavioral measure (the share of participants who saved a link to the presented AI tool).

Furthermore, this null finding applied to a standard disclaimer (as used by Google's Gemini in April 2025) as well as for a stronger disclaimer, which explicitly highlighted error risk of AI.

Our results are consistent with previous research in other domains showing that disclaimers have no reliable influence on perceptions of AI-generated content [12], trust in conversational agents [13], or reliance on AI-generated misinformation [14]. They also parallel the finding that warnings did not influence medical students' use of AI-generated diagnostic advice [15]. The present research extends these findings to medical laypeople, who may be particularly vulnerable to misinformation. For this group, the warning function of disclaimers would be the most important. As our results show, disclaimers do not shift perceptions of AIgenerated information or related behavioral intentions, even in this setting.

Several explanations for the present null findings are plausible. Participants may already hold a baseline skepticism toward AI-generated medical advice [18], so a disclaimer (especially the standard disclaimer in study 1) adds little information [15]. This assumption, however, stands in contrast to our exploratory moderation analyses. These showed that (at least for certain dimensions), disclaimers reduced ratings more, the more negative attitudes people indicated toward AI in general and specifically within healthcare. Furthermore, disclaimers are now commonly part of AI-generated information, especially for higher urgency cases [22].

Accordingly, people may have habituated to such information and no longer pay much attention to it. We tried to address this issue in study 2 by making participants explicitly confirm that they have read and understood the disclaimer, which however did not change the results.

Nevertheless, it is possible that even in this case, participants did not really process the provided information and perceived it as some kind of "boilerplate". In line with such reasoning, several participants indicated in the follow-up questionnaire that they believe that the disclaimer mostly serves transparency and liability reasons and they therefore did not pay much attention to it. From a metacognitive perspective [23], disclaimers may thus trigger monitoring (users register the disclaimer information), without triggering control (users do not adjust how they evaluate the advice).

Implications

Our findings suggest that limitation disclaimers function mainly as a transparency and liability measure. However, transparency alone may be insufficient to protect users from the risks of AI-generated medical advice. This outcome may be critical for AI regulation. For instance, the EU AI Act establishes transparency as a key measure to protect users from risks of AI use [17]. The result that disclaimers do not change the evaluation of AI-generated medical advice, raises doubts as to whether these measures really fulfil their intended goal.

Policymakers and AI developers should therefore avoid treating disclaimers as a sufficient safeguard and should evaluate transparency measures empirically before deployment.

Furthermore, alternative approaches deserve testing. A communication style reflecting a certain degree of uncertainty, rather than adding a disclaimer to a confidently phrased answer, lowered trust in AI in earlier work [13] and may encourage more critical use. Educating users about how LLMs work could allow for more informed decisions about reliance, although the evidence is nuanced: higher AI literacy was associated with greater trust in one study, whereas medium literacy was associated with more skepticism in high-stakes scenarios [24].

Strengthening metaknowledge, that is, awareness of one's own limitations, may also promote critical use. The combination of both AI literacy and metaknowledge may enable users to evaluate AI output properly, rather than being excessively skeptical or blindly trusting [25].

Limitations

The present work has several limitations. First, all advice was verified by a physician and therefore medically accurate. However, disclaimers may work differently for advice containing (obvious) errors. Future studies should manipulate the accuracy of the advice, with appropriate ethical safeguards and debriefing about misleading content. Second, participants evaluated fixed, single-turn dialogues and had to adopt the perspective of another person.

Third, next to our exploratory behavioral measure, all outcomes were self-reported ratings, which can be subject to response biases. Fourth, all participants were recruited from the US via an online panel, so the findings may not generalize to other countries, health systems, or populations with different levels of exposure to and experience with AI tools.

Conclusions

Across two randomized experiments, neither a standard nor a strong disclaimer about AI limitations affected laypeople's perception of or willingness to follow AI-generated medical advice. Disclaimers therefore appear to primarily fulfill a transparency and liability function but do not necessarily encourage critical engagement with AI-generated content. Given the reliance of regulatory frameworks on transparency measures, these findings suggest that disclaimers alone may not provide adequate protection for users. Future research should evaluate additional approaches, such as communicating AI uncertainty, and explore interventions that strengthen AI literacy and metaknowledge.
