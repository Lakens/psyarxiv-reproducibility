To check Non-Significant P Value Check

What we found

We found 3 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

Text Sentence
p = 0.5 Nor should p = 0.5 be interpreted as prior information that a nonzero difference is small or large; that information comes from difference_family and difference_scale.
p = 0.5 With p = 0.5, equality and difference have equal prior odds for every interaction difference.
p = 0.10 A smaller value, such as p = 0.10, expresses a prior expectation that differences are sparse.

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Network models are increasingly used to model multivariate data and many research questions are about whether networks differ across groups. This tutorial provides an accessible introduction to Bayesian model-selection for testing group differences in networks, as implemented in the R package bgms. This approach provides posterior inclusion probabilities and Bayes factors for each group difference, allowing researchers to distinguish evidence for a difference from evidence for equality. We focus the tutorial on group differences in ordinal network models, since the vast majority of data in cross-sectional research are measured on ordinal scales. We explain the model parameters, prior choices, missing-data handling, convergence checks, checks of model fit, and the interpretation of posterior summaries of group differences. The workflow is illustrated with a reproducible comparison of problematic pornography use symptom networks in women and men.

1 Introduction

Statistical network models-including the Gaussian Graphical Model (GGM), the Ising model, and Mixed Graphical Models (MGMs)-have become standard tools for analysing multivariate crosssectional data in the social and behavioral sciences (Epskamp et al., 2016 (Epskamp et al., , 2018;; Haslbeck & Waldorp, 2020; van Borkulo et al., 2014; Williams & Mulder, 2019). In many studies, the primary question is whether such networks differ across populations: Researchers may wish to contrast relations between modeled variables between persons with different demographics; with or without risk factors, or with or without a clinical diagnosis.

Several existing methods allow researchers to infer group differences in networks. Frequentist procedures such as the Network Comparison Test (NCT; van Borkulo et al., 2017), Fisher's z-tests, SEM-based iterative pruning (Epskamp et al., 2020), the Moderated Network Model (MNM; Haslbeck, 2022), or the Fused Graphical Lasso (FGL; Danaher et al., 2014) provide estimates for group differences and select which group differences are zero in the population. Many of these methods have the downside that they do not provide principled measures of uncertainty due to the use of regularization or sequential estimation methods. In addition, in conventional frequentist testing workflows, a non-significant group difference can be difficult to interpret: It may reflect either a truly small or absent difference, or insufficient information in the data.

The difficulty of distinguishing evidence for equality from insufficient information was addressed by Williams et al. (2019), who implemented edge-wise Bayes factors and posterior-interval thresholding in the BGGM package, allowing researchers to quantify evidence for both the presence and absence of group differences. In this approach, the networks of both groups are estimated separately, and differences between corresponding edges are evaluated. These comparisons account for uncertainty in the group-specific edge estimates. A limitation of this edge-wise approach is that it does not place a joint selection prior on the complete configuration of cross-group differences. Consequently, the assessment of a given difference is not averaged over uncertainty about which other parameters are equal across groups. Bayesian variable selection addresses this limitation by assigning prior probabilities to whole configurations of edge differences and assessing them via inclusion Bayes factors (Hinne et al., 2020; Marsman, van den Bergh, & Haslbeck, 2025). The method thereby represents uncertainty about which cross-group differences are exactly zero and averages the evidence for any given difference over the possible configurations of all remaining differences. Importantly, this selection concerns the structure of the cross-group differences, not the presence or absence of edges within each group's network: the average interaction parameters remain continuously estimated. This paradigm provides both (i) familiar point and interval estimates and (ii) posterior probabilities that a given group difference is present-thereby distinguishing absence of evidence from evidence of absence. This approach has recently been developed by Marsman, Waldorp, Sekulovski, and Haslbeck (2025) and is implemented in the R-package bgms (Marsman & van den Bergh, 2026).

While this new methodology is attractive to the many researchers interested in group differences in networks, the existing literature on this new methodology is too technical for most applied researchers (e.g., Marsman, Waldorp, Sekulovski, & Haslbeck, 2025) and does not focus on the practical workflow of applying this methodology in practice. In this tutorial, we provide an accessible explanation of the methodology and walk the reader through the full workflow using a reproducible empirical example application. Specifically, we will analyse a dataset on problematic pornography use (PPU) and compare networks between females and males. We walk the reader through the specification of the model including all priors, convergence checks, checks of model fit and the interpretation of the result posteriors of parameter estimates and inclusion probabilities. Like most cross-sectional datasets, this dataset consists of ordinal measurements and we therefore focus the tutorial on testing group differences in an ordinal network model, the ordinal Markov Random Field (Marsman, van den Bergh, & Haslbeck, 2025).

2 Overview of Methodology

Here we provide the theoretical background of the Bayesian test for group differences in network models. We first introduce the ordinal network model and explain the meaning of its parameters (Section 2.1). We then show how each parameter is decomposed into an average and a group difference (Section 2.2). For every group difference introduced in that section, Bayesian model selection determines whether it should be fixed to zero or freely estimated. Because these decisions are made jointly, the method considers different configurations of group differences while accounting for uncertainty about which other parameters differ (Section 2.3). Finally, we describe how posterior inclusion probabilities and inclusion Bayes factors quantify the evidence for or against the presence of each group difference (Section 2.4).

2.1 Understanding the Ordinal Network Model

The Ordinal Markov Random Field (OMRF) is a probabilistic graphical model for multivariate ordinal data, such as responses on Likert-type scales. It generalizes the Ising model, which is limited to binary variables, to variables with multiple ordered categories (Marsman, van den Bergh, & Haslbeck, 2025). Variables are represented as nodes and conditional associations between pairs of variables are represented as edges. An absent edge indicates that two variables are conditionally independent given all other variables in the network.

The OMRF specifies a joint distribution for all variables. Its node-wise conditional distributions can be understood as ordinal logistic regressions in which each variable is predicted by all other variables. The model contains two types of parameters: An interaction parameter for every edge and a set of J -1 category parameters for a variable with J response categories. Although the regression analogy is useful for interpretation, these are not separate directional regressions: The edge between two variables is represented by a single symmetric interaction parameter.

Edge Parameters. The edge parameter σ ij describes the conditional association between variables X i and X j , holding all other variables constant. Its interpretation is similar to that of a coefficient in logistic regression: A one-category increase in X j multiplies the odds that X i falls in category h + 1 rather than the adjacent category h by exp(2σ ij ). For example, σ ij = 0.20 corresponds to an adjacentcategory odds ratio of exp(0.40) = 1.49. When σ ij = 0, this odds ratio equals one and the variables are conditionally independent. When σ ij > 0, higher categories on one variable are conditionally associated with higher categories on the other; when σ ij < 0, higher categories on one variable are conditionally associated with lower categories on the other. Unlike a partial correlation, σ ij is neither standardized nor bounded. Its magnitude is therefore best communicated through the corresponding odds ratio or model-implied probability differences. These conditional associations should not be interpreted as causal effects.

Threshold Parameters. The threshold parameters µ ih can be understood as category-specific intercepts. Using category 0 as the reference category, exp(µ ih ) is the odds of category h relative to category 0, conditional on every variable connected to X i also being in category 0. This all-zero configuration is a highly specific state of the network and may be rare, atypical, or of little substantive interest. Consequently, a threshold parameter does not generally describe the marginal response tendency of X i , nor the odds for a typical observation: As soon as any connected variable differs from zero, the edge parameters modify these odds. Interpretation also depends on the arbitrary choice of category 0 as the reference. Individual threshold parameters will therefore generally not be the main focus of interpretation; their primary role is to provide the conditional baseline from which the remainder of the network modifies the response probabilities.

Unlike in a Gaussian graphical model, the mean of a variable is not a separate model parameter. The marginal response distribution, and therefore any mean computed from it, is implied by the complete joint distribution, including both the threshold and edge parameters. Marginal probabilities can be calculated by enumerating all possible response configurations in small networks or approximated by sampling from the fitted model in larger networks. For ordinal variables, model-implied category probabilities or the probability of exceeding a substantively meaningful category may be more informative than a mean, whose interpretation assumes meaningful distances between response categories.

2.2 Modeling Group Differences

To compare two independent groups, each model parameter is expressed as an average parameter and a group difference. This parameterization isolates the quantity of substantive interest-the group difference-while the average parameter describes the structure shared across groups.

For example, consider the interaction between variables i and j. Instead of estimating two unrelated interaction parameters, the model estimates an average interaction σij and a difference parameter δ ij . The interaction is then σij -δ ij /2 in Group 1 and σij + δ ij /2 in Group 2. Thus, δ ij is the interaction in Group 2 minus the interaction in Group 1. If δ ij = 0, the groups have the same interaction parameter. Importantly, this does not imply that the edge itself is absent: Both groups may share the same nonzero edge, just their difference parameter is zero. The focus is thus on modeling and testing the edge differences. The same decomposition is applied to the threshold parameters. The model can therefore test both differences in baseline response tendencies and differences in conditional associations. Since threshold parameters are generally difficult to interpret (see above), group differences in these parameters will not be of primary interest in most applications.

The parameterization using a mean parameter shared across groups plus the group difference mirrors the logic of the Bayesian t-test and allows the model to test whether a group difference is exactly zero while estimating the shared structure at the same time. For technical details, see Marsman, Waldorp, Sekulovski, and Haslbeck (2025).

We now have an explicit model for group differences in both edges and thresholds. The remaining question is which of the difference parameters δ should be included in the model and which should be fixed to zero. The Bayesian model-selection procedure described next addresses this question by considering the inclusion of all difference parameters jointly.

2.3 Selecting Differences Across the Network

Each group difference δ that is placed under selection is paired with a binary inclusion indicator. When the indicator is "off," the corresponding δ is fixed to zero and the parameter is equal across groups. When it is "on," that δ is freely estimated. This is a spike-and-slab prior: the spike fixes a difference exactly at zero, whereas the slab assigns a continuous prior to nonzero differences (e.g., George & McCulloch, 1993). Taken together, these indicators define many possible models, ranging from complete equality between the groups (i.e., all inclusion indicators set "off") to differences in all parameters. In bgmCompare(), interaction differences are selected by default. Threshold differences are instead included as freely estimated nuisance parameters by default; setting main_difference_selection = TRUE also puts them under spike-and-slab selection.

The method uses Bayesian model averaging (Hinne et al., 2020; Hoeting et al., 1998) to move between models with all combinations of group difference indicators being "on" and "off" and thereby account for uncertainty about the presence of group differences when testing any given group difference. We can test whether a given group difference is present by computing the posterior inclusion probability (PIP), which is the posterior probability that this difference is included (i.e., the associated indicator being "on"). For example, a PIP = 0.91 means that there is a 0.91 posterior probability that the group difference is present in the population. Translating PIPs into a binary decision on whether the group difference is present in the population requires cutoff values. Below, we transform PIPs into Bayes Factors and use cutoffs commonly suggested for them. Next to the indicator, we estimate the group difference value δ, which describes the direction and magnitude of that difference. These two summaries should be kept distinct, because strong evidence that a difference exists does not by itself indicate that the difference is large.

Considering all configurations in a single Bayesian model ensures that evidence for one difference is averaged over uncertainty about all other group differences, rather than being conditional on one fixed arbitrary structure of group differences. Whether the analysis also adapts for multiplicity depends on the prior assigned to the inclusion indicators. A hierarchical prior, such as a Beta-Bernoulli prior, treats the common prevalence of differences as unknown and allows the data to inform its posterior distribution, thereby providing multiplicity adjustment. A fixed independent Bernoulli prior does not automatically provide the same adjustment (Scott & Berger, 2010).

2.4 Interpreting Evidence for Group Differences

The posterior inclusion probability (PIP), introduced above, gives the probability that a group difference is included after combining the prior assumptions with the observed data. A PIP close to one indicates that the difference is included in most of the models supported by the posterior, whereas a PIP close to zero indicates that models without the difference receive most support.

To quantify how much the observed data have changed our prior evidence, we compare the posterior odds of inclusion with the odds of inclusion specified before observing the data. This comparison is the inclusion Bayes factor:

The subscript in BF10 indicates that the evidence is expressed in favor of a group difference (H 1 ) relative to no group difference (H 0 ). In most applications, we would give inclusion and exclusion equal probability, which means that the formula for the inclusion Bayes Factor simplifies to BF10 = PIP/(1 -PIP).

A value of 1 means that the data have not changed the relative support for the two hypotheses. A value of 3 means that the data have increased the odds of a group difference by a factor of 3, whereas a value of 1/3 means that the data have decreased those odds by a factor of 3 and therefore support equality between the groups.

We use conventional descriptive thresholds to distinguish three possible conclusions (e.g., Wagenmakers et al., 2018). Values BF10 > 3 indicate evidence for a group difference. Values BF10 < 1/3, equivalently BF01 > 3, indicate evidence that the parameter is equal across groups. Values between 1/3 and 3 are treated as inconclusive: the data provide insufficient evidence for either a difference or equality. The final category represents absence of evidence, whereas BF10 < 1/3 represents evidence of absence. These thresholds are interpretive guidelines rather than absolute decision rules.

3 Application: Network of Problematic Pornography Use

In this application we compare the network of problematic pornography use (PPU) symptoms among women with that among men. Although PPU is prevalent among both men and women (Bőthe et al., 2024), research on PPU has focused almost exclusively on men. Consequently, our current understanding of PPU may not adequately capture the experiences of women. Comparing the symptom networks of women and men provides a first step toward identifying whether PPU manifests differently between men and women. These results may contribute to a more inclusive understanding of PPU that also takes into account the experiences of women.

Given that both potential differences and similarities in symptom networks are of interest, this is a particularly good example to show how to use the bgms package (Marsman & van den Bergh, 2026) to select differences and similarities among groups in ordinal networks. We will walk the reader through setting up the analyses, and how to interpret group differences as well as the evidence that differences are present in the population.

3.1 Sample, Design & Materials

The data come from a study of 1,048 individuals active on self-help forums for pornography addiction (e.g., Subreddit "r/pornfree", for details see Klau et al., 2026). For the illustrative two-group comparison in this tutorial, we restrict the analysis to the 520 participants whose recorded gender identity was "Woman" and the 387 whose response was "Man" whom we refer to as women and men, respectively. The remaining 141 participants comprised 87 who selected "Non-binary / third gender," 36 who supplied another gender identity in a free-text response, 12 who selected "Prefer not to say," and six with no recorded gender response.

Participants reported on several variables related to (problematic) pornography use. Here, we focus on the six core symptoms of PPU, which are also assessed by the short version of the problematic pornography consumption scale (PPCS-6; Bőthe et al., 2021), namely tolerance, salience, withdrawal, mood modification, conflict, and relapse. Tolerance, for example, was assessed by the item: "I felt that I had to watch more and more porn for satisfaction". All symptoms were rated on a 7-point Likert scale ranging from 1 ("Never") to 7 ("All the time"). See Appendix A for the exact wording of each of the six items. The original study was approved by the Ethics Committee of the University of Amsterdam.

3.2 Descriptive Statistics

Before fitting any model, we inspect the data. In the six variables we selected for analysis, no data was missing. To get a sense of the distributions of all variables we inspect the relative frequency of each category in Figure 1: We see that for all variables there are responses on all of the 7 response categories. We also see a large variety of distributions across the six core symptoms: The variables about withdrawal and tolerance are heavily right skewed, the variable about mood modification is lightly left-skewed. While the ordinal MRF can fit any marginal distribution, inspecting the empirical distributions is useful to see whether any categories are missing or have very low probability, which would make it harder to detect edges connected to these nodes as well as group differences in these edges.

3.3 Model Specification and Analysis Workflow

We begin with two prepared data matrices, one for women and one for men. The matrices contain the same six variables in the same column order and use the same ordinal response scale; their rows contain the participants in the respective groups. With these inputs ready, we fit the comparison model using bgmCompare() from the R package bgms (Marsman & van den Bergh, 2026) version 0.2.0.0. The complete analysis workflow from the preparation of the data to reproducing all results and figures in this paper can be found at https://github.com/jmbh/OrdinalNetworkGroupTest.

The four subsections below cover the four steps of the analysis workflow. We first discuss the model inputs and difference-selection options, followed by the specification of all priors and then the settings for missing-data handling and MCMC sampling. These first three steps are brought together in the function call of bgmCompare() shown below. The final subsection turns to model evaluation, covering both the evaluation of the sampling process and the evaluation of how adequately the fitted model represents features of the observed data.

sel_int <-bgmCompare(x = PPU_all_female, y = PPU_all_male, difference_selection = TRUE, main_difference_selection = FALSE, difference_scale = 1, difference_family = "Normal", difference_prior = bernoulli_prior(0.5), interaction_prior = normal_prior(scale = 1), threshold_prior = beta_prime_prior(alpha = 0.5, beta = 0.5), na_action = "impute", iter = 20000, warmup = 10000, seed = 1)

3.3.1 Model Inputs and Difference Selection

The arguments x and y identify women as Group 1 and men as Group 2, respectively. For comparisons involving more than two groups, all observations are instead combined in a single matrix supplied through x, a group-membership vector with one entry per row is supplied through group_indicator, and y is omitted; internally, the G group-specific parameters are represented by G -1 orthogonal contrasts. The corresponding inclusion test is omnibus: exclusion means that the parameter is equal in all groups, whereas inclusion means that at least one group differs.

Before fitting the model, bgmCompare() automatically ensures that the ordinal response categories are the same across groups for each variable. The model uses the union of the categories observed across the groups: A category reported in either group is retained for both groups. A category is removed only when it is unobserved in every group, after which the remaining categories are recoded as consecutive integers starting at zero. Consequently, a category that is absent in one group but present in another is not collapsed with a neighboring category. The group in which that category is unobserved contributes no direct information about its corresponding threshold, so that threshold is more strongly determined by the prior; bgmCompare() issues a warning when this occurs. Both groups nevertheless use the same category coding and parameter structure in the fitted comparison model. In the present dataset each category is observed for all variables in both groups, and we therefore expect no such warning.

The two selection arguments determine which group differences receive the spike-and-slab selection described in Section 2.3. Setting difference_selection = TRUE applies selection to the interaction parameters. If it is set to FALSE, all interaction differences are instead included and estimated without indicators that can switch them off. Since our primary interest is in testing group differences in interactions, we set this argument to TRUE. The argument main_difference_selection analogously controls selection for the threshold parameters. Because thresholds are not the primary interest of our analysis, we set it to FALSE. Selection is therefore performed for interaction differences, while threshold differences are always included and estimated. Consequently, the analysis provides posterior inclusion probabilities and inclusion Bayes factors for interaction differences, but only posterior estimates for threshold differences.

3.3.2 Prior Specification

The prior specification has two layers. Continuous priors describe plausible values for the average parameters and the magnitude of group differences, while a discrete inclusion prior determines whether a difference that is subject to selection is exactly zero. In terms of the parameterization in Section 2.2, the former govern the average interactions σij , average thresholds μih , and differences δ; the latter governs the inclusion indicators γ. Below we briefly explain each prior but we provide an expanded discussion of all priors, including a comparison of default priors with other sensible specifications, in Appendix B.

Average interactions and thresholds. Each average interaction σij receives a zero-centered standard Normal prior, as specified by setting interaction_prior to normal_prior(scale = 1). Zero centering expresses no prior preference for a positive or negative conditional association, and the scale of 1 is a broad general-purpose choice on the corresponding odds-ratio scale. The argument threshold_prior applies separately to the average thresholds μih . Its default symmetric beta-prime specification with shape parameters 0.5 and 0.5 is also centered at zero on the threshold scale, but has heavy tails that accommodate strongly skewed category distributions and rare response categories. The quantile and odds-ratio implications of these choices are shown in Appendix B, Figures 3 and 5.

Magnitude of group differences. Both interaction differences δ ij and threshold differences δ ih receive a zero-centered standard Normal distribution. This is specified by setting difference_family to "Normal" and difference_scale to 1; the scale is therefore not restricted to either type of parameter. For the interaction differences selected in this analysis, this distribution is the continuous "slab" used when an inclusion indicator is on; when the indicator is off, the difference is exactly zero. Because threshold-difference selection is disabled, the same Normal prior applies directly to every threshold difference, all of which are estimated. The Normal default expresses no expected direction, is broad enough to permit sizeable group differences, and has finite tails that tend to be more stable than a Cauchy alternative when parameters are weakly identified. Appendix B gives parameter-scale and odds-ratio quantiles for both families and explains why the scale matters for inclusion Bayes factors.

Inclusion of group differences. Finally, we set difference_prior to bernoulli_prior(0.5). This prior applies to the binary indicators, not to the sizes of nonzero differences. It gives each selected interaction difference prior probability 0.5 of being included, so equality and difference have equal prior odds. For this tutorial, we use this fixed specification for simplicity and transparency: The prior odds are immediately clear, and an interaction's inclusion Bayes factor equals its posterior inclusion odds. This choice is not intended as a general recommendation. In particular, the fixed inclusion rate does not adapt to the evidence for differences elsewhere in the network and therefore does not provide an adaptive multiplicity adjustment. Nor should p = 0.5 be interpreted as prior information that a nonzero difference is small or large; that information comes from difference_family and difference_scale. Researchers who expect differences to be sparse may lower the fixed inclusion probability, whereas those who want the common inclusion rate to remain uncertain and be informed by all selected differences may prefer a Beta-Bernoulli prior. Appendix B, particularly the discussion accompanying Figure 6, compares the interpretation, advantages, and limitations of these alternatives.

Prior sensitivity. Inclusion Bayes factors compare a point null with a continuous alternative and can therefore depend on how widely the slab distributes prior mass over nonzero differences. A sensitivity check is especially useful when the slab scale is not strongly determined by prior knowledge or when an inclusion Bayes factor lies near an interpretive threshold. The prior_sensitivity_check() function in bgms traces how the Bayes factors and evidence classifications change across a specified range of slab scales. Appendix C applies this check to the present analysis using the concentrated and dispersed Normal scales introduced in Appendix B.

3.3.3 Missing Data Handling and Sampler Specification

Missing data can be handled either by listwise deletion, using na_action = "listwise", or by imputation within the Gibbs sampler. We set na_action = "impute", however, this will not affect estimation since our data has no missing data. During sampling, missing responses would then be imputed conditionally the observed variables and the model parameters in the Gibbs sampler. In the terminology of Hand (2020), such imputation yields unbiased estimates under Not-Data-Dependent (NDD) missingness, and also under Seen-Data-Dependent (SDD) missingness provided the observed variables that explain missingness are included in the imputation model. Under Unseen-Data-Dependent (UDD) missingness, where missingness depends on unobserved values even after conditioning on the observed data, imputation based only on the observed variables is biased unless the missingness mechanism is explicitly modeled.

The arguments iter = 20000 and warmup = 10000 request 20,000 post-warmup samples per chain after 10,000 warmup iterations, and seed = 1 makes the analysis reproducible. We used more iterations than the package defaults because shorter preliminary runs showed insufficient mixing for two inclusion indicators. For arguments not shown in the call, we retain the current defaults of four chains and the No-U-Turn Sampler.

3.3.4 Model Evaluation

Evaluating the sampling process. The output object contains posterior draws and summaries for the average edge and threshold parameters, their group differences, and the inclusion indicators. Before interpreting these quantities, sampling diagnostics should be examined for both the continuous parameters and the indicators. The R statistic compares variation within chains with variation between chains (Gelman & Rubin, 1992; Vehtari et al., 2021). Values close to 1 indicate that the chains explored the same posterior distribution, whereas values clearly above 1 suggest that they have not mixed adequately. The effective sample size (ESS) estimates how many independent draws contain approximately the same amount of information as the autocorrelated MCMC draws; a small ESS indicates that posterior summaries may be imprecise even when the nominal number of draws is large. The Monte Carlo standard error (MCSE) quantifies the resulting simulation uncertainty in an estimated posterior summary (Flegal et al., 2008). It differs from the posterior standard deviation: the latter describes substantive posterior uncertainty about a parameter, whereas the MCSE describes numerical uncertainty caused by estimating that posterior quantity from a finite simulation. MCSEs should therefore be small relative to the posterior uncertainty and to differences that will be interpreted.

Because the substantive conclusions depend on the posterior inclusion probabilities, their sampling behavior should be checked directly. The table summary(fit)$indicator reports R, ESS, and MCSE. For indicators with non-extreme inclusion probabilities, values of R close to 1, adequate ESS, small MCSE, and similar inclusion rates across chains indicate stable estimation. When chains disagree researchers should extend warmup or sampling, rerun from another seed, and check whether the inclusion probability and substantive conclusion stabilize. Trace plots of key continuous parameters, divergences, maximum tree-depth warnings, and other sampler warnings should also be inspected. These diagnostics assess the reliability of the computation, not whether the model adequately represents the observed data.

Evaluating model fit. Sampling diagnostics do not establish that the model fits the data. Model fit can instead be assessed with posterior predictive checks, in which statistics computed from the observed data are compared with their distributions in datasets simulated from the fitted model. There is no single set of statistics that evaluates every aspect of fit. The choice should reflect the research question and the features of the data that the intended interpretation requires the model to reproduce. An observed statistic outside its central posterior predictive interval suggests that the model does not adequately reproduce that feature; a systematic pattern across related statistics is generally more informative than an isolated discrepancy.

Here, the research question concerns the association structure among PPU symptoms and whether high symptom responses cluster together. For 500 draws from the joint posterior, we therefore simulate a new dataset with the original group sample sizes and examine three kinds of summaries: all pairwise Spearman correlations, all pairwise proportions for which both symptoms were rated "Often" or higher, and the distribution of the number of symptoms per participant rated at least "Often." The correlations assess broad pairwise association, whereas the latter two summaries assess the co-occurrence and participant-level accumulation of high symptom responses. We do not emphasize marginal category frequencies because the Ordinal Markov Random Field already models each variable's category distribution flexibly through its threshold parameters; reproducing those marginals would therefore provide a comparatively weak test of model fit.

3.4 Results

We first report the sampling diagnostics, then evaluate model fit using posterior predictive checks, and finally inspect and interpret the evidence for group differences.

3.4.1 Assessing Sampling Diagnostics

In the present analysis, all R values are at most 1.003. The MCSEs are at most 0.008 for the continuous model parameters and at most 0.013 for the inclusion probabilities, and the smallest effective sample size among the inclusion probabilities is 1, 396. The sampler produced no divergent transitions and did not reach the maximum tree depth. Taken together, these results indicate that the posterior summaries are sufficiently stable for substantive interpretation.

3.4.2 Assessing Model Fit

All 15 pairwise Spearman correlations in each group fell within their 95% posterior predictive intervals, indicating that the model reproduced the broad pairwise association structure. However, the model systematically underpredicted the joint occurrence of high symptom ratings: 9 of 15 upper-tail co-occurrence proportions among women and all 15 among men exceeded their posterior predictive intervals. The model also predicted too many participants with zero or one symptom rated "Often" or higher and too few participants with several highly rated symptoms. Thus, the ordinal network model captures the overall pairwise association pattern but understates the clustering of high symptom responses. These discrepancies do not directly show that the estimated edge differences are incorrect, but their greater prevalence among men means that omitted dependence could affect the group-specific edge parameters differently. The inclusion Bayes factors should therefore be interpreted as evidence about equality of edge parameters within the fitted ordinal network model approximation, not as evidence that the groups have identical complete dependence structures or identical clustering of high symptom responses. Full results are reported in Appendix D.

3.4.3 Inspecting Group Differences

With these model-fit limitations in mind, we now examine the estimated interaction differences and the evidence for their inclusion. Network models can be represented in different ways. Although nodeand-edge network diagrams are the more common representation, in the main text we show the main results in a heatplot (Figure 2) because it allows us to display the estimates for all parameters clearly and in a compact format. The corresponding network diagrams are shown in Appendix Figure 9.

The top-left panel of Figure 2 displays the interaction parameters of the ordinal MRF for women, and the top-right panel shows the corresponding parameters for men. The bottom-left panel shows the model-averaged differences in the interaction parameters, calculated as male minus female. Thus, positive differences refer to larger interaction parameters among men, whereas negative differences refer to larger interaction parameters among women. These model-averaged difference estimates need not be exactly zero even for edges with little evidence for a group difference. The bottom-right panel shows the evidence classification based on the inclusion Bayes factors. Applying the descriptive cutoffs discussed above leads to group differences classified as present (blue), absent (yellow), or inconclusive (gray). The cell labels provide the estimate or inclusion Bayes factor for every parameter.

For 13 of the 15 edges, we see evidence for equality of the corresponding group-difference parameters, given the fitted model and specified priors. Thus, for these edges, the analysis supports similarity between women and men rather than merely failing to detect a difference. For example, there is evidence that the edge between mood modification and relapse does not differ between men and women. For the remaining two edges-withdrawal with tolerance and withdrawal with conflict-the evidence is inconclusive. Consequently, none of the group differences exceeds the inclusion threshold of BF10 > 3.

For illustration, we nevertheless interpret the group difference with the largest inclusion Bayes factor: The edge between withdrawal and conflict. Its posterior inclusion probability is 0.72 and its inclusion Bayes factor is BF10 = 2.64; Figure 2 reports the inclusion Bayes factors for all edge differences. According to the descriptive cutoffs introduced above, the evidence for the withdrawalconflict difference is inconclusive rather than evidence for a group difference. The edge is estimated to be stronger among women (0.06) than among men (0.03). This means that, holding the other symptoms constant, a one-category increase in conflict multiplies the adjacent-category odds for withdrawal by exp(2 × 0.06) = 1.14 among women and by exp(2 × 0.03) = 1.07 among men. To make the estimated difference easier to understand, we computed model-implied conditional probabilities for withdrawal while holding the remaining symptoms at their reference category. When conflict is at its lowest category ("Never"), the predicted probability of reporting withdrawal at least "Often" is below 0.001 in both groups. When conflict is at its highest category ("All the time"), this probability is approximately 0.004 among women and 0.001 among men. These probabilities do not describe how common withdrawal is overall, but rather what the fitted model predicts in this specific comparison. Although the point estimates suggest a stronger link among women, the Bayes factor does not provide sufficient evidence to conclude that this edge differs between the groups. In addition, the differences in predicted probabilities are very small and perhaps not clinically meaningful.

Because inclusion Bayes factors can depend on the scale of the continuous slab, Appendix C varies the Normal difference scale from 0.5 to 2, matching the two alternatives shown in Appendix Figure 3. Twelve of the 15 edge classifications are stable across this range. The withdrawal-conflict Bayes factor decreases from 12.65 at scale 0.5 to 2.64 at the default scale of 1 and 1.62 at scale 2. Thus, the classification of this borderline edge is prior-sensitive: a more concentrated slab produces evidence for a difference, whereas the default and more dispersed specifications yield inconclusive evidence. This sensitivity does not change the primary analysis, which retains the package defaults, but it precludes treating the withdrawal-conflict result as robust evidence for a group difference.

4 Conclusion

The PPU application illustrates both the value of Bayesian model selection for comparing networks across groups. Most importantly, the method can distinguish evidence for equality from evidence that remains inconclusive, a distinction that conventional nonsignificance does not provide. At the same time, the resulting Bayes factors must be interpreted within the fitted network model and specified priors: in our application, posterior predictive checks identified underestimation of clustered high symptom responses, and the evidence for the most prominent potential group difference was sensitive to the slab scale. Model checking and prior-sensitivity analysis should therefore be treated as integral parts of the workflow. By providing an accessible explanation and fully reproducible workflow-including prior specification, sampling diagnostics, model checking, and sensitivity analysis-we hope this tutorial helps applied researchers conduct more transparent, careful, and informative group comparisons with network models. B.1 Overview and Connection to the Group-Comparison Model

Section 2.2 expresses every group-specific parameter as an average parameter plus or minus one half of a group difference. For an interaction, these quantities are the average interaction σij and the difference δ ij ; for a threshold, they are the average threshold μih and its difference δ ih . When a difference is selected, Section 2.3 additionally introduces an indicator γ that determines whether the difference is exactly zero or receives a continuous slab prior. Prior specification in bgmCompare() therefore concerns three distinct questions: what values are plausible for the average parameters, how large an included group difference may be, and how likely a difference is to be included at all.

Table 2 maps these questions to the relevant arguments. The interaction and threshold priors apply only to the average parameters; they do not determine the priors for group differences. Both interaction and threshold differences are governed by the difference family and scale. The differenceinclusion prior acts at a different level: it specifies the prior for the binary indicators, rather than the distribution of the nonzero parameter values. With the defaults used in this tutorial, an interaction difference has a spike-and-slab prior: it equals zero when γ ij = 0 and follows a standard Normal distribution when γ ij = 1. Because thresholddifference selection is disabled in the present analysis, threshold differences have no spike: they are always estimated and follow the same standard Normal distribution. Enabling threshold-difference selection also gives them inclusion indicators. Disabling difference selection altogether estimates all differences without indicators, in which case the difference-inclusion prior is not used.

For a Cauchy distribution, the scale has a particularly direct quantile interpretation: the middle 50% lies between minus and plus the scale. At scale 1, half of the prior mass for an interaction lies between -1 and 1, corresponding to adjacent-category odds ratios from 0.14 to 7.39. For an interaction difference, the same interval describes a ratio between the two groups' adjacent-category odds ratios from 0.14 to 7.39; for a threshold difference, it describes a baseline-odds ratio from 0.37 to 2.72. Scales 0.5 and 2 simply change these middle intervals to [-0.5, 0.5] and [-2, 2].

The Cauchy's tails are much heavier than the Normal's. At scale 1, its central 95% interval is approximately [-12.71, 12.71]. It therefore leaves substantial prior probability for extremely large parameters even when most mass remains near zero. A Cauchy prior can be reasonable when genuinely large conditional associations or group differences remain plausible and the data are sufficiently informative. A Normal prior is usually more stable when some response categories are rare or a groupspecific threshold is weakly identified, because the Cauchy can allow such parameters to wander to implausibly large values.

B.4 The Beta-Prime Prior for Average Thresholds

The default average-threshold prior is beta_prime_prior(0.5, 0.5). It is easiest to understand through the transformation follows a beta-prime distribution.

As explained in Section 2.1, this exponentiated threshold is the baseline odds of category h relative to category 0 when the connected variables are in their reference categories. Figure 5 shows three symmetric choices. Taking α = β centers the threshold prior at zero; unequal values would express a directional prior preference for higher or lower baseline category odds. Under the default α = β = 0.5, the middle 50% of the threshold prior is [-1.76, 1.76], corresponding to baseline odds from 0.17 to 5.83. Its central 95% interval is much wider, [-6.47, 6.47], corresponding to odds from approximately 0.0015 to 648. The default can consequently accommodate strongly skewed category distributions and rare response categories.

The more concentrated choice α = β = 2 has a 95% threshold interval from approximately -2.26 to 2.26, or baseline odds from 0.10 to 9.60. It may be sensible when extreme baseline category probabilities are substantively implausible or when rare categories otherwise yield unstable threshold estimates.

The more dispersed choice α = β = 0.25 has a 95% threshold interval from approximately -12.29 to 12.29, corresponding to odds from about 4.6 × 10 -6 to 2.2 × 10 5.

The dispersed prior should be used only when extremely unbalanced baseline odds are genuinely plausible. These odds always refer to the model's reference configuration; they are not marginal category probabilities in the observed sample.

B.5 Bernoulli and Beta-Bernoulli Priors for Difference Inclusion

Every group difference placed under selection has an inclusion indicator γ r . When γ r = 0, the corresponding difference is fixed to zero; when γ r = 1, it is estimated under the continuous slab prior. The Bernoulli and Beta-Bernoulli specifications both initially assign the same inclusion probability to every selected difference. They differ in whether this common inclusion probability is fixed by the researcher or treated as an unknown model parameter. Neither specification assigns a different prior inclusion probability to every edge. Nevertheless, the edges can have different posterior inclusion probabilities because the data provide different evidence about them.

Fixed Bernoulli prior. The default difference_prior = bernoulli_prior(p) uses the same fixed value of p for every selected difference:

The value of p is chosen before the analysis and is not estimated. The indicators are independent under this prior. With p = 0.5, equality and difference have equal prior odds for every interaction difference. In that case, the inclusion Bayes factor equals the posterior inclusion odds. A smaller value, such as p = 0.10, expresses a prior expectation that differences are sparse. More generally, if R parameters are under selection, the expected number of included differences is Rp.

The main advantage of the fixed Bernoulli prior is its transparency. It is particularly useful when researchers can specify a defensible inclusion probability in advance, when relatively few parameters are under selection, or when a simple default is desirable. Its limitation is that the common inclusion rate remains fixed: evidence that most parameters are equal does not reduce the prior inclusion rate for the remaining parameters, and evidence that many parameters differ does not increase it.

Beta-Bernoulli prior. The alternative difference_prior = beta_bernoulli_prior(alpha, beta) treats the common inclusion probability as an unknown parameter:

There is one common π for all selected differences, not a separate π r for every edge. The Beta distribution represents prior uncertainty about the value of this single common inclusion probability; it does not represent variation in inclusion probabilities between edges. After observing the data, this prior uncertainty is updated to a posterior distribution for the same π.

Conditional on π, the indicators are independent. Marginally, however, they are dependent because they all provide information about the same unknown inclusion rate. If the data support few differences, the posterior distribution of π shifts toward smaller values, making inclusion of the remaining differences less likely. If the data support many differences, it shifts toward larger values. This sharing of information produces an adaptive Bayesian multiplicity adjustment (Scott & Berger, 2010). It should not be interpreted as controlling a frequentist family-wise error rate or false-discovery rate.

Although Beta(1, 1) has mean 0.5, it is not equivalent to the fixed Bernoulli(0.5) prior. The fixed Bernoulli prior expresses certainty that the common inclusion probability equals 0.5. The Beta(1, 1) prior instead expresses uncertainty about π and assigns equal prior density to all its possible values between zero and one. A fixed Bernoulli prior can be viewed as the limiting case of a Beta-Bernoulli prior in which the Beta distribution becomes arbitrarily concentrated around a single value.

Choosing between the priors. The fixed Bernoulli prior is attractive when a common inclusion probability can be specified substantively or when researchers prioritize a simple, transparent analysis without additional dependence among the inclusion indicators. Choosing a smaller fixed p can account for an expectation of sparse differences, but the inclusion rate does not adapt to the evidence elsewhere in the network.

The Beta-Bernoulli prior is attractive when the selected differences can reasonably be regarded as exchangeable and their overall prevalence is unknown. Its shared parameter allows information to be borrowed across differences and provides adaptive multiplicity adjustment. The corresponding tradeoff is that the posterior evidence for an individual difference depends partly on the evidence concerning the other differences. Moreover, the common π may remain imprecisely estimated when only a small number of parameters are under selection.

Researchers choosing the Beta-Bernoulli prior should specify both its prior mean and its concentration. For example, beta_bernoulli_prior(1, 9) has prior mean 0.10 and expresses an expectation of sparse differences while still representing uncertainty about their overall prevalence. Symmetric choices are appropriate only when sparse and dense difference structures are equally plausible a priori. When parameters are not plausibly exchangeable or differences are expected to occur in structured clusters, a grouped or structured prior such as sbm_prior() may be more appropriate.

For the present tutorial, we use the fixed bernoulli_prior(0.5) because its equal prior odds and direct relationship between posterior odds and inclusion Bayes factors make the analysis especially transparent. In applications with many candidate differences whose prevalence is unknown, the Beta-Bernoulli prior may be a more appropriate choice when its exchangeability assumption is reasonable.

C Sensitivity to the Difference-Slab Scale

For applied researchers, prior sensitivity checks are useful whenever substantive conclusions depend on inclusion Bayes factors and more than one slab scale is reasonably defensible. They are particularly important when Bayes factors are near an interpretive threshold, the data provide limited information about a difference, or plausible effect sizes are small relative to the chosen slab. The goal is not to search many priors for a preferred conclusion, but to vary one consequential choice across a prespecified, substantively plausible range and report whether the conclusion changes. When the scale is well justified and the evidence remains far from a threshold throughout that range, a brief confirmation of stability is generally sufficient.

We therefore used the prior_sensitivity_check() function in bgms to vary the scale of the Normal prior for group differences while holding the likelihood, selection targets, inclusion prior, averageparameter priors, and evidence thresholds fixed. The range from 0.5 to 2 matches the concentrated and dispersed Normal specifications in Figure 3; scale 1 is the primary default analysis. Intermediate geometric anchors allow the function to trace a continuous Bayes-factor curve using importance reweighting between anchor refits: prior_sensitivity <-prior_sensitivity_check( sel_int, anchors = c(0.5, sqrt(0.5), 1, sqrt(2), 2), evidence_threshold = 3, seed = 2401)

All five anchors passed the function's convergence gate. The check omits interpolated points when the importance-sampling effective sample size is insufficient and uses a repeated refit to distinguish genuine scale sensitivity from ordinary run-to-run variation. The full curve, anchor diagnostics, and all edge-specific values are included in the reproducibility archive.

Figure 7 shows the result for withdrawal-conflict, the edge interpreted in the main text: Its inclusion Bayes factor decreases monotonically as the slab becomes more dispersed: BF10 = 12.65 at scale 0.5, BF10 = 2.64 at scale 1, and BF10 = 1.62 at scale 2. A narrower slab does not increase the prior probability of inclusion; instead, it concentrates the alternative model's prior mass on modest nonzero differences and can therefore give the observed data a higher marginal likelihood than a diffuse slab that also assigns mass to unsupported large differences. This may initially seem counterintuitive because a narrower slab also shrinks an included difference more strongly toward zero. However, the posterior magnitude of a difference conditional on inclusion and the evidence for inclusion are distinct quantities. A narrower slab can produce a smaller posterior estimate while yielding a larger inclusion Bayes factor when its concentration on modest nonzero differences makes the observed data more probable under the alternative model. In the limiting case where the slab scale approaches zero, the alternative becomes indistinguishable from the point null and BF10 approaches 1, so the relationship need not remain monotonic outside the examined range. The Bayes factor falls below the descriptive threshold of 3 at a scale of approximately 0.92. The shaded band represents Monte Carlo uncertainty in the estimated Bayes-factor curve, rather than posterior uncertainty about the edge parameter. This result illustrates why a borderline Bayes factor should be interpreted together with a substantively defensible slab and a sensitivity analysis.

Across all 15 interaction differences, 12 retain the same classification throughout the scale range. Table 3 lists the three exceptions. At scale 0.5, three edges exceed BF10 = 3; at the default scale, 13 support equality and two are inconclusive; at scale 2, 14 support equality and one is inconclusive. The sensitivity is therefore concentrated in a small number of borderline comparisons, but it is substantively important for the withdrawal-conflict edge selected for illustration.

D Posterior Predictive Checks

Sampling diagnostics establish whether the posterior computation is sufficiently stable, but they do not establish whether the ordinal MRF adequately represents the observed data. We therefore performed posterior predictive checks targeting aspects of the joint distribution that are not simply the marginal category frequencies. We do not focus on marginal-frequency checks because the OMRF models the category structure of every variable flexibly, with a separate threshold parameter for each non-reference category. Reproducing the observed marginals would consequently provide only a weak check of model adequacy; the more informative question is whether the fitted model reproduces associations and joint response patterns across variables. For each of 500 draws from the joint posterior, we simulated a new dataset for women and men with the original group sizes. We then calculated all 15 pairwise Spearman correlations, the proportion of participants rating both symptoms in each pair as "Often" or higher, and the distribution of the number of symptoms rated "Often" or higher. The complete numerical summaries are available in the reproducibility archive. Figure 8 compares the observed statistics with their posterior predictive distributions. An isolated observation outside a 95% posterior predictive interval is not by itself a definitive rejection of the model. We regard multiple deviations in the same direction, or a clear deviation for a substantively central statistic, as evidence of potentially problematic fit. All 30 group-specific Spearman correlations fall inside their 95% posterior predictive intervals, indicating that the model reproduces the overall rank-order associations reasonably well. The upper-tail checks are less favorable: 9 of 15 observed co-occurrence proportions among women and all 15 among men exceed their 95% posterior predictive intervals. The model also predicts too many participants with zero or one highly rated symptom and too few participants with several highly rated symptoms; five of the seven symptom-burden proportions among women and four among men fall outside their intervals. Thus, the fitted ordinal MRF captures the broad pairwise association pattern but understates the clustering of high symptom responses.

These discrepancies do not directly demonstrate that the estimated edge differences are incorrect. The adequate reproduction of the pairwise rank correlations provides some reassurance that the model captures broad pairwise association patterns relevant to the comparison, although these correlations are not themselves conditional edge parameters. Nevertheless, the upper-tail results indicate additional dependence that the pairwise ordinal MRF does not represent, potentially because of higher-order interactions, latent heterogeneity, or another form of tail dependence. Because this discrepancy is more pervasive among men, the omitted structure cannot simply be assumed to affect both groups identically and could be absorbed differently into their estimated edge parameters. The inclusion Bayes factors therefore quantify evidence about equality of the groups' edge parameters within the fitted ordinal MRF approximation. They do not establish equality of the complete joint symptom distributions or of the dependence structure among participants reporting multiple highly rated symptoms.

For the default scale of 1, the middle 50% of the prior lies between -0.67 and 0.67, and 95% lies between -1.96 and 1.96. For an average interaction σij , the corresponding adjacent-category odds ratio is exp(2σ ij ). The default middle 50% interval therefore corresponds to odds ratios from 0.26 to 3.85, while the 95% interval corresponds to 0.02 to 50.4. This makes clear that the default is broad on the odds-ratio scale even though a scale of 1 may appear modest numerically.

The same parameter interval has a different substantive translation for the two types of group differences. For an interaction difference δ ij , exp(2δ ij ) is the ratio of the adjacent-category odds ratios in Group 2 and Group 1. For a threshold difference δ ih , exp(δ ih ) is the ratio of the corresponding baseline category odds. Thus, under the default Normal prior, the 95% interval implies a prior interaction-odds-ratio ratio from 0.02 to 50.4 and a prior baseline-odds ratio from 0.14 to 7.10.

A scale of 0.5 may be preferable when theory or previous studies suggest that conditional associations and group differences are modest: its 95% interval for an interaction translates to odds ratios from 0.14 to 7.10. A scale of 2 is very permissive; its 95% interval translates to interaction odds ratios from approximately 0.0004 to 2,540. Such a dispersed choice should generally be motivated by credible evidence that very large parameters are possible. For model selection, the scale is consequential: a wider slab spreads prior mass across a larger range and can reduce the Bayes factor for a modest observed difference. Applied analyses should therefore report the scale and examine whether conclusions near an evidential cutoff are stable under plausible alternatives.

B.3 The Cauchy Alternative

The Cauchy distribution is a heavier-tailed alternative for average interactions and group differences. The corresponding specifications are: interaction_prior = cauchy_prior(scale = s) difference_family = "Cauchy" difference_scale = s These choices are independent: selecting a Cauchy prior for average interactions does not automatically change the prior on group differences. F Group Differences in Threshold Parameters

Following the parameterization described in Section 2.2, Table 4 reports posterior mean estimates of the average threshold parameters, and Table 5 reports posterior mean estimates of the corresponding group differences. Because females were entered as Group 1 and males as Group 2, a threshold difference is the male parameter minus the female parameter. Thus, the female and male threshold parameters can be reconstructed as the average minus and plus one half of the difference, respectively. The estimates are rounded to two decimals. As explained in Section 2.2, these differences concern baseline category-specific log odds in the reference configuration; they are not direct differences in observed means or marginal category probabilities. The values in Table 5 therefore summarize the estimated magnitude and direction of the differences, but should not be read as posterior inclusion probabilities or Bayes factors for threshold-difference selection.
