How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. Abstract

Dynamic structural equation modeling (DSEM) has become a central tool for analyzing intensive longitudinal data, such as data from ecological momentary assessment and daily diary studies. In practice, DSEM is almost exclusively estimated in Mplus, a commercial, closed-source program, while packages built on the open-source probabilistic programming language Stan offer only a fixed selection of models. This tutorial shows applied researchers how to implement DSEM directly in Stan. Starting from a bivariate multilevel cross-lagged model with random effects, we build the model in three steps: a minimal working version, a non-centered reparameterization that resolves the convergence problems of the first version, and an extension that treats missing observations as parameters to be estimated. Along the way, we explain how to read Stan's convergence and sampler diagnostics, how to inspect the results visually, and how to report a Bayesian DSEM. On simulated data with known parameter values, the Stan implementation recovers the true values and closely reproduces the estimates of Mplus and of the R package mlts. We then demonstrate the flexibility of working in Stan with two extensions that require only local changes to the code: residual DSEM, and a binary within-person predictor, illustrated with data from a micro-randomized mindfulness intervention. All code is openly available and written to be adapted to new models.

Working directly in Stan requires more initial effort than Mplus, but it makes every modeling decision transparent and extensible, and it lets researchers fit the model their research question calls for.

Introduction

Dynamic Structural Equation Modeling (DSEM) is a statistical framework used to model the relations among multiple time-varying latent and observed variables. It combines time-series modeling, structural equation modeling, and multilevel modeling (Hamaker et al., 2023). DSEM is particularly useful in fields where researchers are interested in investigating intensive longitudinal data such as psychology, epidemiology, and economics. The need for DSEM is in part a response to the technological innovations and availability of smart devices that have made data collection through daily diaries, ambulatory assessment, and ecological momentary assessment more easily accessible and feasible (McNeish & Hamaker, 2020). These methods afford researchers to collect longitudinal data across a larger number of subjects, with more frequent and a larger number of time-points. On a conceptual level, intensive longitudinal data allow researchers to capture within-person processes as they unfold over time in individuals' everyday lives. This has been recognized as a key advantage in multiple areas of psychological research and has contributed to a growing community of researchers applying these methods. For instance, DSEM has been employed to investigate the reciprocal relationship between negative affect and rumination (Blanke et al., 2020), as well as the interplay between parent-adolescent interactions and parental well-being (Bülow et al., 2022). Emerging applications of DSEM also include its use in cognitive-behavioral tasks and reaction time data to capture momentary fluctuations in cognitive performance, such as in children with ADHD (Aristodemou et al., 2024). It has also been used to link cognitive control to the dynamics of emotion regulation in adolescents' daily lives (Debra et al., 2024).

One of the most widely used software packages for estimating DSEM "out of the box" is Mplus (Muthén & Muthén, 1998 -2017), which provides a user-friendly interface for model specification and estimation. Mplus tutorial papers and chapters in the past years provide a good starting point for empirical researchers who want to model their data using this approach (see Hamaker et al. (2023), McNeish and Hamaker (2020), McNeish et al. (2024), McNeish and MacKinnon (2025)). Mplus offers researchers the lowest practical barrier to entry: its DSEM module is well documented, actively developed, and automatically handles many practical complications, such as unequally spaced measurement occasions and latent centering. This convenience comes with some constraints. Mplus requires a paid license, which can be a barrier for students, early-career researchers, and institutions with limited funding. It is closed-source, so users have limited insight into its internal computations, default settings, and estimation procedures, which makes it harder to reproduce, audit, or extend an analysis. Its input format also imposes practical restrictions: data must be supplied as a plain-text file whose records may not exceed 10,000 characters, and variables with a variance above 1,000,000 are rejected and must first be rescaled (Muthén & Muthén, 1998 -2017). Finally, Mplus offers fewer convergence diagnostics than, for example, Stan (see below) (Muthén & Muthén, n.d.).

DSEM estimation in Stan

Stan (Stan Development Team, 2025) is an open-source probabilistic programming language for Bayesian inference. Rather than offering a menu of predefined models, Stan lets users write down their model directly: any model that can be expressed as a probabilistic generative model can, in principle, be implemented. Once the logic of a DSEM is written out in Stan code, extending it (for example with additional predictors, other outcome distributions, or a new measurement model) becomes a matter of adding or adapting a few lines rather than waiting for a software update.

In addition, Stan has several practical advantages. It is freely available and fully open-source. Every modeling choice is visible in the code and can be inspected, questioned, changed, and shared. It integrates with statistical environments like R and Python, enabling highly customizable visualizations through packages such as ggplot2 (Wickham, 2016) and bayesplot (Gabry & Mahr, 2025) in R or matplotlib (Hunter, 2007) in Python. Its Hamiltonian Monte Carlo sampler uses information from the model to take bigger, better-guided steps to explore many parameters simultaneously, whereas a Gibbs sampler (used by, for example, Mplus) changes only one or a few parameters at a time, which can require many more iterations, and thus more time, to explore the posterior. Furthermore, Stan by default warns users when something may be wrong, not only with convergence but also with the posterior samples. Specifically, Stan warns about (1) divergent transitions, which indicate difficulties in exploring some areas of the posterior distribution and suggest potential issues with model specification; (2) low effective sample size (ESS), indicating that the posterior samples are highly correlated and may not sufficiently represent the posterior distribution; (3) reaching the maximum treedepth, meaning the sampler may have stopped early; and (4) low Bayesian fraction of missing information (BFMI), suggesting inefficiencies in the sampler's momentum. Stan also suggests how to address these warnings and gives direct control over the sampler settings. Together, these diagnostics provide a more comprehensive picture of whether the posterior samples can be trusted (Betancourt, 2018).

Packages built on Stan

Several R packages make Stan accessible without writing Stan code. brms (Bürkner, 2017) is an excellent interface for a wide range of generalized linear multilevel models and can accommodate certain autoregressive designs, but it does not provide a dedicated framework for DSEM. ctsem (Driver & Voelkle, 2018) focuses on dynamic models, but in continuous rather than discrete time. Most relevant here is the mlts package (Koslowski et al., 2025), which uses precompiled Stan models to fit a selection of multilevel latent time series models through simple R functions. It supports manifest and latent VAR models with measurement models, between-level covariates, and multi-group comparisons, and provides tools for model checking and presentation, including automatic L A T E X model equations, path diagrams, and posterior predictive checks via bayesplot (Gabry & Mahr, 2025).

There is a clear place for these packages. For researchers whose model falls within their scope, they are free and benefit from Stan's sampler and diagnostics, and require minimal programming effort; they are also a valuable sanity check for a custom implementation. Their convenience, however, comes from fixing the model in advance: because mlts relies on precompiled models, users cannot modify the underlying code, and at the time of writing categorical variables and residual DSEM models are not yet supported. This tutorial is written for researchers who do not want to be limited by what a package currently supports, or who want full transparency over how their model is estimated. A tutorial is needed because Stan's flexibility is locked behind a learning curve: Stan requires users to write the entire model in a probabilistic programming language, which can be a barrier for those with limited coding experience.

With this tutorial paper we hope to flatten this learning curve. We begin by introducing a base bivariate DSEM commonly used in psychological research and then walk through the process of implementing this model in Stan. The modeling process unfolds in three steps: First, we present the simplest version of the model, containing only the essential code required for the model to run. Next, we reparameterize the model to improve sampling efficiency and model convergence. In a third and final step, we extend the model to handle missing data.

After the base model is built, we show how to respecify it as a residual DSEM and then extend the model to handle categorical predictors. Along the way we teach how to evaluate convergence, present results visually, and compare the output from Stan and Mplus across these models to discuss the implications and limitations. The Stan code and modeling skills presented here are intentionally general and modular, so that readers can adapt the models to their own needs after the tutorial.

Intended audience and prerequisites. We assume familiarity with the core concepts of DSEM, such as the within/between decomposition, autoregressive and cross-lagged effects, and random effects (Hamaker et al., 2023; McNeish & Hamaker, 2020), with the basics of Bayesian estimation (priors, posteriors, and MCMC; McElreath, 2020), and with basic R. No prior Stan programming experience is required. We do not provide a general introduction to the Stan language (Stan Development Team, 2022), nor do we cover prior selection and sensitivity analysis (Depaoli & van de Schoot, 2017), model comparison, or the substantive interpretation of DSEM results, for which we refer readers to the Mplus tutorials cited above.

The model block generally houses two main building parts of our model: The specification of the priors and the specification of the model equations. While Mplus has default priors behind the scenes, Stan requires their explicit specification. We begin the model block by specifying priors for our three groups of parameters. The three priors chosen here (Normal, Cauchy, and LKJ) are commonly used and generally suitable for DSEM applications. Like the Mplus defaults, which place (near-)flat Normal priors on coefficients and inverse-Gamma and inverse-Wishart priors on (co)variances (Asparouhov & Muthén, 2010), they are broad and only weakly informative.

As a starting point, the gamma ∼ normal(0, 100); prior sets a diffuse Normal prior on the fixed effects, reflecting uncertainty and allowing values to vary widely. The prior tau_Omega ∼ cauchy(0, 2.5); is a weakly informative half-Cauchy prior for standard deviations (the lower bound of zero on tau_Omega truncates the Cauchy), often recommended in hierarchical models because it allows for a wide range of variability while still gently discouraging extreme values (Gelman, 2006). The L_Omega ∼ lkj_corr_cholesky(1.0); pairs naturally with the Cholesky decomposition approach introduced in the previous block. In using Cholesky decomposition, the lower triangular correlation matrix is the only part that needs a prior. The shape parameter of 1.0 corresponds to a uniform prior over all valid correlation matrices, meaning it does not favor any particular correlation structure (Lewandowski et al., 2009).

These priors are a starting point rather than a recommendation for every application. Because Stan, unlike Mplus, requires all priors to be stated explicitly, researchers should choose them deliberately and scale them to the parameter they govern: an autoregressive coefficient, a person mean, and a log residual variance live on very different scales, and a single diffuse prior is rarely weakly informative for all of them.

Priors matter most for weakly identified parameters, such as small random-effect variances, where the data carry little information. We therefore recommend visualizing the priors (e.g., through prior predictive checks) and reporting a sensitivity analysis showing that substantive conclusions are stable across a defensible range of priors (Depaoli & van de Schoot, 2017; Schubert et al., 2025).

Convergence

Besides the estimate statistics, two important convergence statistics are reported in the summary statistics (Figure 1B): the ˆ︁ R (Rhat) and the Effective Sample Size (ESS).

The ˆ︁ R (Rhat) statistic assesses convergence by comparing the variance within chains to the variance between chains.

Values close to 1.0 indicate that the chains have likely converged to the same posterior distribution. Following the latest guidance from Vehtari et al. (2021), it is advisable to consider the sample to be reliable only if all ˆ︁ R values fall below 1.01 with a minimum of four chains. Specifically, running fewer than four chains increases the risk of failing to detect non-convergence issues, and using a ˆ︁ R threshold as high as 1.05 may prematurely signal convergence. The default in Mplus executes only two MCMC chains and utilizes a convergence diagnostic known as the Potential Scale Reduction Factor (PSRF), equivalent to the ˆ︁ R statistic, with a cut-off value of 1.05. The second diagnostic, Effective Sample Size (ESS), reflects how much independent information is contained in the posterior samples. If a chain produces highly autocorrelated draws, then the number of effectively independent samples is much lower than the total number of iterations. The bulk ESS assesses sampling efficiency in the high-density region of the posterior, while the tail ESS evaluates the adequacy of sampling in the extreme(s). According to Vehtari et al. (2021), both bulk and tail ESS should exceed 400 to ensure stable and reliable estimates. Moreover, they recommend that each split chain achieves an average ESS of at least 50 for the ˆ︁ R statistic to be a meaningful convergence diagnostic, making a minimum of four chains essential for robust inference. In Stan, ESS is a default measure of convergence. Mplus did not have the option to access ESS statistics until, and only in, version 9 (released October 2025). This limits the user's ability to evaluate the reliability of the estimates even if the ˆ︁ R falls below the cutoff of 1.01 Zitzmann et al. (2021).

Stan did not report any warnings or convergence issues during the sampling of our simple base model. Nonetheless, it is good practice to inspect the sampler diagnostics explicitly. This can be done by running the final command in Code 8, which returns three key metrics: (1) the number of divergent transitions, (2) the number of iterations that hit the maximum tree depth, and (3) the estimated Bayesian fraction of missing information (E-BFMI) for each chain (Figure 1D).

A divergent transition indicates that the sampler had difficulty exploring a region of the posterior distribution; zero divergences suggest that the model was well-behaved throughout sampling. A maximum treedepth hit means that the sampler reached its limit for how far it can explore in a single iteration before being satisfied with its reached value; in our simple base model run, no iterations needed the full maximum treedepth.

Finally, E-BFMI is a measure of sampler efficiency; values above 0.3 are generally considered acceptable (Betancourt, 2016 (Betancourt, , 2018)). In our run, all E-BFMI values were well above the threshold, indicating efficient exploration across all four chains.

Now that we know that the sampler in our run was well behaved, we can further explore the ˆ︁ R and ESS (Figure 1B). We see that parameters γ 1 and γ 7 (the fixed intercept and residual variance in X) did not manage to fall to or below 1.01.

Furthermore, both the bulk and tail ESS values are not quite satisfactory for the γ 1 , γ 2 , γ 7 , and γ 8 (the two fixed intercepts and residual variances) parameters either. In such a case, there is a general recommendation to increase the number of sampling iterations and re-run the model. However, there are faster and well-established strategies to improve convergence in Stan. One widely recommended approach is reparameterizing the model, which can resolve elevated ˆ︁ R values, low ESS values, and divergent transitions more reliably (Stan Development Team, 2025). Simply put, reparameterization alters the parameterization of the model to facilitate smoother exploration by the sampler resulting in better convergence. We will discuss implementing this strategy in the next section, followed by an elaboration on treatment of missing values. These two sections will equip researchers with the tools needed to deal with real-world issues (convergence issues in complex models, missing data due to non-perfect compliance) they will likely encounter when applying these models to empirical data.

Implementation in Stan: Full Model with Missing Data

Consistent with recommendations by Lüdtke, Robitzsch, and Grund (Grund et al., 2018 (Grund et al., , 2021;; Lüdtke et al., 2017), we handle missingness under MAR by treating each missing entry as an unknown parameter and sampling it from the posterior predictive distribution conditional on the multilevel/DSEM structure. This substantive-model-compatible strategy makes the imputation model at least as general as the analysis model, preserving within-between decompositions, random slopes, and cross-level interactions. Prior work shows that single-level imputation can bias regression parameters and variance components in clustered data, and that special care is needed when imputing predictors with random slopes (Enders et al., 2016; Grund et al., 2016); our Stan specification builds the multilevel (and dynamic) structure directly into the likelihood to avoid these issues.

The main changes required to accommodate this are minimal and fall into three areas: First, in the data block we pass in the positions of missing values as a set of row-column indices (e.g., ii_mis_X) and specify how many are missing (e.g., N_mis_X).

Second, in the parameters block we declare new parameter vectors X_mis and Y_mis, which hold the values to be imputed. And third, in the transformed parameters block we create new arrays X_imp and Y_imp as copies of the input data (e.g., X and Y) and then impute the missing entries as estimated parameters jointly, informed by the observed data.

Reporting the Results

Bayesian DSEM involves more analytic decisions than a typical frequentist multilevel model, and many of them are invisible in the final parameter table: the choice and scale of the priors, the parameterization of the random-effect covariance matrix, the treatment of missing observations, and the sampler settings all shape the posterior.

Transparent reporting of these choices is therefore not a formality but a precondition for replication and for readers to judge whether the posterior can be trusted. Specifically, the random effect standard deviations of the autoregressive effect of Y (0.12) and of the cross-lagged effect from Y t-1 to X t (0.16) had among the lowest effective sample sizes of the reported parameters, as such small variance components create a challenging posterior geometry for the sampler (Betancourt & Girolami, 2015). In our Stan implementation, the non-centered (reparameterized) model handles this situation without difficulty, producing zero divergent transitions and satisfactory ˆ︁ R and ESS values for all parameters (see Figure 2).

The mlts package provides its own solution to this problem through the ranef_zero argument, which constrains near-zero variance components to zero and converts the corresponding parameter to a fixed effect. Koslowski et al. (2025) recommend this approach when Z = estimate/SE < 3 for a given variance component, following guidance from Asparouhov and Muthén (2022). This is a practical and effective strategy within the mlts framework. The reparameterization approach demonstrated in this tutorial offers a complementary solution: rather than removing the random effect, the non-centered parameterization allows the sampler to explore the posterior efficiently even when variance components are small, preserving the full model structure.

Extension: Residual Dynamic Structural Equation Modeling

The autoregressive parameters ϕ Xi and ϕ Y i quantify how strongly each variable at time t-1 predicts itself at time t. In psychological research, these parameters reflect constructs like emotional inertia, which is the tendency for affective states to persist over time (Koval et al., 2012; Kuppens et al., 2010). However, as Asparouhov and Muthén (2020) point out, the standard DSEM autoregressive coefficient does not capture pure inertia. Because the lagged predictor X (w) it-1 includes variance that was already explained by a cross-lagged effect at time t-1, the autoregressive parameter conflates genuine carry-over with the re-prediction of variance that was already accounted for.

This can inflate estimates of inertia and complicate the interpretation of both autoregressive and cross-lagged effects.

The residual DSEM (RDSEM) framework (Asparouhov & Muthén, 2020; Asparouhov et al., 2018) addresses this by having the autoregressive process operate on residuals, that is, on what remains of a variable after its structural prediction has been removed. In Asparouhov et al. (2018), this structural prediction is contemporaneous (lag-0), so that the AR process carries forward only what the concurrent cross-sectional model cannot explain. In our bivariate cross-lagged model, however, the structural predictors follow the lag structure of Equation 2: X (w) it is structurally predicted by the lagged cross-lag β Xi Y (w) it-1 , and Y (w) it is predicted by the contemporaneous link β Y i X (w) it .

We adapt the RDSEM principle accordingly, so that the autoregressive effect of each variable carries forward only the portion that was not already explained by its respective structural predictor. Note that this is only one of several defensible specifications.

Alternatively, the cross-lagged effect could be treated as part of the residual process, so that the residuals follow a full VAR(1) model including residual cross-lagged effects.

Which choice is appropriate depends on the substantive question; the point of the implementation below is that Stan can encode any of these assumptions by changing how the residuals are defined.

Categorical Variables in Stan Require Special Treatment

In the models presented so far, all variables were continuous, and within-person centering was straightforward: the within-person deviation was simply the observed value minus the person-specific intercept. A binary variable like MI requires a more complex solution. Person-mean centering a 0/1 variable produces a continuous deviation score that conflates the between-person probability of receiving MI with the occasion-level deviation. Moreover, the observed person mean is only an error-prone estimate of a person's true MI propensity (i.e., the person-specific probability of receiving the treatment, expressed on the probit scale). Lüdtke et al. (2008) showed that using such observed means in place of the true means yields biased estimates of between-person (contextual) effects, and that this bias is largest when the number of observations per person is small and the between-person variance is small relative to the within-person variance, that is, when the observed means are unreliable. In Mplus, this is handled via latent decomposition: behind each observed MI it lies a continuous latent variable MI * it , linked to the binary outcome through a probit model, which is decomposed into betweenand within-person components.

Implementation in Stan

In Stan, rather than estimating MI * (w) it as an explicit parameter for every person-occasion combination (which would dramatically increase the number of parameters to be estimated), we implement this latent decomposition by analytically marginalizing MI * (w) it out of the likelihood.

That is, we use the mathematical structure of the model to account for all possible values of MI * (w) it without ever sampling it directly. This is possible because MI * (w) it enters both the RU and NA equations linearly, and its prior is standard normal. The product of normal densities is itself proportional to a normal density, so the integral over MI * (w) it has a closed form obtained by completing the square (Bishop, 2006); the probit constraint contributes a truncation factor in the spirit of the latent-variable formulation of binary-response models (Albert & Chib, 1993).

The mathematics behind this marginalization takes up a fair number of lines of code, and none of it is specific to rumination, negative affect, or mindfulness. We therefore placed it in a separate file, dsem_categorical_helper.stan, which defines a new, ready-made distribution called categorical_predictor(). Stan allows such user-defined distributions to be written in their own file and pulled into a model with a single #include statement (Stan Development Team, 2022). The trade-off between Stan, Mplus, and mlts

The choice between Stan, Mplus, and mlts ultimately comes down to a three-way trade-off between accessibility, cost, and flexibility. Mplus offers the lowest practical barrier to entry for researchers: the DSEM module is well-documented, actively developed, and handles many practical complications such as unequally spaced measurement occasions and latent centering automatically. Several excellent tutorials for learning DSEM in Mplus have been published as well (Hamaker et al., 2023; McNeish & Hamaker, 2020; McNeish & MacKinnon, 2025; McNeish et al., 2024). However, Mplus carries a substantial licensing cost that can be prohibitive for students, early-career researchers, and institutions. It is also a closed blackbox system: researchers cannot inspect or modify the underlying estimation code, which limits both transparency and extensibility. When a desired model feature is not yet implemented, the only option is to wait for a future software release.

The mlts package occupies a useful middle ground. It is free, open-source, and builds on Stan's Hamiltonian Monte Carlo sampler, so it inherits Stan's diagnostic framework. For models that fall within its current scope, including bivariate and multivariate VAR models with between-level covariates and optional measurement models, mlts requires minimal programming effort and produces results that closely match both Mplus and our Stan implementation. An introduction to mlts for novice users is also available (Koslowski et al., 2025). The ceiling of mlts is, however, fixed by its precompiled Stan models. For example, RDSEM and categorical variables are not yet supported, and researchers cannot modify the underlying model code to add them. As we showed in the comparison section, mlts can also encounter convergence difficulties in the centered parameterization when random effect variance components are near zero, a problem that the non-centered reparameterization demonstrated in this tutorial handles.

Writing Stan code directly requires the steepest initial investment, but the return on that investment is very high flexibility. Any model that can be expressed as a probabilistic generative process can be implemented, and the modular structure of Stan code means that extensions such as the RDSEM and categorical models demonstrated here often require only localized changes to an existing model file. For research groups that regularly push against the boundaries of available software, and that require full transparency and reproducibility in their estimation procedure, the learning curve is a one-time cost that might pay dividends across many future projects.

Comparing missingness handling in Mplus and Stan

Mplus and our Stan implementation handle missing data in conceptually similar ways. In Mplus, DSEM is estimated with a Gibbs sampler, and missing observations are imputed at each MCMC iteration conditional on the current parameter values and the neighboring observations (Asparouhov et al., 2018). Because the imputation exploits the autoregressive structure, missing values are drawn from the adjacent time points rather than from the person mean, which yields valid inference under the missing-at-random assumption (Asparouhov et al., 2018; McNeish, 2025). Unequally spaced observations are handled the same way: the TINTERVAL option places the data on an evenly spaced time grid, and the resulting empty grid points are treated as missing and imputed (Asparouhov et al., 2018). Our approach in Stan likewise uses Bayesian data augmentation (Gelman et al., 2013), treating missing values explicitly as unknown parameters that are estimated jointly with all other model quantities. In both cases, the posterior distribution of each missing observation is informed by the full multilevel and dynamic structure of the model, including the within-person AR process, between-person random effects, and cross-lagged relationships. Uncertainty about missing values therefore propagates into the posterior distributions of all fixed and random effects, rather than being absorbed into a single point prediction (Gelman et al., 2013; Lüdtke et al., 2017). to compute because it requires evaluating the gradient of the log-posterior (Betancourt, 2018; Gelman et al., 2013). For the simulated dataset used in this tutorial, with 100 individuals and 50 observations each, total wall-clock time across four chains was approximately 244 seconds for the simple model, 342 seconds for the reparameterized model, and 600 seconds for the full model with 30% missing data, run on a standard research laptop. These times are generally longer than comparable Mplus runs on the same data, and will scale with sample size, number of time points, and model complexity.

Several strategies can reduce Stan runtimes in practice. The most immediate is within-chain parallelization via the reduce_sum function in Stan, combined with CmdStanR's parallel_chains and threads_per_chain arguments, which distribute chains and within-chain computations across available cores (Gabry et al., 2025; Stan Development Team, 2022). The chapter on parallelization in the Stan User's Guide provides a step-by-step introduction to reduce_sum. For large datasets or models that need to be run repeatedly, for example across a simulation study or in a tutorial setting with multiple model variants, an RDS-based caching workflow in R can also avoid redundant refitting. While Stan will not always be faster than Mplus in absolute terms, the richer convergence diagnostics it provides mean that researchers can be more confident that the time invested in sampling has produced trustworthy posterior estimates.

Challenges and Limitations

Unequally spaced measurements

The approach presented in this tutorial assumes that observations are equally spaced in time, which is common in cognitive task and laboratory paradigms but is not always the case in ambulatory assessment or daily diary designs. When measurement occasions are unequally spaced, the autoregressive parameter ϕ no longer has a constant interpretation across adjacent pairs of observations, because the strength of temporal carry-over decays as a function of the elapsed time between measurements. As Berkhout et al. (2025) note, in an AR(1) process with ϕ = 0.3, the implied association between observations two steps apart is ϕ2 = 0.09, and the decay is exponential as the interval grows. The choice of measurement interval therefore has direct consequences for parameter estimation and interpretation (Deboeck & Preacher, 2016; Dormann & Griffin, 2015; Reichardt, 2011).

Mplus addresses this through the TINTERVAL option, which inserts placeholder observations at regular time intervals so that the lag structure remains constant and interpretable. Our Stan implementation handles the same problem in a conceptually equivalent but more explicit way: rather than automated insertion by the software, the researcher prepares the data in R by marking the positions of missing observations with

Inf values and passing their indices to Stan as part of the data list. Stan then estimates the values at those positions as unknown parameters, informed by the surrounding observations and the dynamic structure of the model. The key difference is one of transparency and control: the researcher decides where to insert missing observations and can verify that the temporal structure passed to Stan matches their intentions, rather than relying on software-automated restructuring. The substantive modeling challenge identified by Asparouhov et al. (2018), namely that the chosen time unit should be interpretable, should not generate excessive missingness, and should preserve the original time metric, applies equally to both approaches.

It should be noted that handling unequally spaced measurements requires thoughtful decisions that go beyond the scope of this introductory tutorial. For researchers who need to work routinely with irregular measurement occasions, a continuous-time extension of the model may be more appropriate, as it avoids the need to specify a discrete time unit altogether (de Haan-Rietdijk et al., 2017; Voelkle & Oud, 2013), albeit at the cost of considerably more complex model specification.

Three-level DSEM

A further extension that falls outside the scope of this tutorial is three-level DSEM, in which observations are nested within days or sessions, which are themselves nested within persons. This structure arises naturally in ambulatory assessment designs with multiple beeps per day, and in cognitive paradigms where trial-level data are collected across multiple testing sessions. Very recently Mplus released Version 9 with a native three-level DSEM estimator (Asparouhov & Muthén, 2025). In principle, three-level DSEM can also be implemented in Stan, because it only requires adding a further level of random effects to the model code presented here. Developing and evaluating such an implementation is, however, a task for future research.

Conclusion

This paper set out to lower the barrier to implementing Dynamic Structural Equation Models in Stan by providing a step-by-step tutorial that builds from a minimal model to a fully reparameterized implementation with Bayesian missing data handling, and then extends to two model classes, residual DSEM and categorical predictor variables, that are not currently available in other R packages using stan. The reparameterization strategy demonstrated here, switching from a centered to a non-centered parameterization of the random effects, resolved the convergence difficulties encountered in the simpler model and proved robust even when random effect variance components were near zero, a setting where the centered parameterization in mlts required additional constraints. The Bayesian data augmentation approach to missing values made the imputation model explicit and directly consistent with the substantive model, with uncertainty about missing observations propagating naturally through the posterior.

We hope that the modular structure of the code presented here makes it straightforward for researchers to adapt the models to their own research questions, whether by adding between-level predictors, extending to three levels, incorporating measurement error via latent variables, or combining features from the RDSEM and categorical extensions demonstrated here. The fundamental skills involved, writing Stan data, parameter, and model blocks, reparameterizing for faster, more reliable sampling, and handling missing data as parameters, transfer directly to a wide range of models beyond those covered in this tutorial.

Computers store numbers with limited precision, and for values of z far below zero, log Φ(z) can no longer be computed reliably: the result becomes negative infinity and the sampler gets stuck or rejects the proposal. The helper therefore uses its own function, log_Phi_stable(). For z > -30, it simply calls Stan's built-in std_normal_lcdf().

Beyond that point, it switches to a well-known approximation of the normal tail (Abramowitz & Stegun, 1964, Eq. 26 .2.12 which is extremely accurate this far into the tail and can always be computed.

In practice, the sampler hardly ever reaches this region once it has found the typical set, so the approximation has no noticeable influence on the final estimates; it merely keeps warm-up from breaking down.

Following the recommendations ofSchubert et al. (2025) for reporting Bayesian analyses, a complete DSEM report should contain four elements. First, it should state the distribution, parameter values, and a brief rationale for every prior, with each prior scaled to the parameter it governs (see the The model Block section). Second, it should describe the estimation setup: the software and package versions, the number of chains, the number of warm-up and post-warm-up iterations, and the random seed. Third, it should report the convergence and sampler diagnostics introduced in the Convergence section for all parameters, together with any remedial steps taken when the initial diagnostics were unsatisfactory. In this tutorial, the switch from the centered to the non-centered parameterization is one such step, and it belongs in the report rather than being hidden. Fourth, it should summarize the results with posterior medians and credible intervals, stating the interval type. The cmdstanr default used here is the equal-tailed quantile interval, which can differ from a highest-density interval for skewed posteriors such as variance components. Conclusions should be framed in terms of the magnitude of an effect and the uncertainty around it rather than in frequentist language; describing an effect as "significant" or only asking whether a credible interval excludes zero discards much of the information a posterior provides.
