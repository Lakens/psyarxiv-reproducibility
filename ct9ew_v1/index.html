How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Mouthings -mouth movements that mimic spoken language words produced alongside signing -are a unique multimodal phenomenon in that they recruit resources from a second language; however, they have not received much attention in research that explicitly frames itself as multimodal. In Norwegian Sign Language (NSL/NTS), the role of mouthing in comprehension has not been studied extensively from the perspective of deaf users of the language. In this study, we add to these two understudied areas by exploring mouthings in comprehension of Norwegian Sign Language in an unrestricted lexical identification paradigm (N=30). We find that when manual forms are polysemous, plausible mouthings improve accuracy in lexical identification and the certainty of comprehension. When mouthings are implausible, it appears that the dominant strategy is to make identification decisions based on the manual form only. In a smaller number of cases participants appeared to rely solely on the mouthing or blended the mouthing and manual components.

1 Introduction

What is the effect of the presence of multiple information streams in comprehension in language and certainty in that comprehension? We consider this question by examining how Norwegianlinked mouthing in Norwegian Sign Language (NSL)1 contributes to identification of decontextualized signs in the manual channel. Mouthings are mouth patterns that mimic spoken language words, produced with or without vocalisation, that are layered over manual signing (Bisnath 2024). Use of language has long been known to be multimodal2 (Bezemer & Jewitt 2018) and is now receiving more serious consideration in mainstream linguistics (Adolphs & Carter 2013 , Goldin-Meadow & Brentari 2017 , Gullberg 2009 , Ningelgen & Auer 2017 , Ünal et al. 2024 , Zima & Bergs 2017). Prominent in this work are the practices of hearing people, particularly the gestures they produce while speaking and their use of pictorial representations, like drawings or emoji, in writing (Hancock et al. 2024 , Scheffler et al. 2022 , Schilperoord & Cohn 2022).

2 Mouthings and sign language comprehension

We use the term mouthing to refer to mouth patterns that are recognisable as mimicking spoken language words, produced with or without vocalisation, during signing. This definition centers language contact and does not mean that signers necessarily consider mouthing to be exclusively part of a spoken language. Mouthings are found in many of the world's sign languages and are highly diverse in form and function (Bisnath 2024). They vary by sign language, sociodemographic characteristics, grammatical context, deaf status of interlocutors, and grammatical contribution (Bisnath 2024 , Crasborn et al. 2008 , Proctor & Cormier 2023). This variability complicates their description and analysis, and in some cases lends to questioning of their status as linguistic or not (Giustolisi et al. 2017). The present study is guided by the observation that mouthings are present in the repertoires of deaf and hard-of-hearing users of multiple national sign languages (Bisnath 2024). Following usage-based approaches that view grammar as "the cognitive organisation of one's experience with language" (Bybee 2006: 711), we consider coproduction of mouthing with manual signing a reflection of linguistic experience; this motivates our consideration of mouthing in grammar.

Four of the most common forms of mouthing construction are CONGRUENT, MORPHO-PHONOLOGICAL (with subtypes POLYSEMOUS, INITIALISED and HOMOPHONE), MORPHO-SYNTACTIC and FREE (Bisnath 2024). We describe these forms briefly here to provide a framework for discussing mouthing and refer readers to Bisnath (2024) for examples. CONGRUENT mouthings can be glossed in the same way as the manual form they accompany. MORPHO-PHONOLOGICAL identifies a group of constructions that share the same manual form that is specified by mouthings. MORPHO-P r e p r i n t Correspondence: fbisnath@umich.edu PHONOLOGICAL sub-types differ in how group members relate to each other -constructions in the POLYSEMOUS group have similar meaning, INITIALISED use the same manual alphabet handshape as the written form of their mouthing begins with the same letter, and HOMOPHONES are related by chance. In MORPHO-SYNTACTIC constructions, the mouthing contributes propositional content and so, for example, can act as complement of the manual form it is associated with. Lastly, FREE mouthings are those that are not clearly associated with a manual sign temporally i.e. they may be produced in the transition between signs. Across the four constructions, the stability of the form of the mouthing component is assumed to be graded as follows: MORPHO-PHONOLOGICAL > CONGRUENT, MORPHO-SYNTACTIC > FREE. MORPHO-PHONOLOGICAL mouthings are likely most conventionalised because they disambiguate identical manual forms. FREE mouthings are least conventionalised as they can take on any form. CONGRUENT and MORPHO-SYNTACTIC constructions fall in between as are they are constrained in some ways by properties of their manual component. Furthermore, CONGRUENT mouthings are likely not always produced while MORPHO-SYNTACTIC constructions could have manual-only alternates.

Experimental studies can isolate mouthing and thus demonstrate how it specifically is implicated in sign language comprehension. Deaf signers of French Sign Language (LSF) use the manual and mouthing components of CONGRUENT mouthing constructions together in lexical retrieval, and are slower to identify a sign and more inaccurate when mouthing is unexpected (either a pseudo-word or semantically-incongruent) (Bogliotti & Isel 2021). Similarly signers of British Sign Language (BSL) show lower accuracy in sign identification when a manual sign associated with a target image is shown with a mouthing that does not match. They are further most accurate when the manual and mouthing components both match but least accurate when only the mouthing component matches (Perniss et al. 2020). Signers of Italian Sign Language (LIS) are less accurate in identifying that a member of a mouthing minimal pair does not match a target word than for other types of minimal pairs (location, movement, handshape, orientation) (Giustolisi et al. 2017). When presented with highly manually-similar signs they are more accurate when mouthing is visible as opposed to blurred, and tend to repeat viewings of videos of the latter the most (Rinaldi et al. 2024). Furthermore, they are faster at identifying that a member of a mouthing minimal pair matches a target word when mouthing is present (Giustolisi et al. 2017). Together these findings show that users of sign languages in western industrialised countries do use mouthing to identify decontextualised signs and particularly rely on it when manual forms are ambiguous. The Italian Sign Language signers' viewing patterns suggest that noisy mouthing conditions (blurring) create uncertainty. 3 Mouthing in Norwegian Sign Language

Norwegian Sign Language (NSL) is the national sign language of Norway used by approximately 16,500 people, 3000-3500 of whom are deaf (Norwegian Deaf Association). The majority spoken language is Norwegian, in which dialectal variation is institutionally accepted and can be written with two systems (Bokmål and Nynorsk). Major deaf centers are found in Oslo and Ål in the east, Bergen in the west, and Trondheim in the middle (and north of the other cities). Two dialects linked to Oslo and Trondheim are named in the literature (Greftegreff et al. 2015), and 255 signs specific to Northern Sámi-using regions have been recorded (Haualand et al. 2023). A tactile sign language, Tactile Norwegian Sign Language, is also present (Zorzi et al. 2025).

In current practice this means that they are placed in classrooms with hearing students and are unable to regularly socialise with other deaf children (Haualand & Holmström 2019). Deaf and hard-of-hearing children are typically offered cochlear implants and hearing devices, and the number of cochlear implantations is expected to increase over time (Haualand et al. 2023). Examination of participants in the NSL Corpus (Ferrara 2024) suggests that deaf signers know multiple sign languages and may tend to move away from the places they were born (Arnold 2024).

In NSL, mouthing (munnstillinger, munnbevegelser, ordbilder in Norwegian) was described relatively early in the study of sign languages, but has not received much explicit treatment more recently. Mouthing is described as so strongly integrated into NSL that it is perceived as obligatory in marking certain meaning differences (Haualand et al. 2023). This is implicit in educational resources like the Tegnordbok dictionary in which manual signs are documented with mouthing; this is not necessarily the case across sign languages. In terms of distribution, mouthings are most likely to be found at the beginning of narratives and dialogues. They are primarily nouns and bare verbs and much less commonly derived verbs or classifier predicates (Vogt-Svendsen 2001). Anible & Bisnath (n.d.) shows a related pattern, finding that mouthing is more likely to occur with lexical signs as opposed to depicting ones (classifier constructions). Most of the examples Vogt-Svendsen (2001) gives are of CONGRUENT mouthing like HVEM+hvem ('who') (p. 25) and MANN+mann ('man') (p. 31). There is one example of the POLYSEMOUS type in the signs ULV ('wolf ') (p. 13) and REV ('fox') (p. 19). Both Vogt-Svendsen (2001) and Ferrara & Halvorsen (2017) report reduplication of mouthing with nouns and verbs that we consider to be pluractional; this is found in other sign languages but not captured in any of the mouthing constructions identified in Bisnath (2024).

In more recent work, Arnold (2024) identifies additional cases of CONGRUENT mouthing, particularly of wh-words, potential cases of MORPHO-PHONOLOGICAL and MORPHO-SYNTACTIC mouthing, and FREE mouthing. The potential MORPHO-PHONOLOGICAL case is of WHERE being used with hva ('what') and hvor ('where') mouthing to signal the respective interrogatives. There is also a case in which TEGN3 ('sign') and the mouthing bruke ('use') co-occur in a larger utterance asking an interlocutor to specify the sign they used for a concept. The mouthing on its own can be interpreted as specifying the predicate of the utterance, thus acting as part of a MORPHO-SYNTACTIC mouthing construction. A phrasal FREE mouthing example is Hva sa du? ('What did you say?') which appears to be used as a unit in other-initiated repair (Arnold 2024: 204). Mouthing is also reported with pointing to ask questions, fingerspelling4 as in B-A-L-K-A-N+Balkan (Arnold 2024: 158), and in toponyms with single manual alphabet handshapes as in J+Jakobsli (Arnold 2024: 205) and N+Nidarvoll (Arnold 2024: 160).

This overview shows that mouthing has been used and continues to be used in NSL in the four most frequent construction types cross-linguistically (Bisnath 2024). More notable is what is missing, namely understanding of signers' perspectives of how mouthing is implicated in comprehension of NSL and description of distributions of mouthing. This study takes on the former, leaving the latter for when mouthing has been annotated more widely in the NSL Corpus (Ferrara 2024). The study is oriented around the following research question: Are NSL signers more accurate and certain at identifying POLYSEMOUS manual forms when they are produced with a plausible mouthing compared to without? The overarching motivation is to examine how language users make use of semiotic resources, regardless of modality and named language association, in comprehension. We focus on POLYSEMOUS constructions as their manual element is ambiguous without mouthing leading us to expect that their mouthing is most conventionalised (recall Section 2). This makes them a good candidate for showing the role of mouthing in lexical identification as we can assume that signers might expect to see this kind mouthing and respond differently when they do not. Subsequent sections describe the task and stimulus design and predictions. The stimuli and data can be found via this link: https://zenodo.org/records/22977362.

4.1 Task design

The task was designed to be distributed online and so is shorter and less controlled than experiments done in laboratory contexts to increase recruitment and retention. Developing this type of paradigm is important when working with small, scattered linguistic communities like that in Norway. Data was collected from September 20th to October 2nd 2025, primarily through social media networks. The task and following background survey were made in Gorilla Experiment Builder and presented in written Norwegian (https://app.gorilla.sc/openmaterials/ 1338547).5

Participants see 24 unique manual forms, all produced by the second author.6 Twelve forms are test items (in 3 mouthing conditions) and 12 filler items (in 2 location conditions). All items are nouns with at least medium imageability according to ratings for Norwegian (Lind et al. 2015). Norwegian ratings are used because there is no comparable database for NSL. Participants were randomly distributed into one of three pseudo-randomised lists which each contained all 24 manual forms in the same order. Across lists, the manual forms appear in all possible conditions. Within each list four test items appear in each mouthing condition and six filler items in each location condition. After seeing each item, participants are asked two timed questions (see Figure 1). They are given 15 seconds to type one word to represent the meaning of the sign they saw (Norwegian: Hva tror du tegnet betyr? Skriv svaret med ett ord. English: What do you think the sign means? Write the answer with one word.), and 7 seconds to rate how sure they are of their answer using a labelled five-point Likert scale (Norwegian: Hvor sikker er du på svaret ditt? English: How sure are you of your answer?). Allowing participants to give open responses deviates from previous studies in which the space of possible answers is pre-constrained through the use of decision paradigms, but has the advantage of making the stimuli more decontextualised. After the task, participants were asked nine questions in a survey format to assess their NSL experience (see Appendix A.1).

The test items are manual forms that are ambiguous without mouthing, or fall into Bisnath (2024)'s MORPHO-PHONOLOGICAL mouthing type. An example of this is the 5-claw handshape produced on the cheek with short repeated twists, which, when produced with the mouthing tomat ('tomato'), is a sign for tomato, and when produced with the mouthing eple ('apple') is a sign for apple. The test items are produced in three mouthing conditions: (i) MATCHED, plausible mouthing for manual form e.g. tomat (ii) ZERO, no mouthing (iii) MISMATCHED, real Norwegian words that are unlikely to appear with the manual form in citation form (see examples in Table 1). A plausible mouthing here refers to one that exists in the Tegnordbok dictionary.

As the manual forms are intentionally chosen to be ambiguous, multiple mouthings could have been paired with the same manual form to create MATCHED items; however for the sake of simplicity, only one mouthing was chosen. This mouthing was chosen by referencing entries in the Tegnordbok dictionary and the intuitions of the second author. The manual-mouthing pairs in the dictionary are assumed to be reasonably familiar to NSL signers. We did this because there is no available database of frequencies of manual-mouthing pairings for NSL (or likely any sign language). Within the groups that had the same manual form and different mouthings, we chose the mouthing that (i) formed a manual-mouthing pair for concepts that did not have an alternative sign in Tegnordbok according to the second author and (ii) had the highest imageability. Thus in the grouping EPLE-TOMAT-AUGUST ('apple-tomato-august'), TOMAT is selected because there is another sign for EPLE and it has a higher imageability rating than AUGUST. The mouthings in the MISMATCHED condition were selected to be either Norwegian verbs or adjectives i.e. not nouns, to begin with a sound that has a different articulation location than the real mouthing, and to have the same number of syllables as the real mouthing. Thus, the MISMATCHED counterpart of TOMAT has the mouthing høyre ('right').

5 Analysis & Findings

The sample consists of 35 deaf and hard-of-hearing participants who said they had done the experiment once, and defined themselves as knowing NSL very well or fluently. Participants are heterogeneous in their age (m=38, M =35, sd=13.5, min=19, max=77), age-of-onset of NSL (m=2.6, M =1, sd=4.2, min=0, max=16), and years spent participating in the deaf community (m=34.6, M =35.5, sd=16.1, min=0, max=65). The resulting ratings and open responses were analysed quantitatively and qualitatively respectively.

To assess accuracy, the second author examined all the open-response answers given alongside the relevant stimuli and determined if the answer was plausible. She examined the responses given and determined if her interpretation of the manual-mouthing constructions she produced could be interpreted to be the concept given as a response. We took this route as the stimuli had relatively natural mouthing i.e. not highly-emphasised, and thus the same mouthform could be associated with multiple words.

6 Discussion

In this study we aimed to expand understanding of how a cue that has received little attention in multimodality studies -mouthing -contributes to comprehension. We did this by examining an extreme case in NSL, that of POLYSEMOUS mouthing constructions -groups of signs with the same manual form disambiguated by mouthings. We innovated on existing lexical identification paradigms by allowing for open responses, thus making it possible to gain insight into how participants might be bringing together mouthing and manual elements. Our quasi-experimental approach was useful in that it likely increased participant recruitment, but did not allow for more precise and/or indirect behavioural measures, like reaction time. Instead we opted for explicitly asking participants for certainty ratings, which were able to distinguish between the conditions. For researchers interested in recruiting larger and more diverse participant samples in contexts similar to that of Norway (geographically dispersed, industrialised), designs such as ours may be necessary. In the following we situate our findings in the literature on sign languages and co-speech gesture and our methodological contributions.

The significant difference in accuracy between the MATCHED and MISMATCHED constructions demonstrates that NSL signers are actively attending to mouthing when identifying signs, at least when presented in a decontextualised task viewed on a screen. Lowered accuracy and certainty with MISMATCHED constructions suggests that comprehenders have phonological and/or P r e p r i n t Correspondence: fbisnath@umich.edu semantic expectations linked to the mouthing component that can be disturbed, as evidenced by responses that roughly translate to '...but mouth was different' and 'funny in mouthing...' to MIS-MATCHED items. This would be expected for MORPHO-PHONOLOGICAL mouthing constructions as definitionally there should be a limited number of allowable mouthings. That the Norwegian participants minimally attend to mouthing aligns with existing research on NSL and with studies of other sign languages showing that deaf signers tend to look at the face, as opposed to the hands, when viewing videos of signing (Agrafiotis et al. 2003). Gappmayr (2026)'s experimental studies of fingerspelling with and without mouthing in American Sign Language adds some specificity, showing deaf perceivers look to the face more often when mouthing is present. A caveat to this is that deaf signers' looking behaviour may be different in face-to-face interaction as early-exposed American Sign Language signers tend to look between the eyes while adult sign language learners tend to look at the mouth (Emmorey et al. 2009). It is also not clear what differences there may be when viewing videos on computer screens vs. mobile phones -in the present experiment it was possible to do both.

These findings suggest that the mouthing element is broadly analogous to co-speech gestures that resolve ambiguous spoken statements (Hinnell & Parrill 2020), allowing for differences in ambiguity across sentences vs. words/signs and mouthings vs. gestures. Mouthings may represent an intersection between iconic and emblematic gestures as their form reflects that of spoken words which belong to larger symbolic systems. However, much is left to be theorised about the comparability of mouthing in sign languages and co-speech gesture; doing so would be a useful means of including the practices of deaf populations in understandings of multimodality in language.

Qualitative analysis of MISMATCHED stimuli suggests that signers might prefer to ignore the mouthing element when presented with isolated polysemous manual forms and unlikely mouthings. In fact, they largely behave as they do with ZERO stimulus items. This seems to be the case when banan is a response for PØLSE+grave as variants of BANAN and PØLSE are POLYSEMOUS mouthing constructions (with potential minor phonetic differences in Figure 5a). However, it is important to note that the same mouthing could correspond to multiple Norwegian words and can be further complicated by dialectal variation in Norwegian. This variation likely cannot fully explain why a mouthing of grave could be interpreted as banan, but this is an empirical question to be considered in the future.

What could it mean that signers appear to be drawing on mouthing in sign identification in some cases? In Figure 5c, we see an instance in which klemme ('hug') is given as a response for BUNAD+glemme despite the differences in the manual components of BUNAD and KLEMME. A potential reason is that manual forms with the same location may be perceived as similar; this is reported in American Sign Language (Hildebrandt & Corina 2002), but has not yet been explored in NSL. Such an explanation however cannot account for cases like Figure 5b in which the manual form of the test item and the participant's response differ in all parameters.

Clearly the findings of this study do not reflect comprehension in in-person communication. That is, we do not expect that polysemous signs remain so as a conversation proceeds and we expect that participants will signal that they need clarification if they are not understanding something (Skedsmo 2020a). However, this study quantifies the pieces that context may need to fill when elements like mouthing are absent or obscured. Future work should consider the role of mouthing in comprehension of manual forms that are not typically polysemous (CONGRUENT mouthing) as well as mouthing in sentential and conversational contexts.

This study describes the use of a multimodal multilingual phenomenon -mouthing -in comprehension of a sign language. It demonstrates that Norwegian mouthings aid lexical identification and certainty of comprehension for deaf users of Norwegian Sign Language. Similar findings have been made in other sign languages regarding mouthing specifically, and more broadly with co-speech gesture. This study makes a novel contribution in identifying potential ways in which comprehenders might bring together manual and mouthing components. The most common strategy appears to be to ignore the mouthing element when it might be viewed as conflicting with the manual form, suggesting prioritisation of the manual channel in comprehension.
