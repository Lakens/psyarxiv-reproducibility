Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. The LLM can fail to identify information in the paper, and will not have access to information in paragraphs in the paper other than those that contain the word ‘power’. This package was validated by the Metacheck team on articles in Psychological Science.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

This module was developed by Lisa DeBruine and Daniel Lakens

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). Embedded haven labels from data files are also harvested directly.

Each data column is then matched against the parsed variable definitions with match_column_labels(), using normalised-name matching with experiment-group scoping, haven-label priority, and rule-based label-equivalence merging.

Beyond the variable label, the module harvests the DDI-style per-variable properties a source supplies: the value labels / code list (the 1=“Strongly disagree”…5=“Strongly agree” mapping — from SPSS/Stata value labels and from a codebook “values”/“coding” column), the missing-value scheme (which codes denote missingness, from haven declared missings and labels that read as “refused”/“n/a”), and question text and columns when present. These are carried onto the matched data columns and exported into the Psych-DS variableMeasured (as a schema.org code list plus namespaced metacheck: fields).

The module defaults to rules-only when llm_use(FALSE). When llm_use(TRUE), three optional LLM tiers run: parsing unstructured codebook text that the rules could not handle, fuzzy-matching still-unlabelled columns to still-unmatched codebook variables, and merging conflicting label definitions into a single canonical label.

How Repository Check works

This module retrieves information from repositories.

The Repository Check module lists files on the OSF, GitHub, ResearchBox, DSpace (PsychArchives and other legacy- and DSpace 7-based installations), Zenodo, Dataverse, Figshare, Dryad, ReShare, 4TU.ResearchData, Mendeley Data, DataONE (Arctic Data Center, KNB, and other member nodes), and LDbase based on links in the manuscript.

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Virtual Reality (VR) is increasingly used to study Cognitive load and Acute Stress. But VR comes with side effects such as Cybersickness and Visual fatigue. It remains unclear if we can dissociate psychophysiological responses due to confounding effects. Hence, we conducted two experiments to study and distinguish them. Participants fulfilled a Baseline, Stroop task under four different experimental conditions, Relaxation and Endline. We recorded Stroop performances, Eye tracking (ET), Electrocardiography (ECG), Electrodermal activity (EDA), self-reported Cognitive load, Stress, Cybersickness, Visual fatigue, and Disorientation. Pupil diameter, Blink frequency, Fixations, HR, HRV, and Skin Conductance Response derived between the different conditions. Most of the extracted features from ET, ECG, and EDA showed no differences between states. Despite relaxation steps, Saccade ratio, Blink frequency, Blink duration and Pupil size for ET, Heart rate for ECG, Rise time of the mean skin conductance level, the Arc length of the skin conductance level for EDA were still not back equivalent to baseline. Cognitive load differs from Acute stress based on the Heart rate feature from the ECG sensor. Cognitive load provoked more response with EDA features than Visual fatigue / Cybersickness with the ALSC feature. However, most of those differences have small effect sizes. We underline a 60 minutes immersion "limit." ET was more sensitive to Visual fatigue / Cybersickness compared to Cognitive load and Acute Stress and ECG to Cognitive load compared to Acute Stress. We documented physiological features varying depending on the state and which one allowed their differentiation. However, side effects can confound other state measures; especially the longer participants are immersed. More experimental inputs are necessary to tackle this research question.

1 Introduction

1.1 Background

Virtual Reality (VR) is increasingly used in cognitive science to easily control stimuli and gather psychophysiological data (Tarr & Warren, 2002; Kourtesis et al., 2020; Koushik et al., 2020; Vasser & Aru, 2020; Neo et al., 2021). However, VR drives health and safety-related issues for users (Somrak et al., 2019; Lavoie et al., 2020; Y. Chen et al., 2021; Grassini & Laumann, 2021; Masopust et al., 2021; Souchet, Lourdeaux, et al., 2022). VR Heath and safety issues are known as Virtual Reality Induced Symptoms and Effects (VRISE) (Nichols & Patel, 2002; Sharples et al., 2008). According to Stanney et al. (2021) 80% of users experience VRISE at various degrees, and they could impact working memory (S. Park, Kim, et al., 2021). Despite the growing introduction of VR in cognitive science studies, little is known about the effect of VRISE on the data collected in VR experiments.

In recent years, the relevant research has mainly focused on Cybersickness (Mittelstaedt, 2020; Caserman et al., 2021; Howard & Van Zandt, 2021; Tian et al., 2022). However, Cybersickness spans a wide range of issues(K. Stanney et al., 2020) which limits our understanding of the exact sources and effects of VRISE (Souchet, Lourdeaux, et al., 2022). A growing body of the literature uses electrocardiography (ECG), electrodermal Activity (EDA), and eye-tracking/pupillometry (ET) to measure Cybersickness (Dennison et al., 2016; E. Chang et al., 2020). However, Cybersickness might be accompanied by psychophysiological responses caused by sources other than a visually induced motion sickness only, such as cognitive load, stress, or visual fatigue (Rastgoo et al., 2018; Arza et al., 2019; Charles & Nixon, 2019; Koohestani et al., 2019; Matsuura, 2019; Tao et al., 2019; Armario et al., 2020; Lopes et al., 2020; McNamara & Mehta, 2020; Nath et al., 2020; Vanneste et al., 2020; Halbig & Latoschik, 2021; Skaramagkas et al., 2021; Wood et al., 2021; Dammen et al., 2022). Furthermore, most previous contributions focus on one effect at a time, not considering other possible reasons for measured psychophysiological variations (Souchet, Lourdeaux, et al., 2022; Souchet, Xie, et al., 2022).

Finally, to the best of knowledge, there is no evidence that different states (in the rest of the article, when we refer to states, we imply cybersickness, visual fatigue, cognitive load, and acute stress all together to avoid relisting them) can be clearly distinguished based on psychophysiological measures (Maraj et al., 2021; Souchet et al., 2021). Hence, confounding between different states have not been sufficiently investigated yet.

A significant issue of human response to VR is the ability to encompass a variety of complex psychophysiological variations depending on numerous factors (Krohn et al., 2020; Michela et al., 2019). Therefore, the validity of the in-lab strategy to replicate such complexity in controlled settings is challenging (Holleman et al., 2020; Vasser & Aru, 2020). Some sensors are already embedded, or are about to be, in consumer Head Mounted Displays (HMDs), making their use more convenient (Clay et al., 2019; Floris et al., 2020). Several features can be inferred from signals obtained from such sensors. Therefore, deciding which sensors and features should be used to assess each state is an open question. Finally, considering possible links between states (Souchet et al., 2021; Souchet, Lourdeaux, et al., 2022), it is unclear whether it is possible to differentiate them solely based on psychophysiological signals.

This paper documents an attempt to distinguish cybersickness, visual fatigue, cognitive load, and acute stress in VR based on behavioral, selfreported (called "subjective" in the rest of the paper), and physiological data (ECG, EDA, ET) acquired in two randomized controlled (between and within-subject) studies with participants recorded at baseline, during a Stroop task a relaxation period, and an Endline (similar to baseline but at the end of the procedure). We tackle three research questions through height hypotheses to identify specific physiological features associated with each state, the impact of a relaxation period and immersion duration on those features, and which features allow states differentiation. The paper follows an Introduction, Methods, Results, and Discussion (IMRaD) structure.

1.2 Cybersickness in VR and physiological markers

Cybersickness has been defined as an uncomfortable side effect experienced by users of immersive interfaces commonly used for VR (Nesbitt & Nalivaiko, 2018, p. 1). It is associated with symptoms such as nausea, postural instability, disorientation, headaches, eyestrain, and tiredness (Bockelman & Lingum, 2017; Davis et al., 2014; Lawson, 2014; Nesbitt & Nalivaiko, 2018; E. Chang et al., 2020; K. Stanney et al., 2020; Keshavarz & Golding, 2022; Tian et al., 2022; da Silva Marinho et al., 2022). Measuring and predicting Cybersickness with physiological data is democratizing (Dennison et al., 2016; E. Chang et al., 2020; Islam et al., 2020; Lopes et al., 2020; K. Stanney et al., 2020; Caserman et al., 2021; Souchet, Lourdeaux, et al., 2022). We gathered 17 previous work using ET, ECG, and EDA to measure Cybersickness in VR.

Park, Mun, et al., 2021). Gaze movements and blink frequency are the leading features in assessing Cybersickness (four out of eight papers). In addition to Gaze patterns, pupil diameter, fixations, and saccades are also used. The studies included M = 31.00 ± 16.44 participants with a M = 25.67 ± 2.03 years old and a M = 16.58 ± 11.97 minutes stimuli duration. HTC Vive, pro eye, is the most commonly used HMD. Overall, the results from past work we reviewed indicate that Cybersickness increases over time and is characterized by a blink frequency increase.

In Table A.2, we summarized eleven previous work published between 2019 and 2022 using ECG to measure Cybersickness (Cebeci et al., 2019; Garcia-Agundez et al., 2019; Geršak et al., 2020; Hemmerich et al., 2020; Islam et al., 2020; Niu et al., 2020; Magaki & Vallance, 2020; Tsai et al., 2020; Jung et al., 2021; S. Park et al., 2022; Reyero Lobo & Perez, 2022). HR is the leading feature in assessing Cybersickness (ten out of eleven papers). The studies included M = 26.40 ± 14.92 participants with a M = 25.11 ± 4.16 years old and a M = 14.89 ± 7.98 minutes stimuli duration. HTC Vive is the most used HMD. Overall, the results indicate that HR increases with Cybersickness in VR, and Cybersickness reduction techniques tend to decrease this HR rise in VR.

The main physiological features used to assess Cybersickness are blink frequency, HR, and SCR, which are associated with Cybersickness. Cybersickness increases with VR exposure duration.

1.3 Visual fatigue in VR and physiological markers

Visual fatigue is a physiological strain or stress resulting from excessive exertion of the visual system (Lambooij & IJsselsteijn, 2009). Symptoms include eyestrain, headache, blurred vision, dry eyes, and pain in the neck and shoulders (Sheppard & Wolffsohn, 2018). PC, tablets, or smartphones cause less visual fatigue than HMDs (Han et al., 2017; Souchet et al., 2018; X. Yu et al., 2018; Zhang et al., 2020). The main factor influencing visual fatigue in VR due to Stereoscopy is the accommodation-vergence conflict, although several other factors can step in (Bando et al., 2012; Hirzle et al., 2020 Hirzle et al., , 2022)). This conflict arises with HMDs (Yuan et al., 2018; Matsuura, 2019; Souchet, Lourdeaux, et al., 2022). Visual fatigue has been widely studied through ET as it allows continuous and uninterrupted recording while the user is wearing the HMD, rather than solely relying on pre-and post-measurements (Souchet et al., 2021).

In Table A.4, we summarized seven previous work published between 2019 (when the Vive Pro Eye was out) and 2022 using ET to measure visual fatigue (Iskander et al., 2019; Jacobs et al., 2019; Shen et al., 2019; Y. Wang et al., 2019; Thai et al., 2020; X.-L. Chen & Hou, 2021; Marshev et al., 2021; Souchet, Xie, et al., 2022). Blink frequency is the leading feature in assessing visual fatigue (six out of seven papers). Pupil diameter, fixations, vergence angles, and saccades are also used. The studies included M = 27.38 ± 31.90 participants with a M = 29.65 ± 6.52 years old and a M = 30.38 ± 24.58 minutes stimuli duration. HTC Vive, pro, and/or eye are the most used HMDs.

Overall, the results from past work indicate the blink frequency, which increases after at least 15 minutes in VR, is the most used physiological marker to measure visual fatigue, which increases over usage time.

ECG and EDA are not usually used to assess visual fatigue. Interestingly, (Ramadan & Alhaag, 2018) used ECG and EDA to measure visual fatigue by comparing 2D and S3D TVs. However, to the best of our knowledge, only one using HMDs measured visual fatigue with those sensors yet (Souchet, Xie, et al., 2022). But those sensors have been used to measure Cybersickness (Dennison et al., 2016; E. Chang et al., 2020), including oculomotor symptoms that are sometimes hard to differentiate from visual fatigue symptoms (Souchet, Lourdeaux, et al., 2022).

The stimuli, duration, and administration are very heterogeneous among past studies. Although blink frequency is the predominant feature extracted from the ET signal, several work also used others, showing no firm consensus on the best measurement of visual fatigue.

1.4 Cognitive load in VR and physiological markers

Cognitive load corresponds to a subjectively experienced physiological processing state, revealing the interplay between one's limited and multidimensional cognitive resources and the cognitive work demands exposure (Van Acker et al., 2018). Cognitive load depends on cognitive work demands (Causse et al., 2017) and resource consumption. Two demands are often referred to: time pressure and task difficulty/complexity (Galy et al., 2012). In ergonomics approaches, cognitive overload occurs when the operators face more stimuli than they can handle while maintaining their standards of performance (Young et al., 2015). Moreover, working memory is impacted differently in VR compared to other apparatuses (Dan & Reiner, 2016; Lobjois et al., 2021; Mittelstaedt et al., 2019; S. Park, Kim, et al., 2021; Souchet, Lourdeaux, et al., 2022). 1.5 Acute Stress in VR and physiological markers

Stress is the individual state of uncertainty about what needs to be done to safeguard physical, mental, or social well-being (Peters et al., 2017). Acute Stress is a sudden or short time stressor (trauma, perceived threat, death of a loved one, job loss…) in opposition to chronic Stress (long-time stressor) (Fink, 2007, p. 192-193). Our article considers Stress as a negatively perceived factor or situation from a psychological domain (Bienertova-Vasku et al., 2020). The Autonomic Nervous System (ANS) adapts the organism to internal and external changes, maintaining bodily homeostasis and coordinating Stress's bodily responses (Richter & Wright, 2013a; Johnson, 2018). ANS has three subdivisions: -Sympathetic Nervous System (SNS) (Richter & Wright, 2013c) controls the "fight or flight" response preparing the body for physical activity, the effort to either fight off or flee from danger (Chamberlain & Meuret, 2017) -Parasympathetic Nervous System (PNS) (Richter & Wright, 2013b) controls the "rest and digest" response, restoring to counterbalance the stress reaction -Enteric Nervous System (ENS) controls the "gut-brain axis" gastrointestinal function (Rao & Gershon, 2016) Those bodily responses include various physiological variations assessed with ET, ECG, and EDA (Rastgoo et al., 2018; Arza et al., 2019; Armario et al., 2020; McNamara & Mehta, 2020; Nath et al., 2020). VR has been used to induce and study Stress (Dammen et al., 2022). 1.6 Confounding effects and states psychophysiological markers confusion

In our presentation of previous work measuring Cybersickness, Visual fatigue, Cognitive load, and Acute Stress with ET, ECG, and EDA, we gathered 69 papers. Overall, those studies included 36.67 ± 29.41 participants who were 26.61 ± 4.74 years old and were presented with stimuli with a duration of 20.05 ± 17.70 minutes. In the supplementary materials (file 1), we display boxplots comparing the number of participants' mean age and stimuli durations between states. From one state to another, these numbers can be quite different. Across these studies, the same physiological signals were recorded, and similar measures, e.g., HRV, were used. A growing part of the literature uses several sensors (ET + ECG + EDA) to assess these states. However, only one state is assessed at a time, possibly missing confounds or the effect of other states. Previous work aims to elicit each state in isolation, and hence, they create stimuli for that purpose. But this leaves out other plausible co-occurring states with the same stimuli disregarding alternative hypotheses or explanations in physiological variations by focusing the spotlight on one source.

Furthermore, confounding effects are well-documented with studies relying on physiological data (Howards, 2018). In our case, one psychophysiological state could influence another or better explain physiological variations. Such confounding effects make it hard to differentiate one state from another. The various data processing methods for hypothesis testing make findings hard to generalize. These points are relevant whether data is acquired with ET, ECG, or EDA (Dirican & Göktürk, 2011; Sirois & Brisson, 2014; Shaffer & Ginsberg, 2017; Clay et al., 2019; Hughes et al., 2019; Lohani et al., 2019; Tao et al., 2019; Abdelall et al., 2020; Wulvik et al., 2020; Czerniak et al., 2021; Giorgi et al., 2021).

Researchers sometimes underline the complexity of those psychophysiological states (Argyle et al., 2021; Becker et al., 2022; Souchet, Lourdeaux, et al., 2022). Such issues apply when VR is used to study human psychophysiology or VR itself. For instance, when assessing cognitive load, measurements can be impacted differently depending on the perceptual channels stimulated (Marucci et al., 2021). Furthermore, if one sensor is also used to interact with the virtual environment, in Silva et al. (2019), an eye tracker, this can impact VRISE measurements. Finally, 3D object characteristics to stimulate depth perception can also impact Cognitive load (Iskander et al., 2019).

There is a risk that a specific focus minimizes or does not consider confounding effects or that one state can be linked to another (Hancock, 2017; Howards, 2018; Jager et al., 2020).

Typically, research focusing on Stress and Cognitive load pays little attention to the possible impacts of Cybersickness or Visual fatigue during their physiological data recording. Conversely, researchers focusing on Cybersickness or Visual fatigue would not consider Stress or Cognitive load induced by tasks during their physiological data recording. The same issues might apply to Presence (Slater et al., 2022) or other psychological aspects triggered by VR. In summary, alternative explanations to measured psychophysiological variations are, at best, evoked in previous work within material and methods or discussion and limitation sections. By extension, contributions regarding human physiological variations under VR exposure often rely on correlations with questionnaire-based data (E. Chang et al., 2020). Yet, questionnaires are not all standardized. Furthermore, questionnaires can be biased (Palaniappan & Kum, 2019). One is the ambiguity between VRISE or stress/anxiety-related questions with the Simulator Sickness Questionnaire (SSQ), for example (Bouchard et al., 2021). Questions before content exposure in Human-Computer Interactions can induce a priming or anchoring effect (Furnham & Boo, 2011; Weingarten et al., 2016; Doherty & Doherty, 2018). Such priming could even influence experimenters (Doyen et al., 2012). In other words, a set of questions can influence participants' self-reporting. Mentioning Cybersickness and Visual fatigue specifically implies that users are experiencing (and expecting) side effects if they are mentioned at the consent step or assessed before immersion. Therefore, the complex role of placebo and nocebo effects could even step in, depending on users' traits and emotions relating to the VR experience, as documented in medicine (Faasse et al., 2019; Geers et al., 2020). Technostress, which exists with devices other than HMDs (La Torre et al., 2019), could also be considered a confound. Finally, depending on the task and required cognitive resources, evidence measured (e.g., behavioral data) can reflect cognitive processes other than those intended to be measured (S. Gilbert et al., 2012).

There are references to confounding effects in several previous work's discussion and limitation sections, whether they intend to measure Cybersickness, Visual fatigue, Acute stress, or Cognitive load. Here we collected a sample to provide an overview of contributions pointing to the confounding effects of one state on another: -Visual fatigue or Cybersickness in VR as confounding effects of stress assessment (C.-P. Yu et al., 2018; X. Yu et al., 2018; Y. Liu et al., 2019; Caldas et al., 2020) -Stress or emotions or general arousal as confounding effects of cybersickness assessment (Dennison et al., 2016; Gavgani et al., 2017; Magaki & Vallance, 2017 , 2019; Mittelstaedt, 2020; Ashiri et al., 2021; Holzwarth et al., 2021; Varmaghani et al., 2021) -Stress or arousal as confounding effects of cognitive load assessment (Galy et al., 2012; Epps, 2018; Collins et al., 2019; Parent et al., 2019; Borghini et al., 2020; Wulvik et al., 2020) -Cybersickness or visual fatigue as confounding effects of cognitive resources and cognitive load (Daniel & Kapoula, 2019; Bernhardt & Poltavski, 2021; S. B. Gilbert et al., 2021; Souchet et al., 2021; Xu et al., 2021; Kaplan-Rakowski et al., 2022; Sepich et al., 2022).

Previous work have considered complex interactive influences between those states. These include the following linked effects: -Cybersickness and cognitive load (Mittelstaedt et al., 2019; Varmaghani et al., 2021; Xu et al., 2021; Breves & Stein, 2022; Kooijman et al., 2022; Harris et al., 2022; Sepich et al., 2022). -Cybersickness and stress or anxiety (Mittelstaedt, 2020; Pot-Kolder et al., 2018; Powell et al., 2021). -Visual fatigue and cognitive load (Bernhardt & Poltavski, 2021; Daniel & Kapoula, 2019; Souchet et al., 2021). -Stress and cognitive processes (and associated working memory resources) (Alsuraykh et al., 2018a (Alsuraykh et al., , 2019;; Gioia et al., 2021; Becker et al., 2022).

We must embrace that complexity when measuring human psychophysiological variations within VR (Sirois & Brisson, 2014). This implies robust experimental design and statistics (Jones et al., 2003; Sullivan & Feinn, 2012; Hinkelmann, 2015; Dean et al., 2017). Researchers have debated measuring Cybersickness, Visual fatigue, Stress, and Cognitive load via physiological sensors for their reliability, precision, and ability to assess those states better (Ayres, 2020; Crosswell & Lockwood, 2020; Saredakis et al., 2020). HCI research suggests a connection between Stress and Cognitive load (Alsuraykh et al., 2019). Physiological variations measurement in our context faces the same replication issues faced by science in general, specifically psychology and computer science (Collaboration, 2015; Muthukrishna & Henrich, 2019; Cockburn et al., 2020). Therefore, measuring complex psychophysiological states requires a step-bystep validation of experimental paradigms (Krohn et al., 2020) and a standardized set of stimuli. This would allow gathering reliable proof of efficient psychophysiological measures to assess VRISE and Acute Stress and Cognitive load in VR. With this in mind, we present the motivation for using the Stroop task in VR in the next section.

1.7 Stroop task in VR and its utility regarding states' psychophysiological differentiation

The Stroop task has been used to induce: Stress (J. R. Carter & Goldstein, 2014; Usui & Nishida, 2017; van Oort et al., 2017; Brugnera et al., 2018; Arza et al., 2019; Kerous et al., 2020); to study acute stress effects on executive functions such as inhibition (Davison et al., 2018; Henderson et al., 2012; Shields et al., 2016); as well as Cognitive load independently of Stress (Daniel & Kapoula, 2019; Gwizdka, 2010). Previous work have transposed Stroop tasks in VR, such as (Armstrong et al., 2013; Gradl, Wirth, Mächtlinger, et al., 2019; C. Chang et al., 2020; Kerous et al., 2020; Asbee et al., 2022). Cognitive load and stress induction with the Stroop task is documented, and effects on participants' physiological variation are observable in young and older healthy adults in several previous work (Gradl, Wirth, Richer, et al., 2019; Kerous et al., 2020; Parsons & Barnett, 2019; Parsons & Courtney, 2018; Sayed et al., 2016).

Interestingly, Stroop stimuli also illustrate confusion in psychophysiological effects that are expected to be induced via such tasks, whether Cognitive load related or Stress related. The Stroop task has not been designed to induce and study Cybersickness or Visual fatigue, which reduces that bias. Hence, as a well-established and controlled set of stimuli, the Stroop task appears to be a good pick to test hypotheses about Cybersickness, Visual fatigue, Cognitive load, and Acute Stress in VR differentiation. 1.8 Research questions and contributions Previous work show that features extracted from ET, ECG, and EDA allow for measuring Cybersickness, Visual fatigue, Cognitive load, and Stress. However, discussions in previous work regularly indicate confounding effects that could mitigate the reliability of results. Possible confounding effects induce artifacts when trying to measure each state independently. Concretely, physiological variations could be wrongly associated with one state as another could provoke similar variations. E.g., heart rate in VR increases with Stress and with Cybersickness or with Stress and Cognitive load. Hence, it is necessary to make sure we can differentiate each state subjectively, behaviorally, and physiologically. Identifying robust and specific physiological markers for each state is crucial. Finally, since stimuli are not standardized, relying on long-established psychological tests such as the Stroop task could better isolate each state. Based on the review of previous work, three main research questions (RQ) arise when trying to measure Cybersickness, Visual fatigue, Cognitive load, and Acute Stress: -RQ1: What are the physiological features characterizing each state? -RQ2: Can we differentiate between different states according to psychophysiological responses? -RQ3: Does using VR to study cognitive load and stress trigger confounding effects in physiological measures due to Cybersickness and Visual fatigue? Simply put, we aimed to study what we actually measure with ET, ECG, and EDA and with those stimuli. We conducted two experiments and tested 8 hypotheses to tackle those research questions. We conducted two experiments: one with a between-subject design and the other with a within-subject design to isolate possible carryover effects better (Putt, 2005). The data acquisition procedures are displayed in Figure 1 for Experiment 1 and Experiment 2.

Participants tried Stroop tasks with four words written on a board to prove they understood the task's purpose before being immersed. After attaching sensors, subjects were seated and instructed to minimize movements but not be physically tense. The instructions were consistently delivered, but the experimenter (Author 1) answered any questions participants might have had about the procedure and instructions .

During Experiment 1, participants were immersed for 26 minutes in VR with a Stroop task lasting 5 minutes. During Experiment 2, participants were immersed for 74 minutes in VR, with four Stroop tasks lasting 20 minutes in total. 2.7 Physiological signals processing and feature extraction

We applied data correction through interpolation and appropriate filtering to mitigate noise and artifacts from ECG, EDA, and ET signals, as described in Supplementary materials (file 7). We used the BioSSPy package (Carreiras et al., 2015 (Carreiras et al., /2022) ) and Neurokit 2 (Makowski et al., 2021) to perform feature extractions with ECG and EDA signals. Therefore, we only describe the main domains without listing each extracted feature.

The ECG signal can be divided into four domains based on Heart Rate Variability (HRV) (Hughes et al., 2019): -Temporal domain features: HRV time-domain features quantify the number of HRV observed during a given monitoring period.

In our case, 30, 60, and 120 seconds are considered.

-Frequential domain features: we applied a fast Fourier transform to separate HRV into High Frequencies (HF) and Low Frequencies (LF) components or very HF (VHF) and Very (VLF), respectively. We used a 120 seconds window for those features. -Non-linear features: we applied Poincare Plots to extract those features. The EDA signal is separated into two domains (Posada-Quintero & Chon, 2020; van Halem et al., 2020): tonic translated into Skin Conductance Level (SCL) phasic translated into Skin Conductance Response (SCR) We extracted four subdomain features from SCR based on (Clausen et al., 2013): Amplitude features, Morphological features, Time features, and Probabilistic features.

The ET signal was processed with the Velocity-Threshold Identification (Lin et al., 2019) recommended by Tobii for pre-processing and feature extraction.

All features have been baselined to reduce inter-subject variability. It was computed during the Baseline (see Figure 1) step between time intervals [60s, 180s].

2.8 Statistical analyses

First, we checked for normal distribution (Ahsanullah et al., 2014) on each dataset before conducting statistical tests. Since most data weren't normally distributed, we used non-parametric statistical tests for Experiments 1 and 2. All statistical analyses are conducted with a confidence of α = 0.05.

Second, we tested possible differences between experimental conditions for all datasets (see section 2.4). In Experiment 1, we used Kruskal-Wallis tests (McKight & Najab, 2010) and Dunn's Post-Hoc tests (Dinno, 2015). In Experiment 2, we used Friedman and Miller-Friedman Post-Hoc tests (Pereira et al., 2015). We used the Bonferroni correction for all post hoc tests (Dean et al., 2017, pp. 83-84). In both experiments, we used Wilcoxon signed-rank tests (Rey & Neuhäuser, 2011) for posthoc tests between two groups or steps when the Miller-Friedman would provide false negative results incoherent with tests between all conditions together. For Experiment 2, our statistical analyses followed three scenarios: -Scenario 1: we tested Control, Dual, Stressful, and Stereoscopy conditions by not considering the order in which participants performed them (randomized): see 1) Group1 when the experimental condition is performed in the first and second steps, and 2) Group2 when the experimental condition is performed in the third and fourth steps.

We have two groups for the experimental condition and eight groups in total. This scenario allowed us to investigate the possible time-related (step position) influence on states for each condition. It results in Control0-1, Control2-3, Dual0-1, Dual2-3, Stressful0-1, Stressful2-3, Stereoscopy0-1, and Sterescopy2-3 defining the experimental condition step's order occurrence and grouped by the first+second and third+fourth steps.

Third, we tested possible correlations between datasets and time-related physiological variations. We used Spearman Rank Correlation Coefficient (Dodge, 2008) since most data sets were not normally distributed.

4 Discussion and limitations

We designed and conducted two experiments using Stroop tasks to test 8 hypotheses linked to three research questions listed in sections 1.8 and 2.6. Our purposes were to measure physiological variations linked to Cybersickness, Visual fatigue, Cognitive load, and Acute Stress but also to differentiate psychophysiological variations between those states thanks to 4 experimental conditions: Control, Dual task (to trigger high cognitive load), Stressful (to trigger acute stress), and Stereoscopy (to trigger Visual fatigue and Cybersickness): see section 2.3. Considering confounding effects, immersion duration impacts, priming, and anchoring effects, we conducted those experiments with a between-subjects and a within-subjects design. We also considered Baselines, Relaxation, and Endline steps in the procedure to investigate how participants' physiological variations behaved after state induction. We discuss our results by type of recorded data. Therefore, researchers only using a specific data set in their work can also easily envision how our results can be relevant when measuring Cybersickness, Visual fatigue, Cognitive load, or Acute Stress instead.

4.1 Subjective data of Cybersickness, Visual fatigue, Cognitive load, and Acute Stress

The majority of past studies participants' perception of Cybersickness, Visual fatigue, Cognitive load, and Acute Stress via questionnaires to interpret physiological variations better (E. Chang et al., 2020) with inherent limitations (Palaniappan & Kum, 2019). For Cybersickness, acknowledging critics toward the SSQ (Bouchard et al., 2021), we used the VRSQ which the total score corresponds to Cybersickness and sub-scores correspond to Visual fatigue and Disorientation (H. K. Kim et al., 2018; Sevinc & Berkman, 2020; Cid et al., 2021). For Cognitive load, we used the gold standard Nasa-TLX (Hart & Staveland, 1988; Cegarra & Morgado, 2009; Paxion et al., 2014), and for Acute stress, we used the STAI-6 (Marteau & Bekker, 1992; Bouchard et al., 1998). Questionnaires were submitted only after each Stroop task. Our purpose was to assess if participants evaluated Stroop tasks differently depending on experimental conditions and how long they have been immersed for experiment 2. We tested two hypotheses directly with questionnaires.

Our first hypothesis was that subjective states (VRSQ, NASA-TLX, STAI-6) differ between experimental conditions (H1).

Results from the first experiment indicate that the Dual task condition induced the most cognitive load compared to every other condition and more Disorientation compared to the stressful condition. But, reported Stress and Cybersickness were about similar. Hence, in a between-subject design with 26 minutes of immersion, VRISE induction in our experimental conditions lightly influenced reported states. Hence, Cognitive load is perceived differently when a highly demanding task influences cognitive resource consumption. This also drove participants to declare more disorientation. However, stressful noise and stereoscopy did not influence state reporting significantly. Results from the second experiment with statistical test scenario 1 (similar to the first experiment) show that participants reported the Dual task condition induced the most cognitive load compared to every other condition. Hence, these results align with those obtained during the first experiment. However, in experiment 2, the Dual task and the Stressful condition drove similar Stress reports but higher than Control and Stereoscopy conditions. Cybersickness, Disorientation, and Visual fatigue are reported to be almost equivalent in the second experiment. Hence, Visual fatigue and Cybersickness induction with our Stereoscopy condition did not affect participants' reporting. H1 is consequently only partially supported. The Dual task was perceived as cognitively challenging in experiment 1 and stressful in experiment 2. The Dual task influenced a higher VRISE reporting and Disorientation reporting. Our fourth hypothesis was that Subjective VRISE (VRSQ, NASA-TLX, STAI-6) depends on which running order (moment in the entire procedure) they are declared after Stroop tasks (H4). In experiment 2, under scenario 2, Cybersickness and sub-VRSQ Disorientation and Visual fatigue reporting increase with time. The more participants were immersed, the more they reported those VRISE. However, Cognitive Load and Stress reporting were not impacted depending on the Stroop task order. Under scenario 3, immersion time seems to influence Cybersickness reporting (and sub-VRSQ) but not subjective Cognitive load and Stress. H4 is consequently only partially supported. Participants did not seem to have mental fatigue linked with the procedure duration or stress accumulation. But, Cybersickness, Visual fatigue, and Disorientation were time-related. Hence, how long participants are immersed drove different reporting.

Our results align with (Gradl, Wirth, Mächtlinger, et al., 2019), which showed SSQ with a significant time effect. (Henderson et al., 2012; Souchet, Xie, et al., 2022) showed that uncontrollability induced in their protocol did not influence stress reporting, similar to our noise for Stress induction. On the contrary, (Brugnera et al., 2018) used the Stress Rating Questionnaire, which showed a difference in reported Stress, but they compared their baseline to the Stroop task. But most previous work using Stroop tasks to assess Cognitive load, Acute stress, Visual fatigue, or Cybersickness did not apply questionnaires (Gwizdka, 2010; Armstrong et al., 2013; Sayed et al., 2016; Davison et al., 2018; Parsons & Courtney, 2018; Parsons & Barnett, 2019; C. Chang et al., 2020; Daniel & Kapoula, 2019). Furthermore, in the majority of reviewed studies, stimuli are too different from ours to allow a coherent discussion.

In summary, inducing Cybersickness, Visual fatigue, Cognitive load, and Acute Stress was not always driving participants to evaluate them differently. Inducing Cognitive load impacted Disorientation reporting with the Dual task condition in experiment 1. But in experiment two, the significant factor was immersion duration. Participants reporting differentiated the Dual task condition from others in both experiments. In experiment 2, the Dual task and the Stressful conditions were rated similarly stressful, showing that participants were aroused by a cognitively challenging task similar to high noise. Hence, cognitive resources triggering should be carefully monitored when assessing Cybersickness as it could confound Disorientation reporting and trigger stress response as well. Immersion duration should be chosen, so participants are not impacted by Visual fatigue and Cybersickness, although it didn't seem to impact Cognitive load and Stress reporting.

With our procedure, even with very static and simple visual stimuli, more than 1-hour immersion drove participants to report higher side effects than their prior evaluations, like previous works hypothesized or measured (Kourtesis et al., 2019; S. Chen & Weng, 2022).

4.2 Behavioral data of Cybersickness, Visual fatigue, Cognitive load, and Acute Stress

The Stroop task is a long-used set of stimuli to study inhibition, Cognitive Load, and Stress (Scarpina & Tagini, 2017; Shields, 2020). In our version, participants must inhibit reading and state the word color out loud. Performance (correct or wrong answers, time to answer) at that test allows interpreting states induction impacts humans' ability to fulfill the task. Participants were exposed to 25 congruent, and 25 incongruent words with the timing presented supplementary materials (file 2).

Our second hypothesis was that Stroop task performances differ between experimental conditions (H2).

In experiment 1, the Dual task globally leads to lower Stroop task performance than other experimental conditions. In experiment 2, under scenario 1, the Dual task and the Stressful conditions impacted performances more than the Control and Stereoscopy conditions. Our correlation between questionnaires and behavioral data in experiment 1 also supports this. While in experiment 2, all states were associated with a drop in performance, with a stronger one under Stress. Hence, displaying stereoscopy did not impact Stroop task performances significantly compared to other conditions despite correlation results with the VRSQ (and sub-part of the questionnaire). H2 is consequently only partially supported. Highdemanding cognitive resources were the most impactful with the Dual task conditions in the two experiments. Stress induction via noise slightly impacted the experiment's performance but was not different from Control and Stereoscopy conditions.

Our fifth hypothesis was that Stroop task performances differ between the running order they fulfil (H5). Based on our results with experiments 2's scenarios 2 and 3, the order in which experimental conditions were performed and whether tasks were fulfilled at the beginning or the end of the procedure did not impact Stroop's performances differently. This is also supported by the weaker associations between questionnaires and behavioral data determined with correlation tests compared to scenario 1. Hence, H5 is not supported. Cognitive fatigue, stress accumulation, and increasing Visual fatigue and Cybersickness with time did not impact Stroop task performances.

Our results contradict some previous work showing the impact of Acute stress on Stroop performances (Henderson et al., 2012; Parsons & Courtney, 2018).

Although Stress seems to have some effects on inhibition (Shields et al., 2016), it didn't significantly impact Stroop's performance with our stimuli. But they are in line with Asbee et al. (2022), showing no difference between their safe and ambush zones (arousal-induce, i.e., whether stress or higher cognitive load). Our results also contradict work showing Visual fatigue impacting Stroop performances (Daniel & Kapoula, 2019). But they align with Dual or cognitively challenging tasks, negatively impacting Stroop's performances (Gwizdka, 2010; Sayed et al., 2016). Previous work comparing standard or flat-screen Stroop administration to VR showed VR drove poorer performance in response time, implying a higher cognitive load in VR (Armstrong et al., 2013; C. Chang et al., 2020). Part of the previous work did not record or present Stroop performance results when studying Stress or Cognitive load (Usui & Nishida, 2017; Brugnera et al., 2018; Arza et al., 2019; Gradl, Wirth, Mächtlinger, et al., 2019; C. Chang et al., 2020; Kerous et al., 2020), or not with tests making it comparable to our procedure (Davison et al., 2018; Parsons & Barnett, 2019). Hence our stressor (alarm noise at 70 dB) might have been too low (Y. Kim et al., 2017).

Taking some distance from the Stroop task, our results with the behavioral data show no impact on the Visual fatigue / Cybersickness induction, while previous work documented post-VR negative impacts on cognitive performances (Mittelstaedt et al., 2019). But our results align with previous work showing no significant effect (Varmaghani et al., 2021). However, Stress might impact executive functions and cognitive resources (Gabrys et al., 2019; Oken et al., 2015). But our Stressful task did not improve Stroop's performance as observed in other setups (Degroote et al., 2020; Sandi, 2013) and instead aligned with observation showing little to no impact of Stress in standard tasks (n-back) in VR (Martens et al., 2019).

The Stroop task is used to study Cognitive load and Acute Stress (Scarpina & Tagini, 2017). Our results indicate that triggering extra cognitive resource consumption impacts performances more than stress-induced via sound randomly emitted at about 70 dB (IADS_712 alarm-buzzer). But this could be explained by the magnitude of our stressor and extra incongruence from the Dual task (Janczyk & Kunde, 2020). The sound was a distractor triggering uncontrollability (Epel et al., 2018). Even though participants reported higher side effects (Cybersickness and Visual fatigue) linked to immersion duration, those didn't seem to impact their performances.

In summary, states induction significantly impacted performances (behavioral data), mainly with high cognitive load induction but not via Acute stress, Visual fatigue, and Cybersickness. However, subjective Cognitive load and Stress were strongly associated with poorer performances. Our experimental conditions might have triggered different cognitive resources (S. Gilbert et al., 2012). Still, behavioral data seemed to reflect higher inhibition requirements with our Dual task but mostly linked to the incongruence of the Stroop task. The loud sound uncontrollability and possible attentional shift induced by accommodationvergence conflict (Souchet et al., 2021) did not inflect performances.

4.3 Physiological data of Cybersickness, Visual fatigue, Cognitive load, and Acute Stress

ET, ECG, and EDA are increasingly used to assess Cognitive load, Acute Stress, Visual fatigue, and Cybersickness (Rastgoo et al., 2018; Arza et al., 2019; Charles & Nixon, 2019; Koohestani et al., 2019; Matsuura, 2019; Tao et al., 2019; Armario et al., 2020; Lopes et al., 2020; McNamara & Mehta, 2020; Nath et al., 2020; Vanneste et al., 2020; Halbig & Latoschik, 2021; Skaramagkas et al., 2021; Wood et al., 2021; Dammen et al., 2022). But through the review of previous work, we identified that exact features used to measure those states are rarely described: see section 1.6. Furthermore, the same features with the same variations characterize different states. Hence, along with measuring each state (which physiological marker is relevant to measure a given state), we intended to differentiate them.

Our third hypothesis was that physiological responses differ between experimental conditions (H3).

In experiment 1, 92.43% of ET, ECG, and EDA features did not differentiate VRISE from our experimental conditions. Most features vary differently with ET features, and the Stereoscopy drives most differences with more fixations and smaller pupils' sizes than other conditions. In experiment 2 (scenario 1), 71.19% of ECG and EDA features could not discriminate between Cybersickness, Visual fatigue, Cognitive load, and Acute Stress differentiation (eye tracker data were not exploitable). Most features vary differently with features extracted from the EDA, and the Dual drives different physiological variations compared to other conditions 70.21% of the time. Physiological variations between the Dual and the Stressful conditions are mostly similar. Consequently, H3 is only weakly but partially supported as some physiological variations show that state induction drove slightly different physiological effects.

None of the previous work using the Stroop task (see section 0) attempted to differentiate physiological variations between Cybersickness, Visual fatigue, Cognitive load, and Acute Stress except one (Souchet, Xie, et al., 2022). This is only a short communication on pre-tests. Hence, we can't compare our results with those studies on that specific matter. One explanation for the lack of comparable results with previous work is that they usually compared Cybersickness, Visual fatigue, Cognitive load, and Acute Stress induction with their baseline or a rest period only. Despite Cognitive load and Acute stress physiological markers characterization being more advanced than Cybersickness and Visual fatigue, very few work directly try to differentiate psychophysiological variations attributable to each. Most previous work would measure and discuss the interplay of Stress on Cognitive load for behavioral data (Bottenheft et al., 2020), but little physiological work exists (Alsuraykh et al., 2018b). Furthermore, they are not trying to differentiate them, and they are trying to show their tangle through co-variation.

The between-subject design (experiment 1) drove fewer physiological variations differences than the within-subject design (experiment 2). This can be due to inter-individual factors. They can't really be captured in a between-subject design, which is a known blind spot or results in interpretation issues when assessing Cognitive load (Vanneste et al., 2020), Acute stress (Crosswell & Lockwood, 2020; Becker et al., 2022; Dammen et al., 2022), Cybersickness or Visual fatigue (E. Chang et al., 2020; Maraj et al., 2021; Souchet, Lourdeaux, et al., 2022), and psychological variables in general (Michela et al., 2019). This also illustrates the fact features showing differences with the largest effect sizes are different between Experiments 1 and 2. Hence, if Cybersickness, Visual fatigue, Cognitive load, and Acute Stress differentiation are possible, it variates depending on the experimental design (within or between subjects). Our experimental conditions might trigger insufficient Cybersickness, Visual fatigue, Cognitive load, and Acute Stress. Hence, a straightforward explanation would be those physiological variations allowing states' differentiation is stimuli-dependent. But, Stroop tasks themselves have a track record at efficiently inducing high Cognitive load and Stress, same with visual fatigue induced via stereoscopy. Paired tests made show differences between the Control condition and the 3 others. We also made experimental condition choices so that the secondary tasks (in the Dual task group) and the noise used (in the Stressful group) would rely on previous efficient state induction (see section 2.3). However, in the present study, we were more interested in uncertainty in how not diametrically different stimuli can drive each state and then try to differentiate them. Therefore, we were expecting very low possible differentiation. Furthermore, one explanation for those results is confounding (Howards, 2018), as presented in section 1.6 of this paper. Instead of focusing on only one state, we englobed 4 states to address these issues. The bigger picture with our experimental conditions is that most features did not differ. Nonetheless, we identified several features that could be a candidate for differentiation. In other words, features that can characterize physiological variations are mostly due to one of the tested states, which come to say they should be prioritized to assess it.

In summary, we contribute to Cybersickness and Visual fatigue literature using more prolonged stimuli, as the previous work's stimuli duration was 20.05 ± 17.70 minutes ( see sections 1.2 and 1.3). In comparison, our participants were immersed for 74 minutes. Our results also help characterize VRISE physiological markers. Furthermore, it shows that even very low VRISE inducers already impact physiological response. The direct implication for psychophysiological data gathering is that peers should acknowledge that more than 1 hour of immersion might create noise in their data collection.

Our eighth hypothesis was that Behavioral and Physiological features strongly correlate with each subjective state (H8). During experiment 1, participants performed lower with state induction, and correlations with behavioral data were stronger with subjective Stress and Cognitive load induction. The EDA features have the most correlations with subjective states. The difference in correlations between Cognitive load and Stress is mainly with HRV domain features associated with Stress but not Cognitive load. Unexpectedly, Visual fatigue correlates strongly with HRV domain features. Visual fatigue strongly correlates with Blink and Fixation features. Hence, we can differentiate how each physiological variation is associated with each state through correlations. In experiment 1, those variations are more associated with Acute stress and Cognitive load than VRISE with ECG and EDA features, but this is the inverse for ET features. For experiment 2, Stroop performances were mainly associated with experimental conditions rather than in which order participants performed the Stroop task. The correlations are similar between subjective Cognitive load and Stress under Scenario 1. Despite statistically significant differences, the association between subjective reporting and physiological variations doesn't allow clear differentiation between the two. Under scenario 2, subjective Visual Fatigue, Disorientation, and Cybersickness have similar associations with physiological features. EDA features are not related to time for Cognitive load but are for Stress and VRISE. Consequently, H8 is partially supported because behavioral and physiological features strongly correlate with each subjective state. Their variations are linked differently with the specific state as those correlations differ depending on state induction.

Most previous work only tested differences between features and only 9 out of the 69 papers we reviewed (see Appendices) tested correlations. Our results with Cybersickness align with previous work (Garcia-Agundez et al., 2019; Hemmerich et al., 2020; Eftekharifar et al., 2021; S. Park, Mun, et al., 2021; S. Park et al., 2022). They also align with previous work on Visual fatigue (Y. Wang et al., 2019). Our results align with previous work on Cognitive load using ET (Eckert et al., 2021; Dubovi, 2022; Reddy et al., 2022). With our tests, we checked for linear correlation, which has limitations (Janse et al., 2021), and some correlations with our data might be shaped differently (e.g., U-shaped).

In summary, correlations show that Cognitive load and Acute stress strongly affected Stroop task performances, but VRISE had weak effects. Physiological features were differently associated with each state as ET was more associated with VRISE, although the longer participants were immersed, the more EDA features were associated with VRISE. EDA and ECG features had some strong associations with Cognitive load and Stress, which are almost always similar to those two states showing how hard it is to differentiate them based on correlations between subjective reporting and behavioral and physiological data.

4.4 Cybersickness, Visual fatigue, Cognitive load, and Acute Stress differentiation

Our general hypothesis was that we can differentiate Cybersickness, Visual fatigue, Cognitive load, and Acute Stress psychophysiological variations (Hgeneral). Looking at the profile data, we only made sure that populations were alike (they were) for each condition and between the two experiments to overcome that kind of bias (Shields et al., 2016; Mittelstaedt, 2020; Shields, 2020; Hertzum, 2021; Howard & Van Zandt, 2021; Jasper et al., 2021; MacArthur et al., 2021; Y. Wang et al., 2021; Widyanti & Hafizhah, 2021; Cao et al., 2022; Harris et al., 2022; da Silva Marinho et al., 2022; Jang et al., 2022; Martingano et al., 2022; Torres et al., 2022; Tian et al., 2022; Maneuvrier et al., 2022). Measuring stereo acuity would have been interesting to alleviate bias with Visual fatigue estimation (Alhusuny et al., 2020). Although it doesn't support or reject the hypothesis, it allows putting aside the alternative explanation that those variables can explain the following measurements.

Looking at the subjective data, this general hypothesis on only slightly supported. Cognitive load differentiated from Stressful and Stereoscopy induction. In experiment 1, inducing Cognitive load also drove participants to report higher disorientation, while we would expect such reporting for the Visual fatigue inducer condition. Stressful couldn't differentiate from VRISE. The behavioral data showed that induced Cognitive load impacted Stroop performances more negatively than Acute stress and Visual fatigue. But Acute stress is also different from Visual fatigue. Furthermore, part of the subjective and behavioral data did not allow to differentiate Visual fatigue and Acute stress-induced compared to the Control condition. Hence, our stimuli might have been too "weak" to induce a measurable response in participants. But, this also means that subjective data are very limited to characterize subtle and ambiguous comparisons between Cybersickness, Visual fatigue, Cognitive load, and Acute Stress. For physiological data, most features couldn't allow differentiating states.

Although we identified a few, differences have tiny effect sizes. Psychophysiological variations depend on numerous factors, making their interpretation hard (Krohn et al., 2020; Michela et al., 2019). We tried to control and create tightly linked experimental conditions to overcome such issues and for better stimuli validity (Holleman et al., 2020; Vasser & Aru, 2020). We also investigated 251 features inferred from ET, ECG, and EDA to avoid narrowing down possible effects of observations. Despite those precautions, only a handful of the physiological variations are differentiable between Cybersickness, Visual fatigue, Cognitive load, and Acute Stress with our procedures. Consequently, Hgeneral is very partially supported as we can differentiate Cybersickness, Visual fatigue, Cognitive load, and Acute Stress psychophysiological variations but only with a few features from subjective, behavioral, and physiological data.

4.5 Studies' limitations

We tried to apply robust experimental design and statistics (Jones et al., 2003; Sullivan & Feinn, 2012; Hinkelmann, 2015; Dean et al., 2017) to communicate strong results. Therefore, we randomized conditions' order, group assignation, and stimuli triggering Cognitive load and Acute stress. Instructions were standardized. However, the stimuli choices, i.e., a basic task like the Stroop, oriented on cognitive inhibition, might not represent the various ways to induce Cognitive load or Acute stress. Furthermore, those stimuli are rarely to never used to study VRISE. We chose to have reasonably controlled stimuli for physiological data gathering that is reliable and precise (Ayres, 2020; Crosswell & Lockwood, 2020; Saredakis et al., 2020). We also aimed to foster replication possibility (Collaboration, 2015; Muthukrishna & Henrich, 2019; Cockburn et al., 2020). We focused on an in-lab procedure, but VR entertainment, work, or psychological intervention will append in the wild. Hence, more complex variables could influence similar measurements and drive different physiological variations. However, the concept of ecological stimuli is criticized (Michela et al., 2019). Despite using a priori power analysis through G*Power for small to medium effect sizes, we didn't recalculate it a posteriori and used non-parametric tests for statistical analyses following the normality check.

With that, we might have lost part of the statistical reliability in our results.

We tried to induce Cybersickness and Visual fatigue by displaying stereoscopy at the limits of the comfortable zone (Shibata et al., 2011). Maybe the stimuli weren't aggressive enough on the visual system to get participants subjectively reporting visual fatigue (as Stereoscopy did not vary compared to Control). But, since we document physiological variations, especially with ET features more impacted with Stereoscopy than other conditions, we can see here the limits of questionnaires to assess states.

We used between-subject and within-subject designs to allow carryover effects identification within the results (Putt, 2005). Experiment 2 results show that part of Relaxation is getting less efficient with time.

However, a cross-over design (Lim & In, 2021) could be more suitable for Cybersickness, Visual fatigue, Cognitive load, and Acute Stress studies. But it also implies a larger experimental timeframe and extra logistics for participants. To prevent priming or anchoring effects (Furnham & Boo, 2011; Weingarten et al., 2016; Doherty & Doherty, 2018) by asking participants about their subjective Cognitive load, Stress, Cybersickness / Visual fatigue, we only administered questionnaires after the Stroop task. It degraded the amount of data we could use to characterize observed physiological variations when testing differences between procedure steps. We also used a within-subject design to reflect possible individual physiological measurement components better.

We did not measure the scenes' luminosity, although it could have impacted eye tracker data recording, especially for pupil size variations. All steps, except for the Relaxation, were mostly the same, with a grey background to restrict the influence of luminosity differences. Although stimuli have been created to reduce the light influence on eye tracker metrics, we could also have applied light influence reduction during data processing (Eckert et al., 2021; Shi et al., 2020; Eckert et al., 2022). Hence, there is a potential bias here. Furthermore, despite frequent eye tracker calibration (B. T.

Carter & Luke, 2020) before every step of the procedure, too much data was missing during experiment 2 for us to exploit them.

Our study only used the reaction time as behavioral evidence of cognitive control (related to inhibition with the Stroop task). We considered the difference between congruent and incongruent stimuli. However, this represents only an overall aspect of the process and might lack precision (Littman et al., 2019).

We did not consider previous work using electroencephalography (EEG), functional magnetic resonance imaging (fMRI), postural sway and electromyography (EMG), or electrogastrogram (EGG). But, those sensors are relevant and could help to characterize states better (Caserman et al., 2021; Pöhlmann et al., 2022). EEG is used successfully but can imply too many artifacts yet (G. Kim et al., 2018).

4.6 Conclusion and future works

This paper documented an attempt to distinguish Cybersickness, Visual fatigue, Cognitive load, and Acute Stress in VR with two experiments using a Stroop task. The use of physiological markers to assess those states suffers two main shortcomings. First, previous work usually focus on one state at a time, making them missing alternative explanations for observed physiological variations. Second, previous work do not consider confounding between those states. We focused on that complexity in physiological variation interpretation (Sirois & Brisson, 2014; Argyle et al., 2021; Becker et al., 2022; Souchet, Lourdeaux, et al., 2022). But we also analyzed subjective and behavioral data, often used to assess Cybersickness, Visual fatigue, Cognitive load, and Acute Stress. We tested 8 hypotheses to give insights into three research questions. 7 out of those 8 hypotheses were partially supported as all tests on data would not appear statistically significant or with strong correlations.

The first research question was: what are the physiological features characterizing each state (RQ1)? Previous work we reviewed would mainly indicate physiological features or indicators are similar no matter the state, and physiological variations are alike for Pupil diameter, blink frequency, fixations, HR, HRV, and SCR-derivated features. Our results align with previous work as those features differ between the conditions where we induced states compared to the Control. Although, our Stressful had very few differences from the Control condition in our two experiments. In our experiments, despite relaxation steps and Endlines, Saccade ratio, Blink frequency, Blink duration and Pupil size for ET, Heart rate for ECG, Rise time of the mean skin conductance level, the Arc length of the skin conductance level for EDA were still not back equivalent baseline. Hence those physiological features can help target Cybersickness, Visual fatigue, Cognitive load, and Acute Stress in VR. The second research question was: Can we differentiate different states according to psychophysiological responses (RQ2)? Previous work wouldn't focus directly on that except for notable work on Cognitive load and Stress Alsuraykh et al., 2018a Alsuraykh et al., , 2019;; Gioia et al., 2021; Becker et al., 2022). Most previous work testing covariation between states to underline their links, or when trying to discriminate each state, they would focus on subjective and behavioral data. Our results show that it is possible to distinguish Cognitive load and Acute stress from Visual fatigue / Cybersickness, with ET, features varying more with the latest. Although hard to distinguish, Cognitive load differs from Acute stress based on the Heart rate feature from the ECG sensor.

Cognitive load provoked more response with EDA features than Visual fatigue / Cybersickness with the ALSC feature. However, most of those differences have very small effect sizes (this might be due to our stimuli varying only slightly from one experimental condition to another). Furthermore, most of the extracted features from ET, ECG, and EDA showed no differences between Cybersickness, Visual fatigue, Cognitive load, and Acute Stress in VR. Hence, the short answer to this research question is yes, we can differentiate psychophysiological responses between states. But only with a few features, and those differences have low magnitudes. Therefore, measured physiological responses can be very ambiguous to interpret in VR, especially with tasks triggering high Cognitive load and Acute stress such as the Stroop.

The third question was: does using VR to study cognitive load and stress trigger confounding effects in physiological measures due to Cybersickness and Visual fatigue (RQ3)? Previous work evoke this possibility in their discussions as a limitation to data interpretation. Our results show a threshold of about 1 hour where features vary more significantly because of immersion duration than experimental conditions. Furthermore, results in experiment 1 with the ET feature show that pupil size, blinks, and saccades are more impacted by stereoscopy (visual fatigue provoked by accommodation-vergence conflict). Our results also show that questionnaires partly fail to measure differences between states, while behavioral data allow limited differentiation. For instance, Disorientation was estimated higher by subjects while the high cognitive load was induced in experiment 1. Hence, the short answer to this question is yes; using VR to study cognitive load and stress triggers confounding effects in physiological measures due to Cybersickness and Visual fatigue. Furthermore, suppose subjects are asked to estimate side effects, stress, or high cognitive load at rest, during relaxation, and then during/after stimuli administration. In that case, they will likely overestimate subjective states because of anchoring and priming effects.

For future work, we encourage other researchers to replicate our procedure to contribute to standard stimuli-based Cybersickness, Visual fatigue, Cognitive load, and Acute Stress measurements. Precisely, reproducing a within-subject study would be interesting mainly because our ET data were unusable. Our studies took place in France. Hence it would be interesting to investigate if results can variate depending on psycholinguistic factors. Furthermore, our study mainly falls into the biases of including young, highly educated people with little ethnic diversity. Hence testing the procedure with specific populations (older, less educated, less techno-enthusiast, and considering various ethnicities) remains necessary. Machine learning techniques could efficiently deal with states differentiation complexity or associated uncertainty with physiological measures (Dennison et al., 2016; Smets et al., 2018; Weech et al., 2018; Y. Wang et al., 2019; Assila et al., 2020; Islam et al., 2020; Rodrigues et al., 2020; Yang et al., 2021; Souchet, Diallo, et al., 2022; Porcino et al., 2022). But it implies vast data sets (Epps, 2018) with standard stimuli (Krohn et al., 2020; Shields, 2020), which is partly the reason for the present paper. We shared our data so the community could start tackling the issue. We performed one between-subjects and one withinsubjects study to control better possible biases induced by the study design.

One valuable contribution would be to assess the same procedure with a crossover design.

We only have results allowing for partial hypothesis support, showing that Cybersickness, Visual fatigue, Cognitive load, and Acute Stress differentiation are difficult. But, it has direct relevance for several research fields. First, cognitive psychology increasingly using VR should be aware that Cybersickness and Visual fatigue can be an artifact of their physiological measures of Cognitive load and Acute Stress, especially if they aim at using ET features. Second, even acknowledging the influence of those side effects on measures, part of physiological variations can be wrongly associated with only one state. I.e., literature increasingly points to confounding between Cognitive load and Acute stress, but Visual fatigue and Cybersickness can also confound obtained measures. Our results support this with an about 60 minutes immersion "limit." Thirdly, with our stimuli and setup, EDA features allowed the most states differentiation. However, ET was more sensitive to Visual fatigue / Cybersickness compared to Cognitive load and Acute Stress and ECG to Cognitive load compared to Acute Stress. Fourthly, the study design influenced physiological variations as more differences were observed during the withinsubject (experiment 2) than the between-subject study (experiment 1). The results from this article can be considered by peers using VR to study Stress and Cognitive load. They can now estimate how Visual fatigue and Cybersickness could impact psychophysiological variations even with standard stimuli such as the Stroop task. Conversely, peers focusing on assessing, detecting, predicting, and reducing Visual fatigue and Cybersickness can consider those results to explain part of the measured variance in their studies with ET, ECG, and EDA. In summary, Stress, Cognitive load, Visual fatigue, and Cybersickness can confound one another, which implies noticeable limitations in interpreting psychophysiological measurements in VR. Consequently, studies using physiological sensors should be parsimonious with their claims. Studies focusing on Acute stress and Cognitive load should assess VRISE through questionnaires to consider alternative explanations. Nevertheless, we observed with our experiments that questionnaires are very limited, and subjects tend to overestimate VRISE when facing complicated tasks.
