To check Non-Significant P Value Check

What we found

We found 3 non-significant p values that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. Abstract

The Systematizing Confidence in Open Research and Evidence (SCORE) project recently published a large-scale replication project within the social and behavioural sciences 1 . The authors replicated only 151 of 274 (55%) claims, a finding covered by major outlets such as the New York Times 2 and Forbes 3 . Here, I audited SCORE replications of six studies where at least one claim surprisingly failed to replicate. These failures were surprising because the original study produced a p < .01 while the replication yielded a significant effect in the opposite direction.

I show that, of the 12 claims tested across these six replications, five were miscategorised as failed replications because of data analysis and interpretation problems, and six replications were invalid because of poor data quality and an error in the replication's experiment code. I conclude that individual replications within replicability projects may benefit from more thorough peer review, and that a more comprehensive audit is necessary before we can be confident in the project's overall replicability estimate.

The replication crisis is often attributed to underpowered studies and flexible analyses producing false positives and inflated effect-size estimates [4] [5] [6] . This account has shaped proposed measures to improve replicability, such as preregistration and power calculations, as well as the statistical tools used to estimate replicability. For instance, the p-curve method assesses the evidentiary value of a set of findings by testing for skew in the distribution of significant p-values 7 , while the z-curve uses significant p-values to estimate the average power of a set of tests 8 . These methods work because the distribution of significant p-values depends on statistical power: high-powered studies are more likely to produce very small p-values, and true null effects yield uniformly distributed p-values. We can therefore treat a body of work full of very small p-values as evidence of real, replicable effects. This association between p-values and replicability also tells us what failed replications should look like. Original studies with p-values just under .05 should be the least likely to replicate, and their replications should generally produce smaller or null effect size estimates. The

[div-01]

Open Science Collaboration's (OSC) 9 large-scale effort to estimate the replicability of the psychological sciences found exactly this pattern. Only 2 of 11 studies (18%) reporting p > .04 replicated, compared with 20 of 32 (63%) studies reporting p < .001. Given this pattern, it is somewhat surprising when an original study with a small p-value fails to replicate. Especially if the replication produces a significant effect in the opposite direction. Compared to typical replication failures, such results are more likely to reflect meaningful methodological or analytical differences between the original and replication studies. Therefore, it is worth investigating further when two high-powered studies produce incompatible results before simply concluding that the original finding is not replicable.

Large-scale replication efforts do not usually lend themselves to this kind of investigation. In SCORE's replication project, study protocols underwent peer review before data collection, but completed reports were reviewed only by other team members. In other words, the reviewers may have been less familiar with the study's methods and analyses than we would expect from external reviewers invited for their expertise. Additionally, replication reports usually lacked details, such as descriptive statistics and plots, that one would expect in an independently submitted manuscript. Without these details, data anomalies that could explain conflicting results may be more likely to go undetected by both authors and reviewers. In this audit, I illustrate the value of a more thorough review process by identifying methodological and analytical details that help explain some of SCORE's more surprising replication failures. I reviewed replications of six studies where an original claim statistic had p < .01, but the replication produced a significant reverse effect. This revealed five claims that were incorrectly classified as replication failures. For the first claim (Supplemental Materials B1), re-running the replicator's analysis script failed to reproduce their reported numbers. Instead, the effect was significant in the same direction as in the original study. The cause was a bug in the R package the replicators used 10 , which was not fixed until the following year.

Other issues stemmed from the replicators' code. Replications of two studies, each contributing one claim, produced reverse effects because the replicators' analysis deviated from the original study. In one case, the replicators' model included a term that was not in the original study (Supplemental Materials B3); in the other, they omitted a model term that was (Supplemental Materials B6). Correcting these deviations yielded significant effects consistent with the original studies. One original study contributed three claims (Supplemental Materials B2). For two of these claims, the replicator reported the wrong model parameters. The correct parameters supported the original finding. The third claim was subject to replication by two independent replicators. I found that one incorrectly filtered participants, and one omitted a model term. Correcting these did not turn the result into a successful replication, but it shifted the result from a significant reverse effect to a non-significant effect in the same direction as the original.

Finally, reverse correlations across two online replications were traceable to poor data quality. In one case, the replication found a positive relationship between responses on two scales whereas the original found a negative one (Supplemental Materials B4). The original data were also available, so I could compare response distributions across the two studies. Strikingly, responses on the psychopathology scale were positively skewed in the original, but roughly uniformly distributed in the replication. The scales used to test the claim had no reverse-keyed items, but both studies administered two additional scales that did. In the original dataset, responses to forward-and reverse-keyed items were negatively correlated in both scales, as expected for genuine responses. In the replication, however, there was a positive correlation in one scale, and no significant correlation in the other. In other words, the replication seems to have found a spurious positive correlation for the focal claim because participants responded similarly to every item across both scales.

In the second case (Supplemental Materials B5), the original study reported a positive correlation between responses on an alexithymia scale and performance on a memory task. The replication found a negative correlation. Average alexithymia levels were notably higher in the replication, and responses to forward-and reverse-keyed scale items were positively related, indicative of careless responding. Performance on the memory task was similarly poor, with 30% of participants performing at or below chance. The negative correlation between these two measures therefore appears to be an artefact of careless responses, which simultaneously inflated alexithymia scores and reduced memory task accuracy. This replication also contributed four more failed tests (albeit not as surprising) to SCORE's dataset. Another major error meant that the replication would have been invalid even without data quality issues; an inspection of the online materials revealed that the experiment played the wrong music prime in one condition, meaning one of its focal manipulations was not implemented correctly.

Conclusions

What can we conclude from such a small audit of replication failures? Because I selected claims based on their p-values, the percentage of false negatives observed here is almost certainly much higher than in SCORE's full dataset. But that does not mean there are not a meaningful number of problematic replications still to be identified. Even among the 15 replication failures I identified as surprising, I only briefly audited eight claims. Moreover, I did not examine other categories of surprising findings. Cases where the original effect was highly significant and produced a near-zero or reversed (but not significant) effect also warrant further investigation.

Finally, because I only examined replication failures, this audit could not identify failed replications misclassified as successes. In sum, much more work is needed before we can judge whether, and to what extent, SCORE's overall replicability estimate requires revision. What we can conclude is that SCORE's quality control efforts were insufficient to prevent a non-trivial number of false negatives (and perhaps even false positives) in their dataset. This audit was post hoc and driven by priors about the replicability of original findings with small p-values. As research shows, prior beliefs can bias how researchers analyse and interpret data 11 . But in some cases, such priors can help detect a study's shortcomings. A famous example in psychology is Bem's 12 experiments on extrasensory perception. Priors about the laws of nature drove scrutiny of the project, which helped reveal that common statistical practices in the psychological sciences were conducive to false positives 4, 13 . Considering the plausibility of results and data distributions could have strengthened SCORE's quality control process. For example, one of the claims audited here was a quite plausible finding that Spanish English language learners had lower reading achievement than native English speakers at the beginning of the study 14 . A replication study finding the opposite would ideally prompt, at the very least, a closer look at the methods and analyses.

It is critical to distinguish clearly between auditing failed replications and post-hoc rationalisation 15 . Although I selected replications to examine based on their results, the problems I identified would require correction regardless of their conclusions. The impact of any issues discovered in a review must be demonstrated. For instance, it is not enough to argue that a replication is invalid because of a single unusual descriptive statistic, such as a high average on a particular measure, without showing how this would explain the observed results. Finally, audits should avoid post-hoc theorising based on differences between original and replication studies 15.

Many effects in the social and behavioural sciences may be context-or demographic-sensitive 16 , and a replication may indeed fail because of a previously undiscovered moderator, but such moderation should be demonstrated in new data before being proposed as an explanation.

Whether the kinds of issues identified here are more likely in large-scale replication projects than in individually submitted papers cannot be answered by an audit. Nevertheless, it is easy to imagine how conventional peer review of a full manuscript with descriptive statistics and plots could have identified and prevented several of the problems seen here. For example, a reviewer familiar with psychopathology symptoms would likely suspect that something is amiss upon seeing a uniform distribution of scores on a psychopathology scale.

It is possible that SCORE's overall replicability estimate is nevertheless accurate because the issues identified here occurred very rarely, or because they produced false positives and false negatives at similar rates. But the project's results also speak to the replicability of individual claims. For this reason, a comprehensive, systematic audit may be warranted, perhaps starting with the most surprising findings. Fortunately, SCORE's outstanding transparency and thorough documentation make such an undertaking possible. The audit could also collect data on how and when errors occurred to help design preventive measures for future projects. For example, errors may be more likely when the original authors' analysis scripts are unavailable or when replicators have less familiarity with the original study's methods.

Large-scale replicability projects remain essential to documenting and improving the credibility of studies in the social and behavioural sciences. Their impact, however, makes ensuring the reliability of their own findings all the more critical. Implementing expert peer review of more comprehensive reports and applying greater scrutiny to implausible or surprising results would be valuable initial steps. Without ensuring the integrity of individual replication studies, projects like SCORE risk conflating estimates of replicability with estimates of social and behavioural scientists' ability to conduct replications.

The SCORE dataset contained 15 claims where the original study produced a p-value <.01 but the replication found a significant effect in a different pattern. I selected eight of these claims spanning six articles to audit for potential methodological deviations or analytical errors that could explain such discrepancies. I hand-picked these based on how straightforward the audit would be given the topic, analyses used, and my experience with both. B3. Teney (2016)

Teney 22 examined citizens' framing of the EU during an economic crisis. The general finding was that poor economic performance is associated with more negative framing of the EU.

The SCORE project attempted to replicate Teney's claim that higher national unemployment rates are related to less cosmopolitan framing (B = -0.0034, p = .001), but found the opposite (B = 0.002, p = .046). The replicators made two major deviations from Teney's study. First, the original paper's reported model did not include quadratic predictors, whereas the replicators did.

Teney did fit models with quadratic terms but dropped them when they were not significant. This may be unclear from the original paper's wording, which states that "only the significant effects of the squared terms are shown (emphasis mine)", but the original paper's associated figure confirms this, showing a linear relationship 5.

Second, the replicators computed the dependent variable differently. The original study used the number of cosmopolitan framing items survey respondents ticked as a proportion of all relevant framing items ticked. The preregistration defined the dependent variable correctly, but the code implemented it incorrectly. The replication took the number of cosmopolitan items ticked as a proportion of all five cosmopolitan items. After correcting these two issues, the unemployment rate coefficient changed so that it predicted cosmopolitan framing negatively, as in the original study (B = -0.002, p < .001).

I inspected SCORE's replication of Vermeulen et al. 28 because it yielded one surprising reversed effect, but the original contributed four additional claims that failed to replicate. The reproduction yielded different values (but the same pattern) because their analysis differed slightly from Roberts et al.'s. I discovered this when I asked Claude Opus 5.5 to convert the reproducer's MPlus code to R. After adapting the code to align more closely with the original study's analytical decisions, I ensured the converted R code still reproduced Roberts et al.'s pattern on ECLS-K 1998 data before running it on the 2011 dataset.

The only major difference in the reproduced 1998 results is that the intercepts were all around five points higher. This was likely because the final dataset recalibrated the scores analysed here, whereas Roberts et al. used an earlier version21 . The pre-calibration dataset is unavailable so this cannot be confirmed, but all group comparisons were in the original direction and significant. I documented all code changes in the GitHub repository.
