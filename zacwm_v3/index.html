Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

To check Non-Significant P Value Check

What we found

We found 1 non-significant p value that should be checked for appropriate interpretation.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

Metacheck does not yet analyze automatically whether sentences which include non-significant p-values are correct, but we recommend manually checking the sentences below for possible misinterpreted non-significant p values.

ps ≥ .18 The remaining items showed no evidence of statistically significant misfit (ps ≥ .18) and likewise exhibited small RMSEA values.

How Ethics Approval Check works

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

Animal research committee names - Institutional Animal Care and Use Committee / IACUC (US standard) - Any sentence containing animal(s) and committee (or board/panel) within ~5 words of each other — catches Experimental Animal Care and Use Committee, Animal Ethics Committee, Animal Welfare Board, Animal Welfare Ethical Review Body, etc. - UK: Animal Welfare Ethical Review Body / AWERB - Dutch: Dierexperimentencommissie / DEC (see DEC constraint above); Instantie voor Dierenwelzijn / IvD - German: Tierversuchskommission / TvK (advisory committee under §15 Tierschutzgesetz) - French: Comité d'éthique en expérimentation animale / CEEA; Comité d'éthique animale - Spanish: Comité de ética en experimentación animal / CEEA

How Power Analysis Check works

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. With the use of an LLM, it checks if the power analysis is reported with all required information.

The regular expressions can miss power analyses, or fail to classify them correctly. The type of power analysis is often difficult to classify, which can easily be solved by explicitly specifying the type of power analysis as ‘a-priori’, ‘sensitivity’, or ‘post-hoc’. Note that ‘post-hoc’ or ‘observed’ power is rarely useful. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

1. Introduction and Theoretical Background

People-pleasing is generally understood as a tendency to prioritize others' needs, wishes, and approval over one's own preferences and interests. Although such behaviors may facilitate interpersonal harmony, excessive people-pleasing has been associated with difficulties in assertiveness, heightened approval seeking, interpersonal dependency, and psychological distress. Recent theoretical work has further suggested that people-pleasing represents a distinct interpersonal disposition characterized by a strong motivation to avoid interpersonal conflict and maintain social acceptance, even at personal cost. Consequently, valid assessment of individual differences in people-pleasing is important for both research and applied contexts (Blötner, 2026; Kuang et al., 2025).

To facilitate empirical investigation of this construct, the People Pleasing Scale was recently developed and validated. Initial validation studies provided evidence for the threefactor structure (Responsibility, Others' Expectations, Neglect of Own Needs), sufficiently high estimates of reliability, and construct validity using classical test theory (CTT) approaches. These findings established the People Pleasing Scale as a psychometrically promising instrument for assessing people-pleasing tendencies in adults.

Although the original validation of the People Pleasing Scale yielded promising evidence regarding reliability and construct validity, several important psychometric questions remain unanswered. In contrast to CTT, item response theory (IRT) enables the evaluation of item discrimination, category thresholds, conditional reliability, and local dependence at the item level. Therein, item discrimination parameters indicate how effectively an item differentiates between respondents with similar trait levels, whereas threshold parameters identify the levels of the latent trait required to endorse increasingly higher response categories. In addition, IRT affords the identification of specific regions of the trait continuum at which a measure provides the greatest precision. These analyses bear implications for score interpretation and refinement of the measure as they can identify particularly informative items and highlight potential redundancies, among others (Embretson & Reise, 2000).

Importantly, an IRT investigation is not simply a replication of previous validation efforts using different statistical techniques. Rather, IRT provides information that is unavailable within conventional CTT frameworks. For the People Pleasing Scale, such analyses can clarify whether the scale adequately captures the full spectrum of peoplepleasing tendencies, whether some items contribute disproportionately to measurement precision, and whether all response options contribute meaningful information or whether certain categories are redundant or underutilized. These issues are directly relevant to the interpretation and application of test scores and therefore constitute an important extension of the original validation research (Embretson & Reise, 2000).

Conceptually, people-pleasing may be understood as a broad interpersonal disposition or as a constellation of interrelated but distinguishable facets. The People Pleasing Scale was developed to capture three theoretically derived dimensions, namely Responsibility, Others' Expectations, and Neglect of Own Needs (Blötner, 2026). Nevertheless, these facets are expected to share substantial common variance because they reflect different manifestations of a broader tendency to prioritize others' needs and interpersonal harmony. Consequently, both unidimensional and multidimensional representations warrant empirical evaluation.

Accordingly, we conducted an IRT-based evaluation of the People Pleasing Scale.

Using a Graded Response Modeling approach (Samejima, 1997), we examined the discrimination and threshold parameters of the items, evaluated model fit and responsecategory functioning, and investigated the measurement precision with which the measure assesses people-pleasing across the latent trait continuum. In doing so, the present study aims to provide psychometric information that complements previous validation findings (Blötner, 2026) and advances the understanding of the People Pleasing Scale.

2. Methods

>Methods

2.1 Sample

The present study partially re-analyzed data from the original scale-development project (Blötner, 2026). The contribution therefore lies not in providing an independent validation but in generating information unavailable within the CTT framework, such as measurement precision across the latent continuum, category functioning, and potential itemlevel issues. More specifically, our present research sample is composed of both commercial panel data, specifically the two German samples from Blötner's (2026) studies (Nafter data exclusions = 1,894), as well as an additional data collection conducted at German universities, Ntotal = 2,538. As such, our final sample size exceeds the recommended minimum sample size requirements for IRT analyses (n > 500; Jiang et al., 2016). Our extended data collection involved only the ten-item People Pleasing Scale and questions about demographics. Across samples, the corresponding items were mandatory to respond to, such that complete data existed for all questions.

From the total sample, 1,918 (76%) participants self-identified as female, 580 (23%) as male, and 40 (1%) self-identified as nonbinary or did not respond. The mean age was 32.9 years (SD = 12.3, range from 18 to 81). Most participants (n = 2,328; 92%) reported a high school-equivalent or university degree as the highest obtained qualification. Moreover, most indicated currently being enrolled as a university student (n = 2,203; 87%). The comparatively high average age despite the large proportion of university students reflects substantial participation from mature and part-time students as well as the partial inclusion of participants from a commercial panel.

2.2 Measures

The People Pleasing Scale (Blötner, 2026) assesses Responsibility, Neglect of Own Needs, and Others' Expectations with three, four, and three items, respectively. Responses were collected on a five-point scale,1 = Does not apply at all,2 = Does not apply,3 = Neutral,4 = Applies,5 = Completely applies. Blötner (2026) provided initial evidence in favor of the three-factor structure, criterion validity (behavioral economic games), construct validity (concerning benevolent, aversive, and emotion-related personality features), and residual measurement invariance across genders (suggesting that manifest test scores of the People Pleasing Scale can be meaningfully compared between men and women).

2.3 Analytical Strategy

In a set of preliminary analyses, we computed response frequencies, means, standard deviations, and skewness parameters for all items of the People Pleasing Scale. Item response distributions were inspected to identify potential floor or ceiling effects and to evaluate utilization of the five response categories.

All subsequent analyses were conducted in R using the package mirt (Version 1.46.1;

Chalmers, 2012) with expectation-maximization estimation. We employed the Graded Response Model (Samejima, 1997), which is appropriate for ordered polytomous item responses and estimates both item discrimination and category threshold parameters.

The latent structure of the People Pleasing Scale was evaluated using confirmatory item factor analytic models estimated within the mirt framework. Besides the three-factor structure reported in the original scale-development study, we also fit a single-factor model.

Model fit was evaluated using the fit statistic M2, Root Mean Square Error of Approximation (RMSEA), and Comparative Fit Index (CFI). These indices were used jointly to determine the adequacy of the proposed latent structure. Moreover, we computed Sample-Size Adjusted Bayesian Information Criteria (SABIC) for both model alternatives, with lower absolute values indicating better fit.

To test the assumption of local independence within the preferred model alternative, we computed Yen's Q3 statistics, that is, item residuals after fitting the model. Because no universally accepted cutoff exists, we considered both the traditional criterion (|Q3| > .20; Chen & Thissen, 1997) and adjusted criteria that account for characteristics of the instrument and sample (Christensen et al., 2017). More specifically, Christensen et al. (2017) argued that fixed cutoffs are often inappropriate and recommended evaluating whether the particular Q3s differ by more than .20 from the average Q3. Reporting multiple criteria affords a more comprehensive assessment of the extent to which local independence may have been violated.

Item-level model fit was evaluated using the S-χ 2 statistic (Kang & Chen, 2008; Orlando & Thissen, 2000) as well as RMSEA derived from the same model. Given the large sample size, S-χ 2 values were interpreted cautiously because even trivial deviations from model expectations may achieve significance. Therefore, conclusions regarding item fit were based primarily on RMSEA values, with S-χ 2 statistics reported for completeness and comparability with previous research.

For each item, discrimination (a) and category threshold (b) parameters were estimated. Discrimination parameters indicate the degree to which an item differentiates between individuals with different levels of the latent trait, whereas threshold parameters indicate the latent trait levels at which adjacent response categories are equally probable (Embretson & Reise, 2000). Following Baker (2001), we deemed discrimination parameters to be low, moderate, high, and very high when they exceed 0.35, 0.65, 1.35, and 1.70, respectively. Furthermore, we applied the following classifications of θ: Well below average (θ < -2), below average (-2 < θ < -1), average (-1 < θ < 1), above average (1 < θ < 2), and well above average (θ > 2).

The functioning of the five response categories was evaluated through inspection of category response curves derived from the graded response models fitted for each subscale because the curves from the unidimensional model are easier to interpret than those from the multidimensional model. Particular attention was paid to the ordering of threshold parameters and to whether each response category displayed a distinct region of peak probability.

Reliability was evaluated using conditional standard errors of measurement. Item information functions were additionally inspected to determine the contribution of individual items to measurement precision. These analyses were used to identify which items contributed most strongly to the reliable measurement of people-pleasing tendencies.

3.2 Model Fit, Local Independence, and Item Misfit

A unidimensional model fitted to the 10-item People Pleasing Scale exhibited good fit, M2(5) = 75.45, p < .001, CFI = .97, RMSEA = .08, SABIC = 60,178.18. The three-factor model representing the dimensions Others' Expectations, Neglect of Own Needs, and Responsibility proposed by Blötner (2026), however, demonstrated even better fit to the data, M2(2) = 19.79, p < .001, CFI = .99, RMSEA = .06, SABIC = 59,052.63. Correlations among the factors ranged from .74 to .78 (see our supplement for details and for additional fit indices). These correlations indicate substantial overlap while remaining sufficiently below unity and thus support the empirical distinguishability between the three facets. Therefore, our subsequent analyses rested on the three-factor, multidimensional graded response model.

Although 10 item pairs exceeded the conventional threshold of |Q3| > .20 (Chen & Thissen, 1997), only four surpassed the more conservative adjusted criterion proposed in the literature (Christensen et al., 2017). More specifically, the average residual correlation was Q3, mean = -.10. The largest residual associations were observed among items within the same subscales, suggesting that the detected dependence primarily reflects content overlap or shared wording rather than a substantial violation of the underlying latent structure (Chen & Thissen, 1997; Noventa et al., 2026). Two of these involved the second Responsibility item in relation to the remaining Responsibility items, whereas one involved the residual correlation between the second and third Others' Expectations items. Importantly, the observed residual correlations were modest in magnitude and did not indicate pervasive local dependence across the scale. Thus, the magnitude of the present effects appears insufficient to materially affect substantive conclusions (Chen & Thissen, 1997; Noventa et al., 2026).

4. Discussion

This study investigated the People Pleasing Scale (Blötner, 2026) from an item response-theoretical perspective. We did so to expand on the psychometric information about the measure provided by the seminal work that built on evaluations as per the Classical Test Theory. Most prominently, the original, CTT-based validation study suggested all items functioned similarly, which can be tested by means of applying IRT. Moreover, the original study treated the scale as uniformly reliable, whereas IRT shows where on the latent trait continuum reliability varies. Last, unlike IRT, the original validation could not determine which trait levels were required to display specific levels of item endorsement. Accordingly, we tested whether the People Pleasing Scale accurately discriminates between individuals with similar trait levels (a), which trait levels are required to obtain low, moderate, or high scores on the scale (b1 to b4), and at which regions of the latent trait continua the items and subscale scores provide ample information (i.e., item information and reliability, respectively). The findings largely support the utility of the People Pleasing Scale, even though certain aspects stand out.

4.1 Dimensionality of the People Pleasing Scale

Consistent with previous CTT-based research on the People Pleasing Scale (Blötner, 2026), the three-factor IRT model outperformed a unidimensional alternative. At the same time, the strong factor correlations suggest that the dimensions share considerable common variance and may reasonably be conceptualized as facets of a broader people-pleasing disposition. Thus, Responsibility, Others' Expectations, and Neglect of Own Needs constitute distinguishable but closely related manifestations of an overarching construct. This interpretation is further supported by previous evidence indicating differential relationships within the nomological network with cognitive empathy and extraversion, for instance, despite substantial overlap among the dimensions (Blötner, 2026).

4.2 Item-Level Issues of the People Pleasing Scale

While the results provided some evidence of local dependence among items, the observed residual associations were weak and limited in scope. Local dependence often arises from content overlap or common stimulus features (e.g., when items stem from the same subscale). Such minor violations are not unusual in practice and do not necessarily compromise model validity. As the magnitude of local dependence was generally small, the assumption of local independence can be regarded as sufficiently met for the present analyses.

Nevertheless, the clustering of elevated residuals among conceptually similar items suggests some degree of item redundancy and may cause slight inflation of discrimination estimates for affected items (Chen & Thissen, 1997; Noventa et al., 2026).

Although several items displayed statistically significant S-χ 2 values, the magnitude of model misfit was negligible as evidenced by consistently small RMSEA values. Given the large sample size, these findings likely reflect minor departures from model expectations rather than meaningful deficiencies in item functioning.

Besides ostensible local dependence in some cases, some items performed poorly in the remaining multidimensional IRT analyses. More specifically, the third items tapping into

Others' Expectations and Neglect of Own Needs revealed overlapping response categories in the category probability plots, and the third items tapping into Others' Expectations and

Responsibility provided comparatively little measurement information across the continuum.

Instead of limiting the utility of the measure at large, however, these findings suggest promising candidates for future item reduction studies. Decisions regarding item removal should, however, additionally consider content validity and require independent validation.

The findings also provide an empirical answer to the question posed in the title. It can be answered by means of the upper threshold parameters b4, which were comparatively low in magnitude (b4, max = 1.63), suggesting that endorsement of the highest response categories does not require extremely high levels of the latent trait. Thus, endorsement of the highest response categories can occur already at moderately above-average levels of the latent trait.

4.3 Limitations and Future Directions

Despite the size of the utilized sample and the empirical contribution of this study to the assessment of people-pleasing, the present research was not without limitations, especially with respect to the sample. More specifically, it entailed comparatively young, highly educated, and mostly female university students, primarily enrolled in an undergraduate psychology course. Thus, the sample may have been somewhat preselected because females and individuals studying social sciences usually report higher scores on benevolent personality traits than males and those studying law, business, and economics (Barbee et al., 1993; Vedel, 2016).

Although analyses of differential item functioning of these features may provide valuable information regarding group-specific differences, they were not essential for addressing the central aims of the present study, namely evaluating item-level functioning and measurement precision of the scale as a whole. Questions concerning differential item functioning across demographic groups represent an important but conceptually separate line of inquiry that should be addressed in dedicated follow-up studies.

Another limitation of the present study is that recruitment took place exclusively in Germany, a relatively individualistic country in which personal goals are often prioritized over those of salient ingroups (Hofstede et al., 2010). Consequently, the extent to which the present findings generalize to more collectivistic cultural contexts remains unclear. One might expect individuals in collectivistic cultures to exhibit stronger people-pleasing tendencies, as greater value is placed on social harmony, interpersonal obligations, and attending to the needs of others (Hofstede et al., 2010). In light of these limitations, replications of the present findings in culturally more diverse samples, along with examinations of differential item functioning across cultural groups, are needed to evaluate the generalizability of our findings.

4.4 Conclusion

The findings support the People Pleasing Scale as a psychometrically sound instrument, but refinements are necessary. Beyond confirming favorable discrimination and reliability, the present study demonstrates that the most extreme response categories can be endorsed at only moderately elevated trait levels and identifies specific targets for future revisions. These results illustrate the value of item response-theoretical approaches for advancing the measurement of people-pleasing beyond the perspective of classical test theory.
