Reporting p values imprecisely (e.g., p < .05) reduces transparency, reproducibility, and re-use (e.g., in p value meta-analyses). Best practice is to report exact p-values with three decimal places (e.g., p = .032) unless p values are smaller than 0.001, in which case you can use p < .001.

Show details

Meta-scientific research has shown nonsignificant p values are commonly misinterpreted. It is incorrect to infer that there is ‘no effect’, ‘no difference’, or that groups are ‘the same’ after p > 0.05.

It is possible that there is a true non-zero effect, but that the study did not detect it. Make sure your inference acknowledges that it is possible that there is a non-zero effect. It is correct to include the effect is ‘not significantly’ different, although this just restates that p > 0.05.

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Code Check works

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

The Code Check module checks R (also R Markdown and Quarto), Python (also Jupyter notebooks), SAS, SPSS, Stata, Mplus, and MATLAB files, using regular expressions to check the code; JASP files are listed but not read. The language of a Quarto document or a notebook is read from the file itself (its engine or kernel), not from its extension. The regular expression search will detect the number of comments, the lines at which libraries/imports are loaded, attempts to detect absolute paths to files, setwd() and install.packages() calls, and lists files that are loaded, and checks if these files are in the repository; R code is also parsed. The module will return suggestions to improve the code if there are no comments, if libraries/imports are loaded in lines further than 4 lines apart, if files that are loaded are not in the repository, if absolute file paths, setwd() or install.packages() are found, and if R code cannot be parsed.

The regular expressions can miss information in code files, or falsely detect parts of the code as a fixed file path. Libraries/imports might be loaded in one block, even if there are more than 3 intermittent lines. The module was tried out internally on papers published in Psychological Science, but has not been formally validated. There might be valid reasons why some loaded files can’t be shared, but the module can’t evaluate these reasons, and always gives a warning.

The module also checks whether the repository pins the R/package versions the analysis actually depended on: an renv.lock file (parsed for the R version and every locked package + its version/source), a sessionInfo()/sessioninfo::session_info() text dump (matched by filename — sessionInfo.txt/session_info.txt and similar, or embedded in a README), or a groundhog::groundhog.library()/checkpoint::checkpoint() date-pin call in the code (a bare library(groundhog)/library(checkpoint) does not count — the pinning call itself must be present). When none of these is found, the report flags it as a reproducibility gap: package versions may drift between when the analysis was run and any later reproduction attempt.

If you want to extend the package to perform additional checks on code files, or make the checks work on other types of code files, reach out to the Metacheck development team.

Checking code requires downloading its file contents. For a paper whose repository is on Dryad, this never succeeds unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (listing the repository’s files does not need one). Without a key, every Dryad-hosted code file is listed but unchecked, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures recorded in the manifest.

How Data Check works

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

The Data Check module consumes the file list produced by repo_check (or any files added via local_path). Each file is classified with rule-based heuristics layered over metacheck’s file_category() and file_types: file names matching README / codebook patterns win first, then an extension crosswalk, then format-locked extension overrides. For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). Concepts are detected by name+value rules (the demographic concepts via data_check_demographic()); when llm_use(TRUE) the model fills concepts and measurement levels the rules left blank. Qualtrics survey exports are recognised (data_check_is_qualtrics()): their extra header rows are stripped so columns type correctly, and the reserved response-metadata columns (StartDate, Duration, Finished, …) are tagged.

The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). Without an LLM the study group is left NA (unknown).

Column extraction requires files to be readable from disk. Files fetched by repo_check from OSF/GitHub/etc. without a local copy (file_location is NA) are classified but not column-extracted; pass local_path to point at a downloaded copy of the repository.

For a paper whose repository is on Dryad, this means column extraction never happens unless a Dryad API key is set: Dryad requires one to download file bytes, even from a fully public dataset (dataset listing and metadata do not need one). Without a key, every Dryad file stays classified but un-downloaded, column_n is 0, and a warning naming Dryad and ?dryad_pat/?dryad_auth is included among the download failures. A one-time session message is also shown (see repo_check) the first time a Dryad dataset is encountered with no key set.

Every downloaded text file the authors wrote (code, settings, survey definitions such as Qualtrics .qsf files, documentation, outputs) is searched for keys: API keys, access tokens and private keys, which let anyone who downloads the file use a paid service at the authors’ cost. Of a tabular data file only the column names and first 3 rows of the table as read are searched: its values come from participants, but a key the authors set for a whole survey (as embedded data in a Qualtrics survey flow) is exported in every response. The search uses the rules of the secret scanner betterleaks (https://github.com/betterleaks/betterleaks, MIT licence) of high and medium confidence. A key found turns the traffic light red; the report and the keys table give its file, line and type, and only its beginning. Other files over 25 MB and binary files are not searched. A key is never tested with its provider. Every module’s result has any whole key replaced by “keyremoved” (see module_run()).

How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Background: Within predictive coding accounts of autism spectrum disorder (ASD), two competing explanations locate perceptual atypicalities within inference: weak prior formation versus altered weighting of prediction errors. We propose the atypical iterative prior updating (AIPU) account, which shifts the locus from inference to what happens afterwards: sensory evidence is overweighted during iterative belief updating over time. The accounts predict distinct temporal signatures of attentional divergence.

Methods: To distinguish among the accounts, we presented autistic and typically developing adults with a distractor suppression paradigm using a 100%-valid spatial cue and varying distractor prevalence, while eye movements tracked the temporal dynamics of attentional selection.

Results: Both groups showed equivalent first-fixation capture, ruling out prior-formation differences.

Distractor prevalence modulated interference differently across groups. Autistic participants produced larger reaction time interference, more fixations, and more target refixations, a pattern emerging after initial selection. These findings locate ASD-related differences specifically in iterative updating across time, not in perceptual inference.

Conclusions: The mechanism points to sustained attentional engagement: rather than terminating sensory sampling once expectations are confirmed, autistic individuals continue accumulating evidence even under perfect predictability. The world might feel "too much" not because perceptual inference is altered, but because updating continues beyond resolution.

Introduction

Visual search in everyday life requires not only finding what is relevant but continuously suppressing what is salient yet irrelevant. Many autistic individuals describe environments that feel noisy and difficult to filter(1-4), whereas experimental studies report typical or even superior performance on certain perceptual tasks (5) (6) (7) (8). This discrepancy fuels a debate about attentional control in autism spectrum disorder (ASD): Do salient events capture attention more strongly in ASD, or do differences emerge after attention is engaged? Two frameworks address this discrepancy. Classic attentional accounts emphasize competition between stimulus-driven salience (9) (10) (11) (12) and goal-driven control (13) (14) (15) (16) (17) (18) (19). In additional-singleton paradigms (20), a color singleton reliably slows responses to a shape-defined target-"distractor interference"-unless observers can form expectations that help them proactively suppress the distractor (21) (22) (23). Predictive coding accounts frame perception as inference under uncertainty, combining prior expectations with sensory evidence weighted by their precision (24) (25) (26). Within this framework, differences in ASD reflect atypical estimation or use of precision: overweighting immediate sensory input while underweighting priors during perceptual inference (27), or atypical weighting of prediction errors (24, 26), particularly for surprising events (28). When sensory input violates expectations, autistic individuals may treat the mismatch as highly informative evidence demanding high weight rather than noise to discount.

Recent work points to a different locus: Shi et al. (29) showed that autistic individuals integrate prior knowledge typically for immediate perceptual estimates, contradicting the weak-prior account (27). We term this perspective atypical iterative prior updating (AIPU). Unlike precision-regulation accounts, AIPU specifies that sensory evidence is overweighted not during perceptual inference (i.e. prior + likelihood → posterior), but during the updating of priors over time (i.e. posteriorₜ → priorₜ₊₁). Evidence from perceptual estimation (28, 29) and learning paradigms (30) supports the AIPU account.

Whether AIPU extends to attentional control remains unclear. Some studies point to increased distraction by salient but irrelevant stimuli in ASD, consistent with stronger bottom-up capture or weaker top-down suppression (31, 32). Other studies find intact or even advantageous performance, particularly when regularities allow the construction of reliable priors (28). Allenmark et al. (28) provided critical evidence showing that both ASD and typically developing (TD) groups acquired spatial priors equally, deploying them to guide where to look (the pre-selective stage) with comparable effectiveness. Crucially, differences emerged at the post-selective stage: when a target appeared at the location previously occupied by a rare-region distractor, the ASD group showed a coincidence effect, reflected in prolonged processing and re-checking, five times larger than that shown by the TD group. These findings localize the core difference in ASD not at initial attentional capture, but in what happens after a salient event is encountered: the speed of disengagement from irrelevant information and the translation of perceptual evidence into decisions.

Both AIPU (29) and precision-regulation accounts (24, 26, 28) agree on a common principle: autistic individuals process prediction errors differently, not because they fail to form priors, but because they weigh unexpected sensory evidence more heavily. The accounts diverge on when: precision-regulation places the overweighting within perceptual inference; AIPU specifies it in the iterative updating of beliefs across time. This divergence generates testable predictions for attentional control. First, Allenmark et al. (28) showed intact acquisition of statistical regularities but heightened sensitivity to surprising deviations from them.

Does this dissociation between "where to look" and "what is there" depend on learning spatial priors from statistical regularities, or does it persist even when priors are provided explicitly, trial-by-trial, via perfectly valid spatial cues? If the difference lies in a weak priority itself or deploying priors, perfect cues should substantially reduce or eliminate group differences. In contrast, if it reflects more dynamic, sensory-driven belief updating, as Shi et al. (29) demonstrated, then even a 100%-valid cue may not fully shield against distractor interference. Second, if the core difference lies in iterative updating rather than prior itself, it should surface not only in manual response times but also in the temporal unfolding of attention. Autistic individuals should exhibit more total fixations (deeper search) and more frequent returns to the target to confirm identity before committing to a response. Such temporal signatures would directly reflect sustained sensory engagement that prolongs processing, present even when distractors are frequent and thus less surprising.

The present study tests these alternatives by pairing a 100%-valid spatial cue, signaling exactly where a distractor will appear, with session-wise manipulation of distractor prevalence (low vs. high), which varies how often distractors occur and thus how expected they are. Because prevalence determines the balance between prior expectations and sensory evidence, group differences in how prevalence modulates distractor interference directly index perceptual inference. In TD individuals, explicit spatial cues allow proactive suppression, reducing oculomotor capture (33). Three predictions follow. If the core difference in ASD reflects weak spatial prior or deployment, both groups should benefit from the 100%-valid cue, but the ASD group should still show more initial oculomotor capture by distractors. General precision-regulation accounts predict that group differences should emerge in perceptual inference, reflecting differences in the adaptive, context-dependent weighting of prediction errors. The AIPU account predicts neither differences in initial capture nor in prevalence modulation, but prolonged post-selective processing: more total fixations across the trial (deeper search), and more returns to the target location (sustained engagement with sensory evidence). Eye-movement recording pinpoints the temporal stage at which these alternatives diverge.

Methods and Materials

The study was approved by the Ethics Committee at the Faculty of Medicine at LMU Munich (reference number: 23-0268) and was conducted in accordance with the Declaration of Helsinki (World Medical Association, 2013). All participants submitted a written declaration of consent prior to experiment commencement and received monetary compensation for their participation in the complete study.

Participants

All autistic participants had a confirmed diagnosis of either F84.5, F84.0, or F84.1 according to ICD-10(34), without comorbid neurological conditions. They were recruited from the autism outpatient clinic database at the Department of Psychiatry and Psychotherapy, LMU Munich, and through local autism network contacts. TD participants reported no neurological or psychiatric conditions and confirmed no use of psychotropic medication.

Power analysis using PANGEA v0.2(35) determined our target sample size based on the effect size (d = 0.33) reported in Allenmark et al. (28). To achieve 90% power with an alpha level of 0.05, a sample size of 24 participants per group would be required to detect the critical interaction between group and distractor prevalence. We recruited a total of 71 individuals, comprising 32 autistic participants and 39 TD participants. Data from eight TD participants was excluded either due to incomplete eye-tracking data or elevated scores on the Ritvo Autism Diagnostic Scale -Revised (RADS-R)(36) indicating autism-like traits. Data from four autistic participants was also omitted due to incomplete or poor-quality eye-tracking data.

The final analyzed sample comprised 28 autistic adults (age range: 20-44 years, M = 29.8, SD = 7.1; 16 males, 12 females) and 31 TD adults (age range: 19-41 years, M = 28.4, SD = 5.6; 14 males, 17 females).

All participants had normal or corrected-to-normal vision, as assessed with the Landolt ring eye vision test (37) and the Ishihara test for color blindness (38). The two groups were similar in terms of age, vision and color blindness scores, IQ scores as measured by the Culture Fair Test (CFT-20-R) (39), as well as concentration and speed (d2 test of attention)(40) (Table 1). However, the groups differed significantly on several clinical measures: autistic participants showed elevated scores on the Beck Depression Inventory (BDI-II)(41), the short form of the RADS-R(36), intolerance of uncertainty (IU) (42), and state-trait anxiety (STAI) (43). Since this work forms part of a larger study, measures of IU and STAI state were recorded here, but will be primarily reported in a separate paper to address a different research question. We did, however, use the scores from BDI, IU, and STAI trait measures for additional correlation analyses to reveal any individual differences in distractor interference (see Supplementary Information).

Apparatus and Stimuli

Testing occurred in a well-lit experimental cabin featuring sealed doors to minimize auditory interference. Participants sat 57 cm away from a Dell UltraSharp U2412M LCD Monitor

Design and procedure

We employed a statistical learning paradigm to examine distractor suppression under two distractor prevalence conditions. Participants had to identify the orientation of a line segment within a diamond target presented among five non-diamond distractors. A singleton color distractor (either orange among cyan items or cyan among orange items) appeared on certain trials; its color was randomized across trials. The experimental manipulation centered on distractor prevalence, implemented across two counterbalanced sessions. One session featured low distractor prevalence (50% singleton presence), while the other featured high distractor prevalence (90% singleton presence). Session order was counterbalanced across participants both between and within groups to control for potential order effects. Cue-distractor validity remained at 100% throughout all conditions, with the line cue reliably pointing to the singleton distractor location when present and to a random location when absent.

Each session comprised 10 blocks of 20 trials each, yielding 400 trials per participant across both sessions. This structure provided sufficient statistical power for detecting prevalence-dependent learning effects while maintaining manageable block durations for sustained attention. Before each session, participants completed ten practice trials to familiarize themselves with task requirements and response mappings, with opportunities for clarification questions. PsychoPy software controlled experimental presentation, with session-specific parameters (participant identification, session number, distractor prevalence, cue validity) configured via a dialog interface. Eye-tracker calibration employed a standard five-point procedure, followed by validation. Instruction screens were then displayed explaining the task.

Each trial began with a fixation cross lasting 500 ms. A white line cue subsequently appeared alongside the fixation cross, forming the cue display (500 ms). Participants received instructions to ignore the line cue and maintain focus on the fixation cross. The search display then appeared and remained visible until response execution via keyboard input. The inter-trial interval was jittered between 1.0-1.5 s.

Participants had to identify the diamond target and determine its internal line orientation as quickly and accurately as possible. Horizontal line orientations required left arrow key responses, while vertical orientations required up arrow key responses. Instructions emphasized ignoring any color distractors appearing in the search display. After each block, an accuracy report appeared, encouraging participants to maintain optimal performance levels. Following the first session, participants could take a short break and complete questionnaires. After the break, eye-tracker recalibration was performed before the second session proceeded with identical procedures but adjusted distractor prevalence settings.

Data analyses

We excluded outlier trials when response times (RTs) fell below 0.1s or exceeded individual participant means by three standard deviations in either direction, or when responses were incorrect. This preprocessing eliminated 1.33% of trials, which was relatively low. All subsequent analyses examined correct trials only.

Behavioral analyses

Primary RT analysis employed a mixed ANOVA examining response latencies across experimental conditions. This analysis incorporated RT as the dependent variable, Singleton Presence (absent/present) and Distractor Prevalence as the within-subject factors, and Group (ASD/TD) as the between-subject factor.

Distractor interference analysis quantified the cognitive cost imposed by the presence of singletons through a derived measure calculated as the difference between RTs for singletons present and absent for each participant and prevalence condition. A similar mixed ANOVA was employed to examine this interference.

Eye movement analyses

Eye-movement data underwent analysis using 1.5° visual angle regions of interest positioned around each stimulus location. Fixation measures included target and distractor fixation frequencies, fixation durations, and the first fixations, providing insight into attentional allocation patterns during visual search.

Separate mixed ANOVAs were used to capture within-group and between-group attentional dynamics.

Results

Manual Reaction

Response Time (RT)

Mean RTs showed clear group and condition effects (Figure 2A). Autistic participants responded more slowly (M ≈ 1300 ms) than TD participants (M ≈ 1100 ms) overall, F(1, 57) = 9.97, p = .003, ηp² = .149. RTs were slower on distractor-present than distractor-absent trials, F(1, 57) = 25.72, p < .001, ηp² = .311, manifesting distractor interference. Interestingly, this distractor interference was larger for autistic participants than TD participants (Group × Singleton), F(1, 57) = 13.86, p < .001, ηp² = .196, indicating that autistic participants were more affected by the presence of distractors. Distractor Prevalence had no impact on overall RTs, F(1, 57) = 0.14, p = .712, ηp² = .002, and did not interact with Group or Singleton (all ps ≥ .162).

Distractor Interference (Presence -Absence)

Interference scores (Singleton Presence -Singleton Absence) reinforced this pattern (Figure 2B).

Autistic participants showed reliably higher costs than TD participants, F(1, 57) = 13.86, p < .001, ηp² = .196. Post-hoc tests revealed virtually no interference for TD participants (9.64 ms, p = .332), whereas autistic participants showed robust slowing (62.88 ms, p < .001); a one-sample test confirmed TD interference did not differ from zero, t(61) = 1.07, p = .287. Distractor Prevalence and Group × Distractor Prevalence were not significant (both ps ≥ .162), indicating that simply making distractors more frequent did not modulate the overall interference pattern. Descriptively, TD participants hovered near zero (Low = 21.4 ms; High = -2.2 ms), while autistic participants showed consistent costs (Low = 52.9 ms; High = 72.9 ms).

Eye movement patterns

While RTs clearly showed more substantial distractor interference in the ASD group than in the TD group, the timeline of attentional processing in which this occurred can be revealed by examining the pattern of eye movements across the entire search trial.

Individual Pattern Examples

Representative scan paths from distractor-present trials illustrate characteristic differences: autistic participants show more dispersed sequences with revisitations, whereas TD participants exhibit more direct paths with fewer fixations (Figure 3). This qualitative pattern foreshadows the quantitative group differences reported below. First Fixation

We first estimated the proportion of initial fixations-those immediately following the central fixation-that landed on either the target or the singleton distractor, under each combination of distractor prevalence and singleton distractor presence, ensuring fair between-group comparisons across conditions (Figure 4). Across all conditions, the first saccade toward the target was relatively low (M = 6.5%) and comparable, Fs < 3.05, ps > .086. Although the first saccade toward the distractor was also relatively low (M=7.2%), repeated-measures ANOVA revealed a significant increase with the distractor presence, F(1, 57) = 37.18, p < .001, ηp² = .395, reflecting strong capture effect when a salient distractor was present.

Neither Distractor Prevalence, Group, nor Group × Distractor Prevalence interaction reached significance, Fs < 2.15, ps > .148, ηp²s < .036. That is, initial capture by the singleton distractor was comparable between ASD and TD groups.

Number of Fixations per Trial

The number of fixations mirrored the RT pattern (Figure 5A). Autistic participants made more fixations overall, F(1, 57) = 5.49, p = .023, ηp² = .088. Singleton distractor presence increased the number of fixations, F(1, 57) = 28.06, p < .001, ηp² = .33, and this increase was stronger for autistic participants than TD participants (Group × Singleton), F(1, 57) = 8.32, p = .006, ηp² = .127: distractor interference, measured by differences in fixations, was greater in the ASD group than in the TD group (Figure 5B). Posthoc simple t-tests revealed that distractor interference effects were significant in both high and low prevalence sessions with autistic participants (ps < .01), while the interference was only significant in the low-prevalence session with TD group (p = .0357). This suggests that TD participants effectively learned to avoid the singleton distractor when its prevalence was high, whereas autistic participants failed to do so despite both the high prevalence and perfect cue validity.

Compensatory Re-checking

To better understand why autistic participants made more saccades, we analyzed the number of fixations directed separately towards the target and the distractor. Figure 6A showed that autistic participants made more returns to targets than did TD participants overall, F(1, 57) = 4.42, p = .040, ηp² = .072, consistent with compensatory re-checking of task-relevant items. The remaining factors and their interactions failed to reach significance, Fs < 1.25, ps > .268, ηp²s < .021.

Analysis of distractor fixations further revealed informative patterns (Figure 6B). Although Group alone showed no significant effect, F(1, 57) = 0.37, p = .547, ηp² = .006, a clear interaction emerged between Group and Singleton Presence, F(1, 57) = 4.51, p = .038, ηp² = .073. The presence of the singleton distractor generally increased fixations toward the distractor location, F(1, 57) = 17.71, p < .001, ηp² = .237; this tendency was especially pronounced in the ASD group. Moreover, raising distractor prevalence significantly reduced fixations on the distractor location overall, F(1, 57) = 14.28, p < .001, ηp² = .2. A significant interaction between Distractor Prevalence and Singleton Presence followed suit, F(1, 57) = 15.59; p < .001, ηp² = .215: when no singleton distractor appeared, participants made fewer fixations toward the cued location under high than low prevalence -that is, they more effectively avoided the cued location when distractors were common and no salient signal was present. This pattern intensified within the ASD group as revealed by a three-way interaction among Group, Distractor Prevalence and Singleton Presence (F(1 ,57) = 6.12, p = .016, ηp² = .097). Autistic participants were more likely to avoid looking towards the cued direction under high-prevalence conditions when no salient distractor appeared there.

Trait Correlation: Intolerance of Uncertainty

To explore whether attentional control differences relate to self-reported intolerance of uncertainty (IU), we correlated each participant's mean distractor interference (averaged across prevalence) with their IU score (for more details, see Supplementary Information). The overall correlation was significant, p = .0015. However, after partialling out Group, the correlation was no longer significant, p = .64, indicating that the association was largely driven by between-group differences rather than a continuous within-group relationship.

In short, behaviorally, autistic participants showed pronounced distractor interference despite perfect cue validity, whereas TD participants showed minimal or no interference. Eye movements suggest similar initial capture by singleton distractors across groups, but autistic participants exhibited more total fixations and more target refixations-consistent with sustained engagement with sensory information and deeper search.

Discussion

Predictive processing differences in ASD manifested neither in initial attentional capture, indicating intact deployment of spatial priors, nor in how distractor interference was modulated by prevalence, indicating preserved perceptual inference. Instead, group differences emerged at later processing stages: autistic participants showed increased response times, more fixations, and more frequent target refixations, consistent with the AIPU account's prediction that differences arise in the temporal dynamics of belief updating following salient events.

Specifically, the first-fixation results argue against a capture account. Both groups were drawn to the singleton distractor equally, replicating previous reports of intact initial orienting in ASD and high-autistictrait samples (28, 45). The 100%-valid cue functioned as an effective spatial prior for both groups, corroborating previous evidence of intact acquisition and use of spatial prior knowledge for attentional deployment in ASD (28). These findings argue against accounts that locate predictive processing differences in ASD at prior formation.

General precision-regulation accounts (24, 26) instead would predict that group differences should emerge in perceptual inference, namely in how distractor interference is modulated by prevalence. Phasic precision accounts specifically predict that atypical processing should scale with surprise, strongest for unexpected events and diminishing as events become predictable (28). The current data do not conform to this prediction: autistic participants showed interference even in the high-prevalence condition, where distractors were highly expected. The larger interference effects found in ASD might appear to indicate altered perceptual inference. However, eye-tracking localized group differences to post-selective processing stages, suggesting that the elevated interference across prevalence levels observed in ASD arguably arises from prolonged iterative updating rather than atypical perceptual inference. Together, these findings argue against accounts that attribute predictive processing differences in ASD to altered, contextdependent weighting of prediction errors during perceptual inference.

Autistic participants made more fixations overall, particularly when singleton distractors were present, and returned to targets more frequently compared to TD participants. Critically, while both groups showed fixation-based interference under low prevalence, only the ASD group showed interference under high prevalence conditions, where distractors were highly expected, though the Group × Prevalence interaction did not reach significance. Under high prevalence, autistic participants made fewer fixations on the cued distractor location when no singleton distractor appeared there, demonstrating that the ASD group learned the prevalence statistics (frequency prior) to avoid the cued location. This pattern rules out a simple failure of proactive suppression (which would predict more distractor refixations and a stronger prevalence benefit) and instead points to sustained post-selective processing difference in ASD. These results support the AIPU account (29), and suggest a mechanistic process: sustained attentional engagement reflects the accumulation of sensory information for iterative updating of priors over time (i.e. posterior-to-prior updating). When a singleton distractor appears , the system must update its belief about what is present at that location.

Under AIPU, this updating process requires continued visual sampling before the belief stabilizes. Increased target refixations reflect re-checking to accumulate confirmatory evidence, while the overall increase in fixations signals deeper search to resolve conflict between prior expectation and current sensory evidence.

This interpretation aligns with formal accounts of decision-making. Findings from drift-diffusion models support the view that evidence accumulation thresholds, not perceptual sensitivity, differ in ASD (46). The overweighting of sensory evidence in iterative updating, as suggested by the AIPU account, would map to larger effective evidence thresholds, requiring more fixations and more target re-checking before response commitment. Future computational modelling studies will be required to test this suggestion.

The correlation between intolerance of uncertainty and distractor interference was significant but became non-significant after controlling for Group. Rather than IU driving atypical attentional control, the AIPU account suggests the reverse: the iterative updating mechanism gives each sensory sample excessive weight, generating persistent residual uncertainty that may give rise to heightened experience of uncertainty in ASD. In this view, the habitual experience of a less stable perceptual world could foster avoidance of uncertain situations, manifesting as elevated trait IU. The cross-sectional nature of our data precludes directional inference, but future longitudinal or computational work could test this prediction.

Our sample size was adequate for the observed effects (df ≈ 57), but the perfectly valid cue and simple visual search display limit ecological validity. Whether our findings generalize to more naturalistic, complex scenes with higher target-distractor similarity and more ambiguous priors remains to be tested.

We also cannot rule out that a larger sample might detect surprise-grading, given that descriptive means show some numerical variation across prevalences in ASD (RT interference: Low = 52.9 ms vs. High = 72.9 ms). Furthermore, given the high comorbidity of attention-deficit/hyperactivity disorder (ADHD) in ASD, future studies should test this paradigm in an ADHD sample to disentangle ADHD-related attentional difficulties from AIPU-related updating. Additionally, varying cue validity, salience, or error costs may reveal conditions under which distractor prevalence exerts greater influence.

In conclusion, the present study reframes predictive processing differences in ASD: the issue is not whether priors are weak or prediction errors are amplified, but how long updating persists once a salient event occurs. A clear processing stage-specific pattern emerges: spatial priors are formed and deployed effectively, and perceptual inference is largely preserved; yet differences emerge during post-selective processing. Autistic participants continued sampling sensory evidence even when distractor occurrence was highly expected, in line with the AIPU account(29) rather than strictly phasic precision-regulation accounts (28). Across paradigms, spanning spatial prior learning (28), probabilistic associative learning of facial emotion recognition(30), temporal estimation(47), and attentional control in the present study, a converging pattern emerges: sustained sensory engagement constitutes a unifying mechanism through which atypical iterative prior updating unfolds. The world may feel "too much" not because predictions fail, but because updating never quite finishes.
