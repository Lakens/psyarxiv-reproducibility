How Ethics Approval Check works

This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

Human research committee names - Institutional Review Board / IRB (US standard) - Independent Ethics Committee / IEC (ICH-GCP international clinical trial term) - Ethical/Ethics Review Board (generic) - Ethics (Advisory/Review) Committee/Board/Panel/Sub-committee - Research Ethics Committee/Board/Panel (UK/Canada/Australia) - Medical Ethics Committee - Human Subjects/Research Committee / Human Research Ethics (Advisory) Panel - Committee for/on the Protection of Human Subjects - Committee on (Health) Research Ethics - Office of Research Ethics - Abbreviations: IEC, REC, REB, ERB, METC, DEC. IRB and IEC are kept unconstrained as they are not observed to collide in practice. - Dutch: Medisch-ethische toetsingscommissie (METC) - French: Comité d'éthique / Comité d'Ethique

Animal research committee names - Institutional Animal Care and Use Committee / IACUC (US standard) - Any sentence containing animal(s) and committee (or board/panel) within ~5 words of each other — catches Experimental Animal Care and Use Committee, Animal Ethics Committee, Animal Welfare Board, Animal Welfare Ethical Review Body, etc. - UK: Animal Welfare Ethical Review Body / AWERB - Dutch: Dierexperimentencommissie / DEC (see DEC constraint above); Instantie voor Dierenwelzijn / IvD - German: Tierversuchskommission / TvK (advisory committee under §15 Tierschutzgesetz) - French: Comité d'éthique en expérimentation animale / CEEA; Comité d'éthique animale - Spanish: Comité de ética en experimentación animal / CEEA

Approval phrasing - Ethics/Ethical (approval|clearance) [was] (granted|obtained|received|given|secured) - Ethically approved - Approved by the (ethics|irb|institutional|independent|local|review|research) ... - This/The study/protocol/experiment/procedures/methods/research [was] (approved|reviewed) by - Study was ethically approved - (Followed|met|follow) the ethical (guidelines|standards|requirements) - In accordance with ... ethical (guidelines|standards) - Ethics protocol - Approved under (protocol|reference|number)

Waiver / exemption - Ethics/Ethical (waiver|exemption) - IRB (waiver|exemption|exempt) - Exempted from (ethics|irb|institutional review) - Waived by the (ethics|irb|institutional|review) (committee|board) - Deemed exempt

Declaration of Helsinki - Declaration of Helsinki / Helsinki Declaration

How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

This module uses regular expressions to identify p-values. It will flag any values reported as p > ? or p < numbers greater than .001. It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module retrieves information from repositories checked by repo_check about code files (R, Python, SAS, SPSS, Stata, Mplus, MATLAB).

This module classifies the files in a repository into semantic types (data, codebook, code, software, output, supplemental, readme, asset, other) and, for tabular data files, extracts each column’s type and summary statistics.

For every file classified as tabular data that is available locally, the module reads the file head, describes each column with data_col_facets() and computes summary statistics for numeric columns. Every sheet of a spreadsheet that holds a table is read: a file with several such sheets has its columns under source_file = "file.xlsx [sheet]", and the sheet column names the sheet of any spreadsheet with several sheets; a sheet of notes or a codebook is treated as documentation when the file has another table. Following DDI, a column is described by orthogonal facets rather than a single type: representation (numeric/text/datetime/code — how it is stored), measurement_level (Stevens: nominal/ordinal/interval/ratio), concept (what it measures: reaction_time/age/gender/likert/id/…), role (identifier/measure/condition/timestamp), unit, and a quality state (ok/empty/constant). The module defaults to rules-only when llm_use(FALSE): columns the rules cannot resolve (ambiguous 3–20-unique integers, ambiguous character columns) fall back to continuous / text respectively. When llm_use(TRUE), ambiguous columns and unresolved file types (other) are sent to llm() for optional refinement, and every file is assigned a study group (ex1, pilot2, shared, …) so that multi-study repositories can be recognised (used by psychds_check). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Run order is derived from read-after-write data dependencies (a script writing a file another reads must run first), source() edges, and numeric filename prefixes as a weak tie-breaker. Ambiguous orderings, dependency cycles, and inputs a script reads but that no earlier script produces (and that are not in the repository) are surfaced as warnings, since these are the situations most likely to make an otherwise-correct reproduction fail.

Python code (.py files, and notebooks and Quarto documents whose code is Python, from which the code is extracted first) goes through the same two phases, reported in its own “Python code” section. Each file is checked for syntax errors with Python’s own parser when a Python interpreter (python, or else python3) is available; dependencies are read from the import statements, with versions from a requirements.txt or pyproject.toml when there is one, and installed with pip; each script runs as its own python process (processx is required), so unlike R scripts, a name one script defines is not available to another. When no Python interpreter is available, the Python files are reported as not run and the R results are still returned. Statistics the Python scripts print are compared with the paper together with the R output and any self-reproducible output (JASP/jamovi, SPSS-Viewer, notebook outputs).

Abstract

Cognitive Distortions are unhelpful thinking patterns that Cognitive Behavioral Therapy (CBT) aims to identify and restructure, so classifying cognitive distortions is a crucial process for reframing. The classification becomes difficult as the data is limited, and the data are imbalanced most of the time. We study dominant distortion classification on the publicly available Therapist Q&A dataset (Shreevastava and Foltz, 2021) where the annotator agreement on the dominant distortion is low (34%). Using the annotated distorted span as input, we compare TF-IDF baselines with RoBERTa, DeBERTa-v3 and MentalBERT (with and without focal loss) over three seeds, reporting accuracy, macro F1 and Cohen's kappa with significance tests. The encoders reach 0.39 to 0.44 accuracy, well above the majority-class baseline (0.15), the three crossentropy encoders are not significantly different from each other, while the weighted focal loss is worse. An error analysis shows that errors concentrate on a small group of overlapping distortions, mainly All-or-nothing thinking, Magnification and Mental filter, which suggests that unclear category boundaries limit performance more than model choice.

1 Introduction

Cognitive Behavioral Therapy (CBT) is a widely used treatment for people who struggle with negative thought patterns, which are common in depression and anxiety (Hofmann et al., 2012). The central goal of the CBT is to identify these patterns known as cognitive distortion, and to help the person reframe them (Beck, 1963). As digital and online therapy become more accessible, the need for automated tools that recognize distortion in text is growing. Natural Language Processing (NLP) offers a practical route to this with suitable data and models; a system could flag a distortion in what a person writes and support reframing between therapy sessions. Such a tool would assist therapists and users, not replace them. Classifying distortion is difficult for several reasons; labelled data is rarely available, and classes are imbalanced. The categories also overlap and trained annotators often disagree. On the Therapist Q&A Dataset, agreement on the dominant distortion is only 34% (Shreevastava and Foltz, 2021). Later work on this dataset studied a multi-step pipeline (Phan et al., 2025) that first extracts the distorted span and then classifies it. However, a controlled comparison of model families that reports variation across random seeds, statistical tests, and an error analysis is still missing.

Rather than focusing only on classification performance, we examine which distortions are confused, using the average confusion pattern of the four encoders and per-class scores across all models. These patterns can reveal the limitations in the current dataset and classification formulation, and offer useful insights for developing more reliable cognitive distortion detection systems. In this paper, we study dominant distortion classification over 10 classes, using the annotated distorted span as input. We compare TF-IDF baselines with three transformer encoders under identical settings and three seeds; we report accuracy, macro F1 and Cohen's kappa with significance tests. Our contributions are: A controlled comparison of six models on dominant distortion classification, with results averaged over three seeds. Evidence that three cross-entropy encoders do not differ significantly from each other, although they tend to outperform the TF-IDF baselines. An error analysis showing that mistakes concentrate on small groups of overlapping distortions, which suggests that unclear category boundaries limit performance more than model choice.

2 Related Work

Cognitive distortion detection has grown quickly, but a recent survey of 38 studies described the field as fragmented, with inconsistent taxonomies, task formulations and evaluation practices, and few shared benchmarks (Sage et al., 2025). The therapist Q&A dataset is one of the few public resources (Shreevastava and Foltz, 2021) Varadarajan et al. (2025) trained detectors on their annotated spans and found spans worked better than full messages (detection F1 0.823 vs 0.693), then linked detected distortions to mental health outcomes. Phan et al. (2025) proposed multi-step framework that extracts the distorted span then classifies it. Other work addresses the imbalance that we also face. Ding et al. (2022) compared data augmentation with domain specific MentalBERT on rare distortions in therapy messages, and found the domain-specific model gave larger gains than augmentation. Related tasks include cognitive reframing, where Sharma et al. (2023) study how language models can help people reframe negative thoughts, and joint distortion detection and emotion cause extraction in clinical conversations (Singh et al., 2023). Our study differs in scope: we compare model families under identical conditions on one fixed task, report variation across seeds with significance tests, and analyze which distortions are confused.

3 Methods and Data

3.1 Dataset

Limited data is a common obstacle in mental health NLP, because the conversations are confidential and rarely shared. We use the Therapist Q&A Dataset (Shreevastava and Foltz, 2021), which contains anonymized patient questions collected from Kaggle. Each entry is a short message in which the patients share their situation, followed by a response from the therapist. Annotators labeled each message with a dominant distortion, and a secondary distortion where one applied, chosen from 10 types; All or Nothing, Overgeneralization, Labeling, Fortune telling, Mind reading, Emotional Reasoning, Should Statements, Magnification, Mental filter and personalization. They also marked the part of the messages where the distortion appears, which we call a distorted span. For the dominant distortion, the original author reports a joint probability of agreement of 33.7% between two annotators, measured on about 730 messages. In our study, we drop the messages labeled "No Distortion" and keep the 1,597 distorted messages, using only dominant labels. We hold a stratified test set of 240 messages and use the remaining 1,357 for the training and validation. All models use the same split.

3.2 Methodology

Following earlier work that found distorted spans more informative than full message (Varadarajan et al., 2025; Phan et al., 2025), we predict the dominant distortion from the annotated distorted span. The split is fixed for all models: a stratified test set of 240 messages (split seed 3407) and 1,357 messages for training and validation. We use TF-IDF features with Logistic Regression and random forest. The regularization strength and the tree depth are chosen by 5-fold cross validation on the training data, using macro F1. We fine-tune three pretrained encoders for sequence classification: RoBERTa-base, DeBERTa-v3-base and MentalBERT, a BERT model pretrained on mental health text that Ding et al. (2022) also used for distortion classification. MentalBERT is trained with two losses, standard cross-entropy and a weighted focal loss (gamma = 2, class weights proportional to inverse class frequency). Because the focal variant also uses class weights, any difference from cross-entropy mixes the two effects.

For encoders, we ran 5-fold cross-validation (6 epochs, learning rate 3e-5, batch size 16) to check that this configuration was stable (Table 1). Crossvalidation accuracy was within about one point of test accuracy, RoBERTa and MentalBERT (CE) were tied in both, and DeBERTa-v3 was lowest. We then fixed this configuration for all encoders. Crossvalidation chose C = 30 for logistic regression in all seeds and a tree depth of 60, 60 and unlimited for random forest. We train for up to 10 epochs (15 for DeBERTa-v3, which converged more slowly in our trials). We keep 10% of the training data for early stopping in macro F1 (patience 3) and evaluate the best checkpoint once in the test set. Every model is run with three training seeds (1,2 and 3) separate from the split seed. We report mean and standard deviation of accuracy, macro-F1, weighted F1, and Cohen's kappa against the gold labels. A majorityclass predictor serves as reference. To compare models, we ran McNemar test on each seeds predictions and report the p-value for each seed. Because the three seeds use the same test set, the per seed pvalues are not independent, so we do not combine them. We also computed a paired bootstrap (5,000 resamples of the test messages) on the accuracy difference averaged over seeds, and call a difference significant only if its 95% interval excludes zero. The differences between the three cross-entropy encoders are not statistically significant (Table 3), so none of them is reliably better than the others. Weighted focal loss is worse than MentalBERT (CE) by 5.0 points. RoBERTa and MentalBERT (CE) beat TF-IDF + LR by about 7 points, and their bootstrap intervals exclude 0. The per-class results (Table 4) show that Allor-nothing thinking, mental filter and emotional reasoning were consistently weak, falling between 0.1 and 0.3, while mind reading, labeling, and fortune telling were easy to identify, falling between 0.5 and 0.6, with mind reading at 0.65.

4.2 Discussion

The three cross-entropy encoders are within about three points of each other (0.415 to 0.442 accuracy), and none of the pairwise differences is significant. MentalBERT (CE) has the highest mean, but its lead is smaller than the variation across seeds and the standard error of a 240-message test set. Weighted focal loss was worse than crossentropy (0.392 vs 0.442 accuracy) and less stable (SD 0.046). Because this variant uses class weights, we cannot tell whether the focal term or the weights caused the drop. It raised the All-or-nothing F1 score (0.271 vs 0.207), but this is a single small class and probably noise. MentalBERT (CE) and RoBERTa beat TF-IDF with logistic regression with kappa of about 0.37 vs 0.28, yet this advantage is significant under McNemar in only one of three seeds, because the p-values are 0.008 and 0.005. Overall, scores of about 0.44 on ten classes are far above the majority baseline but still modest. Errors are not spread evenly. 5 Conclusion

We compared TF-IDF baselines and three transformer encoders on dominant cognitive distortion classification, using the annotated distorted span and three seeds. The encoders reach 0.39 to 0.44 accuracy and clearly outperform the majority class baseline, but the three cross-entropy encoders are not significantly different from each other, while the MentalBERT (Focal) is worse and their ad-vantage over TF-IDF with logistic regression is borderline. Errors concentrate on small groups of overlapping distortions, mainly all-or-nothing, magnification and mental filter, which suggests that unclear category boundaries and noisy labels limit performance more than the choice of model. Future work should revisit the category definitions, model multiple distortions per message, and evaluate on larger, independent data with clinical review.

Limitations

All results come from one dataset, and the test set has 240 messages, 15-36 per class. Differences of few points and per class F1 values are therefore uncertain, and the error analysis is exploratory. With only three seeds, the estimation of variation is rough. Annotator agreement is low, and a message may contain several distortions, yet we predict one dominant label, so some errors may be valid alternative labels. We used human-annotated distorted spans as input, so we do not test a full automatic pipeline that must first find the span. We did not correct for multiple comparisons across the model pairs. Fine-tuning on 1,357 messages is noisy, and results can shift between full reruns. The encoders share the same hyperparameters, with only the epoch limit changed for DeBERTa-v3 per model; tuning could change the ranking. We did not include large language models in the comparison. Finally, the data are public forum posts, and no clinician reviewed the predictions, so the results are not clinically validated.
