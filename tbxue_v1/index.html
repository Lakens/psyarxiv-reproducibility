This module searches for statements of ethics approval, IRB approval, institutional review board approval, and related terms.

Patterns are designed to capture:

This module uses regular expressions to identify sentences that contain a statistical power analysis. If specified by the user, it also uses a large language model (LLM) to extract information reported in power analyses, including the statistical test, sample size, alpha level, desired level of power, and magnitude and type of effect size.

The Power Analysis Check module uses regular expressions to identify sentences that contain a statistical power analysis. Without the use of an LLM, the module uses regular expressions to classify the power analysis as a-priori, sensitivity or post-hoc. How Exact P-Values works

List any p-values reported with insufficient precision (e.g., p < .05 or p = n.s.) or reported as exactly zero (e.g., p = .000).

It will also flag p-values reported as exactly zero (e.g., p = .000, p = 0.00), which are mathematically impossible — p-values are never exactly zero and should instead be reported as p < .001.

A p-value that is not the result of a test is not flagged: a table note (“* p < .05, ** p < .01”), a figure legend (“Asterisks indicate significant differences (p < .05)”, “Values in bold are significant at p < .05”) or a stated threshold (“p < .05 was considered significant”, “thresholded at p < .001”). GROBID often puts such notes into the running text, so each p-value is judged by the words in its own clause (the text up to a “;” or a full stop), and never left out when a test statistic belongs to it (“F(1, 7) = 8.03, # p < .05”). The column not_a_test of the table says why a p-value was left out (“marker”, “threshold” or “legend”). Notes in other forms, such as a marker after the p-value (“p < .05 (*)“), are still flagged.

This module sometimes flags false positives when sentences discuss how p-value thresholds were set. It can also miss an imprecise p-value that is reported against a threshold (“decreased at the p < .05 significance threshold”).

This module only checks p-values reported in the running text of the manuscript. It cannot (yet) process p-values reported only in tables (as opposed to a table’s footnote text, which the module does see and tries to exclude — see above).

How Codebook Check works

This module checks whether the data columns in a repository are documented in a codebook or README. It locates codebook/readme files, extracts the variable definitions they contain, matches those definitions against the data columns extracted by data_check, and reports documentation coverage: how many data columns are documented, and which documented variables are never used.

The Codebook Check module consumes the columns and file classification produced by data_check (and, transitively, repo_check). Files classified as codebook or readme are parsed with parse_codebook(), which reads structured tables (CSV/TSV/Excel with a variable-name column and a label column), embedded labels in haven files (SPSS/Stata/SAS), and plain text from rich-text formats (docx/pdf/rtf/odt). How Reproducibility Check works

This module assesses whether a paper’s R and Python code can be run on its data. It works in two phases. The static phase (always run) collects the package dependencies the code declares, rewrites the data-file paths that do not work in the repository as the authors organised it, works out the order the scripts must run in, and diagnoses why any referenced input file is unavailable — reporting what a reproduction attempt would involve and where it is likely to break. The execution phase (opt-in, execute = TRUE) then actually runs the code: it copies the repository into a throwaway directory, optionally installs the declared dependencies into a throwaway library, runs each script in order in an isolated subprocess with a per-script timeout, and captures the outcome and full output of each run.

By default (execute = FALSE) the module does not run any code — it performs only static analysis: reading dependencies with the same extractors as code_check, finding the files the code references in the repository, and building a run-order dependency graph. It reports what would be installed and run rather than doing it.

When execute = TRUE, the module additionally runs the downloaded code on your machine — a deliberate, opt-in action gated behind that argument (callr is required for R code). Each script runs in an isolated subprocess so a crash cannot take down the R session; note this isolates crashes, not the filesystem or network. Installs (when install_missing = TRUE) and the throwaway run library never touch your main R library. Each script’s outcome is one of ran_ok, errored, timed_out, dependency_unavailable, not_parsed, run_by_source (an R script another script runs with source(), which is run only inside that script, since on its own it lacks the packages and objects the sourcing script sets up first), run_by_import (a Python file other files import, a module rather than a script, unless it has an if __name__ == "__main__": block), jags_model (a JAGS or BUGS model saved with an R extension, which another script reads) or not_r_content (a file that is not R at all, such as a JSON or HTML dump); these last two are not run and are not failures. python2 marks Python 2 code that was not run. With sandbox = "docker" such code runs with Python 2.7 (option metacheck.docker_image_py2; FALSE turns this off), which modifications records; it is never converted, since that can change results. defines_functions is a file that only defines functions, which is used, not run (table$used_by names the scripts that use it), and not_analysis is a file of software rather than of the analysis: a package’s code, tests, documentation or setup.py, a copy of a tool, a web application, a script a program wrote (table$not_analysis_why says which); neither is run or counted as a script. docker_failed means the container never started, which says nothing about the script, so it keeps the light from being green but does not make it red. needs_a_person is a script that stopped because it asks a person to choose a file or answer a question, or that starts an app, and needs_internet one that stopped because the network is off in a Docker run, or, with internet = TRUE, could not reach what it asked for; download_too_large is a script stopped for downloading more than the limits allow (see internet), and out_of_memory one that, or a program it started (such as a compiler), ran out of the memory each script may use. All four are treated the same way. not_downloaded is a script that stopped on a file the repository lists but that was not downloaded, such as one over max_file_size: it could not be tried, so it is not counted as a script that did not reproduce (summary_table$repro_not_downloaded_n counts them apart). not_read is a file metacheck could not read, so it was not run; the light is then not green, as the file may read and run on another computer, and table$error_message says why, naming a package that is installed but cannot be loaded on the computer that ran the check. empty is a file with nothing in it, which is not run or counted as a script. For a script that did not run through, table$error_message is its error, short (at most 300 characters): the error line of its output, which names a package that is not there, with the address it asked for when it needed the internet, or the time limit it reached; table$reason sorts it into a kind. A timeout means “still running at the cutoff”, not a failure, so raise timeout for legitimately long-running (e.g. Bayesian) scripts. dependency_unavailable means the script’s own package could not be installed from live CRAN, the CRAN Archive, or a named GitHub/URL source — an infrastructure limitation, not a defect in the paper’s code, so unlike errored/timed_out it does not force the traffic light red. The full stdout/stderr of every run is kept in the result’s run_results (the report shows it in per-script dropdowns, capped for readability). The traffic light reflects the STATIC readiness signals by default, but an execution error (errored/timed_out) does recolour it to red — a script that crashes on its own analysis is a genuine reproduction failure. A script that fails with could not find function is run once more with the library() calls the project’s other scripts make added at its top (or the one package that exports the function, or magrittr for %>%), and a script that then runs is reported as reproducible only after that repair.

Dependencies are reported name-only, with the source (CRAN, GitHub, or a base package already shipped with R) — static analysis of the code cannot know which version was used, and running against current package versions is itself informative: a break argues the authors should have pinned versions. When the repository does record versions, a run with recorded_versions = TRUE installs the packages the scripts load at those versions, but it does not change the R version, which remains a limitation of the check.

Abstract

Psychological processes are characterized by constant change and complex underlying dynamics and are often researched using intensive longitudinal data (ILD). Although such data are often analyzed with parametric models, these models impose strong and simplified assumptions about the system's dynamic rules that can be unrealistic and may fail to capture phenomena such as multistability. Recent work has enabled estimation of the stability landscape of psychological systems from ILD, yet drawing statistical inferences from such landscapes remains challenging. In this work, we present a new method for statistical inference based on stability landscapes. The core of the method is bootstrapping, complemented by specialized techniques applied before and after the bootstrap procedure to make computation feasible and to effectively summarize information across bootstrap samples. Across three simulation studies with different data-generating mechanisms, we evaluated the method and, in particular, four approaches for summarizing information about the locations and depths of local minima. Overall, we found that using fixed reference points, such as the local minima from the original sample, helps guide the assignment of bootstrapped minima. When the data-generating mechanism differs from the estimated stability landscape, directional bias may occur; however, the relative locations of minima can still be retrieved. The method generally shows higher precision, whereas achieving high recall may require clear separation between minima, longer time series, and lower measurement noise. We also provide an empirical illustration using an existing dataset. An implementation is available in the latest version of the R package fitlandr.

Nonparametric inference of stability landscapes from intensive longitudinal data

How do we describe the dynamic property of psychological systems? For a long time, the major approach has been to use parametric models with parameters that are used to give information about questions of interest. The vector autoregressive model (Bringmann et al., 2013; Hamilton, 1994), for example, uses specific parameters to describe the relationship between one variable and another. We can estimate these parameters and their uncertainty levels, and compare them to zero to know if the effect from one variable to another is positive or negative; we can compare them across participants to know whether this effect is stronger for one person than another.

Yet, the assumptions implied by these parametric models are often unrealistic, as psychological systems operate in a far more complex way than the models assume. Recent developments from the complex systems perspective have pointed to the possibility of an alternative approach (Hayes & Andrews, 2020; Olthof et al., 2023). From this perspective, complex, nonlinear interactions across different elements at all levels give rise to certain psychological phases that differ qualitatively and have important meanings. These phases may represent, for example, different behavioral patterns that differ in health or sustainability (Heino et al., 2022; Schüler et al., 2025), adaptive and pathological phases in psychopathology (Hayes & Andrews, 2020; Olthof et al., 2023), or the optimal and suboptimal solutions in problem solving (Tulver et al., 2025). There, what is in the spotlight is not how strongly one variable is related to another one in time, but rather what states of the system are overall more stable, and whether the psychological system may transition from one phase to another (see Figure 1). A key challenge is that researchers often cannot start from the microscopic level and fully understand all dynamics in detail, and similarly, they often cannot specify in advance the functional form of stability across different states. For example, if we want to know the relationship between the stability of the state and its corresponding depression symptom score, it is very hard to specify the functional form (e.g., quadratic or linear) in advance. The relationship between stability and mental states can vary substantially across contexts and individuals. Ideally, we would therefore infer stability directly from the data rather than impose a particular parametric specification.

The theoretical development calls for quantitative methods that can be used in analysis to obtain such a stability landscape from psychological data. Applying results from applied mathematics, biology, and economics, our recent work has made this possible (Cui, Hasselman, & Lichtwarck-Aschoff, 2026; Cui, Lunansky, et al., 2026; Cui et al., 2023), and subsequent work has shown the potential of this approach to connect and form a uniform bridge between different disciplines and better understand the dynamic properties of a psychological system through various models (Hoekstra et al., 2026; van Bork et al., 2024).

However, a critical challenge of these recently developed nonparametric methods is the ability to draw statistical inferences. This is an underdeveloped aspect of the current method. In fields such as chemistry or biology, there is often less need for statistical inference because of the abundance of data (e.g., Qiu et al., 2022; Zhou & Li, 2016).

However, as psychological time series are often limited in length and often contain strong noise, we cannot simply believe the landscape calculated from a data set is accurate at every point. Instead, we need to know how accurate the estimation is, or in other words, to what extent we can believe the landscape shape and the basins we found are likely to come from actual dynamics of the psychological systems, instead of representing random fluctuations. Essentially, this issue is comparable to the need for a standard error estimate for an estimated parameter. When we want to know whether a psychological therapy is effective, for example, we do not only need the mean difference in symptoms before and after treatment. We also want to know whether this mean difference is significantly different from zero, so we can be confident that the non-zero change is real rather than just random fluctuation. What motivates us to estimate the error in our landscape estimates is similar. However, the key methodological challenge presented here is that the target of estimation is not a single value, but rather a landscape surface defined on a two-dimensional state space. Therefore, a novel methodological workflow is required to make the range estimates and statistical inferences possible.

In the current article, we present a method to draw statistical inferences about estimated landscapes. It is centered around a nonparametric bootstrapping approach, with specific preparations and an analysis workflow afterward to summarize the results. We structure the article in the following way. First, we detail the challenges required for statistical inferences on stability landscapes and the technical solutions we propose. For certain steps, we propose several possible options and introduce their pros and cons, as well as the considerations behind them. Second, we use a systematic simulation study to evaluate the method we propose. Finally, we use an empirical example to showcase the possibility of applying this method in a real-life setting. Before the Bootstrapping

Efficient Calculation of the Generalized Potential Function

A common approach for estimating the uncertainty of a nonparametric estimation result is to use bootstrapping (Efron & Tibshirani, 1994), in which the original dataset is resampled with replacement, and each resampled dataset is used for the same estimation procedure. The results from different bootstrapping samples are then summarized to provide information on the estimation uncertainty. In a common setting, hundreds or thousands of bootstrapping replications are needed, depending on the goal (e.g., estimating a standard error usually requires fewer bootstrap replications compared to an exceedance probability). To make sure the bootstrapping can be finished in reasonable computation time, each estimate needs to be efficient.

In fitlandr 0.1, the most time-consuming step is estimating the steady-state distribution. On a personal computer, it takes around 10 minutes to give a reasonable accuracy, and may take even longer if a higher accuracy is needed. This becomes computationally heavy when combined with bootstrapping. Therefore, the first step to build an inference workflow on stability landscapes is to improve the efficiency for a single estimate.

In fitlandr 0.2, we no longer use the Monte-Carlo simulation for estimating the steady-state distribution. Instead, we apply a numerical method to directly calculate the steady-state distribution from the drift-diffusion equation. Specifically, we apply a finite-volume method (FVM; Eymard et al., 2000), illustrated in Figure 2. The central aim of this approach is to find a solution of the probability density p that meets the steady-state criterion: the probability density does not further change over time. Here, by way of metaphor, it may help to think of the probability as sand in a big box. We then want to understand how the sand will be distributed in the end if wind blows through the box (representing the dynamic functions). To achieve this, we try to obtain a simplified local linear representation of how the probability density changes as a function of p. In the first step (Figure 2a), we divide a finite computational region of the state space into n × n grid of cells (n defaults to 100 in fitlandr). At the center of each cell, we evaluate the estimated drift and diffusion functions, µ and a. We then approximate the net probability flow across the four faces shared with orthogonally adjacent cells, meaning how much of the probability flows in and out of the boundaries, as a function of the probability densities in these cells and the estimated drift and diffusion coefficients (Figure 2b). We impose reflective boundary conditions, so that probability cannot flow out of the computational region. This is to make sure the sum of probability does not change over time: once the probability flow hits the boundary, it should return back. In this sand-and-box metaphor, this means we have walls for the box so that no sand can be blown out of the box. The steady-state probability density vector p can then be estimated by solving Lp = 0 (Figure 2c), subject to the constraint that the density integrates to 1. The elements of the sparse n 2 × n 2 matrix L are known and can be calculated based on the estimated diffusion equation and the grid discretization. Intuitively, this matrix describes how probability flows between neighboring cells. The exact calculation of these flows is provided in Appendix A. With this numerical approach, the computation time for each run is reduced to seconds, roughly 80 times faster than the previous Monte Carlo approach.

Identifying Meaningful Minima from Stability Landscapes

The location and depth of local minima are the primary focus of the inference step, as they contain information on the characteristics of psychological phases and their stability. A minimum is defined when the value of the potential function at this location, U (x), is lower than all its neighbors. As we use a rectangular grid for numerical calculations, there are eight neighboring states for each given state. The potential values outside the estimation boundary are defined as infinite.

After locating all minima, we first need to remove those minima that do not have practical significance or are mainly caused by numerical instability (we call these minor minima). We apply several rules to label minor minima. First, we remove the minima that fall outside the convex hull of all the observed data points. The convex hull of a set of points is the smallest convex polygon that encloses all the points (see Figure 3). We exclude the outer minima because the actual state of the system has never visited the area outside of the convex hull. Therefore, the outer region has almost no chance of containing a true minimum informed by data. At the same time, there is relatively little information regarding the stability of the system. Therefore, the local minima outside the convex hull are almost certainly due to numerical instability, which is often observed in estimated landscapes.

Second, we exclude the basins that are too shallow to be practically meaningful.

The depth of a minimum needs to be defined as the barrier height separating the minimum and another local minimum. Therefore, we first calculate the minimal energy path between each pair of minima and obtain the barrier height from both sides. If there is more than one dimension, there are infinite routes connecting two minima, so we first need to find the minimal energy path (MEP), defined as the path that goes through the lowest saddle point between the minima (the detailed algorithm is described in Cui, Olthof, et al., 2026, also see Figure 4a). Next, across the landscape, we find the deepest barrier height and the shallowest barrier height. If the height of the shallowest barrier is lower than 10% of the highest one, we mark this local minimum related to the shallowest barrier as minor, and repeat the procedure again with the remaining minima until the shallowest barrier is at least 10% of the highest one. We also remove the minima associated with barriers that are shallower than 1% of U max -U min within the convex hull of all observed data points. This step is to prevent the situation where there is only one flat basin, but some numerical fluctuations exist around the bottom of the basin, resulting in many tiny minima. In this way, the local minima caused by small local fluctuations can be effectively removed. See further marked as minor, and the whole procedure concludes. In the two-dimensional situation, there are an infinite number of paths connecting two local minima, so we need to find first the most optimal path, or the MEP.

Setup for Bootstrapping

In the estimation (see Equations 2 and 3), the information extracted from the data consists of the current state x t and the increment ∆x t = x t+1x t . Therefore, we perform bootstrapping at the level of these paired observations. Thus {(x t , ∆x t )} T -1 t=1 are the data to be resampled. To account for temporal dependence in the data, we perform blocked bootstrapping. Specifically, we first generate all the possible moving blocks with length ℓ block , which defaults to the cube root of the number of valid vectors rounded up to the nearest integer following the general suggestion by Hall et al. (1995). After that, in each of the B bootstrap samples, we randomly draw a block from all the blocks with replacement, and draw another block to combine together until the sampled number of vectors reaches or exceeds the original number of valid vectors, and truncate any excess vectors. The cross-validated bandwidth is fixed across bootstrap samples. By default, we use B = 200 bootstrap replications. This is a balanced choice between accuracy and computational efficiency. From these bootstrapping trials, we obtain B = 200 landscape functions.

In Approach 3, we perform clustering on all the bootstrap samples and use the mean and covariance of all the minima within a cluster to estimate the minima and their uncertainty. Specifically, we apply the Hierarchical Density-Based Spatial Clustering of Applications with Noise (HDBSCAN, Campello et al., 2013), which is an unsupervised machine learning algorithm that can find clusters of data points. HDBSCAN can also identify outliers that do not belong to any clusters. There is a potential issue with clustering on all bootstrap minima: it does not take into account the hierarchical structure of the data, namely, minima belong to different bootstrap samples. This can be problematic when the bootstrap minima do not show clear clusters when taken together, but each of the bootstrap samples still shows consistent patterns (e.g., Figure 6). To solve this problem, we apply another approach, in which we first conduct a Hungarian matching on each of the total B(B -1)/2 pairs of the bootstrap samples. We then form a network with each of the bootstrapped minima as nodes. The weights of the edges between nodes are given by the distances: when the minima are closer, the edge is also stronger. After that, we apply the Leiden algorithm (Traag et al., 2019), which is an efficient approach to find clusters from the network. Each cluster represents a minimum.

To limit excessive splitting of bootstrap minima into separate clusters, we set the Leiden resolution parameter to a relatively low default value of 0.01. Subsequently, we calculate the locations, depths, and uncertainty of locations for all minima using the same approach as in Approach 3 (Equations 15 and 16). In this way, we take into account the hierarchical structure of the data, namely, the minima are nested in bootstrap samples.

General Discussion

The current study presents a novel approach to draw statistical inferences on stability landscapes of psychological systems. This approach relies on bootstrapping applied to the stability landscape. To make the bootstrapping inference possible, we provided a set of technical solutions, including cross-validation to find the optimal bandwidth, the finite volume approach for precise and efficient calculation, and four approaches to summarize the local minima from bootstrapped landscapes. these approaches in three simulation studies, with the first one using a potential-based model as the data generation mechanism, the second one using a linear Regime-Switching VAR model, and the third one using a nonlinear Lotka-Volterra model. Finally, we illustrated the performance of fitlandr 0.2 on an empirical dataset.

To our knowledge, this is the first work to achieve statistical inferences on a potential landscape function from intensive longitudinal data. Earlier work in other fields that constructs a stability landscape from empirical data, for example, biology (Qiu et al., 2022) and animal movement (Brillinger et al., 2012), typically involved far longer datasets with more precise measurements, where the uncertainty issue is less pressing. In psychology, self-reported data from experience sampling are often much shorter and involve larger measurement errors, thus requiring a systematic method to evaluate whether the stability landscape, especially the number and location of basins on it, is obtained with confidence or is more likely to result from random noise. Nevertheless, we believe the application of the current method is not confined to the field of psychology and experience sampling data. For any other fields where stability and uncertainty are central focuses, the current method could be potentially applied.

The simulation results showed that, overall, summarizing approaches guided by minima from the full-sample results (Approach 1 and Approach 2) perform better than approaches that directly cluster all bootstrapped minima (Approach 3 and Approach 4).

Although the guidance-free clustering approaches are designed to go beyond the full-sample results and incorporate additional information (Table 1), their performance is unsatisfactory, mainly because they report too many minima. Referring to the full-sample results overall is more beneficial. Further, the performance of fitlandr 0.2 depends on both the data generation mechanism and the specific indicator of interest.

As a non-parametric method that is agnostic about the true data-generation mechanism, we observe some estimation bias in the location of the minima across all simulation conditions. Consequently, the estimated minima and their associated uncertainty regions may not overlap with the true minima. In Simulation Study 1, the bias is small and practically unimportant, but it can still affect precision when the time series is long, leading to a small confidence ellipse. In Simulation Studies 2 and 3, the bias can be larger in some conditions. In Appendix B, we showed that the main sources of bias include the time gap between observations and the kernel smoothing. Because the algorithm does not know the data-generation mechanism, it cannot know the true form of the conditional distribution of the next observation given the current one, and therefore has to assume that the first and second moments provide enough information. Also, because the datasets are not very long, it has to assume that the dynamics are locally similar, so that information from nearby observations can still be used. These are good approximations when the sampling frequency is high compared to the underlying dynamics, or when the kernel is not too wide. In Appendix B, we found that the bias would disappear in Simulation Study 1 as the time gap between assessments and the kernel width approach zero. However, these conditions are not realistic in real life. To keep the bias low, it is important to ensure that the assessment frequency is not too low relative to the dynamic process, as also found in earlier research (Cui, Hasselman, & Lichtwarck-Aschoff, 2026). The kernel bandwidth is optimized through cross-validation and thus should not be manually reduced, but having more data points and more accurate assessments would also help reduce the bandwidth needed. Furthermore, when the data-generation mechanism deviates more from what fitlandr assumes, it may induce additional bias. One example is the transient transition behavior caused by regime switching in Simulation Study 2. When the system is close to Phase A but the underlying mechanism suddenly switches to Phase B, it adds directional, drift-like information around the local minimum of Phase A, making the estimated minimum location lean toward the other phase. As shown in Appendix B, this bias is intrinsic and results from the mismatch between the assumptions of the data-generating model and the assumptions of fitlandr, rather than from the specific estimation procedure.

Therefore, which model is preferable mainly depends on the theoretical view: whether the true psychological process has a latent "switch", or is better described by a multistable landscape. Nevertheless, the results of fitlandr still preserve the relative locations of the minima in all simulation studies. We can see this from the results after compensating for the bias: the confidence ellipses show close to 95% probability of covering the true minimum location when the measurement noise is not too strong. Meanwhile, the recall rate increases as the time series becomes longer and the minima become more separated.

Therefore, when the psychological phases are sufficiently different and the assessment period is longer, the power of fitlandr to identify minimum locations increases.

While the results for the minima locations showed good performance, the relative depth of the basins is more difficult to estimate. In Simulation Study 1, although the data generation mechanism aligns well with fitlandr, the estimation of ∆U is biased to zero and has a large confidence interval. The key reason for this difference is that the information required for minima location estimation is different from basin depth comparison. Minima location mostly requires local information close to the minima. However, to obtain the information for depth comparison, we also need information for the region between minima.

In other words, we need to know how exactly the system transitions between minima. As the minima location represents the most stable psychological states, we naturally have more information there, yet the transition paths need to pass through unstable regions which are relatively rare in data, making the estimation difficult. In order to better estimate the relative stability of different psychological phases, data with more frequent transitions are probably needed (e.g., data in experimental settings and for phenomena with more frequent changes). Another possible reason is that we required the system to reside in either basin for at least 25% of the time and discarded time series that did not meet this requirement. This was mainly intended to ensure that enough data were available to describe each local minimum, but it may have biased the depth estimate.

Overall, in simulation studies, we found that fitlandr leans to the conservative side.

It is more likely to miss true minima or true stability differences, but is less likely to report false minima or differences. Therefore, it is relatively reliable in empirical settings, even when the time series are short. The location of the minima is easier to find than their relative depths. When the true data-generation mechanism differs from what fitlandr assumes, the location of the minima may be biased; the estimated minima may be closer than they actually are, yet the relative location of the minima is still reliable.

In our empirical illustration, the length of the time series is shorter than the adequate values in the simulation studies, yet the result can still show bistability in one case, suggesting the example participant has two psychological phases differing in emotional valence. However, to improve the statistical power, we still suggest that empirical users collect longer time series to perform analysis with fitlandr. Future work may also explore other approaches to make use of group information or prior theories to reduce the data length requirement for a single participant.

The key advantage of the current work lies in two parts. First, fitlandr is a nonparametric approach with few assumptions about the underlying dynamics of the systems. Without committing to a specific, simplified assumption for the data generation mechanism of psychological data, fitlandr allows various kinds of dynamics to be detected and analyzed in the form of drift-diffusion equations, vector fields, and landscape representations. In this work, we propose an innovative technical pipeline that shows that drawing inferences from such nonparametric models is technically feasible. Therefore, it adds an important complement to the toolbox of analysis methods for intensive longitudinal data. Second, to our knowledge, it is the first method to obtain an estimation of the stability landscape for psychological phases through self-rated time series. While many theorists have emphasized the use of the stability landscape in understanding complex psychological dynamics, a concrete estimation method was not available until the current line of work, which plays an important role in connecting dynamic systems theories with empirical data and paves the path for future empirical work. In the earlier version of fitlandr (Cui, Hasselman, & Lichtwarck-Aschoff, 2026), we showed that this pathway is possible, and with the current development, we ground this innovative approach in a solid technical pipeline for statistical inferences, thus making the method practically usable for a wide range of psychological questions and theoretical hypotheses on stability. Future empirical research can, in turn, provide information on the stability of various psychological states, which can be used to update relevant theories and models.

We see several future directions for further methodological development. First, the results of fitlandr contain more information that has not been systematically examined in this study. For example, it provides the percentage with which a bootstrap minimum occurs in the bootstrap samples, which provides information on how confident we are that a minimum exists. Incorporating this information and setting a threshold (i.e., only accepting a minimum when it appears in more than a given percentage of bootstrap samples) may also help improve the method's precision. Nevertheless, as the precision of the method is high in general, the improvement by adding this threshold may be limited unless for more complicated situations. Second, apart from the landscape, the vector field also contains some remaining dynamics that represent the curling behavior of the system (Zhou & Li, 2016). This part of the dynamics illustrations, as the local minimum of participants with a BPD diagnosis seems to have lower valence. Therefore, future work may extend the fitlandr method to group settings, either with multilevel extensions or clustering methods. Finally, some important parameters in the fitlandr method still rely on rules of thumb (e.g., the length of bootstrapping blocks). Future work may also calibrate these parameters in different settings to further improve its performance.

Theoretical Analysis of the Source of Bias

The fitlandr method uses observations close to a given state to extract local dynamic information, and it uses discrete-time samples to infer the underlying continuous-time dynamics. Therefore, two intrinsic factors can lead to bias in fitlandr estimation results: the kernel smoothing method used when estimating the drift-diffusion equation, and the time interval between observations. When the number of available observations is limited, the algorithm has to pool information from further observations, which may lead to directional inaccuracy. When the observations are too far apart, the dynamic information at a subtler time scale may be lost. Appendix B: Bias Analysis for Simulation Studies Empirical Bias in Simulation Studies and the Bias Compensation Procedure

In simulation studies, we applied a bias-compensation procedure to investigate how much the directional bias influences the precision and recall. As the data-generating model has certain symmetry properties, the bias should also follow them.

In the λ = 0 conditions of Simulation Study 1 and the two-minima conditions of Simulation Study 2, the actual minima are along the horizontal axis, and both regimes only differ in the equilibrium locations. Therefore, we expect that when the bias is present, it should be along the horizontal axis as well. If the bias is inward (i.e., the estimated minima are closer than they actually are), its effect should be the same for both minima, and vice versa (empirically, we found the mean bias is always inward). Similarly, when the true minima are aligned as vertices of a regular triangle in Simulation Study 2, the bias should point either towards or away from the center of the triangle, and the extent should be the same for all minima. For the λ ̸ = 0 conditions of Simulation Study 1, the minima are not fully symmetric, but we observe that the empirical bias is similar for both minima. Also, strictly speaking, the innovation matrix in Simulation Study 2 may break some of the symmetry conditions above.
